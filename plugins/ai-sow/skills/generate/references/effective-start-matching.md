# Effective Start 匹配

先用自然语言确认项目开始时真实可依赖的对象，再判断 Task 的实施方式。往期 SOW 是合同起点，不自动证明当前能力已存在；粗粒度历史条目也不能替代对具体实施对象的确认。

## 面向用户的确认

- **已存在**：项目开始时该对象已可用，并有当前证据或明确责任承诺；本次不重新建设它。
- **可修改**：该对象已经存在，且本次工作会直接改变它；需确认对象身份、当前状态、允许修改的责任与证据。
- **可使用**：既有对象保持不变，本次只在项目侧完成使用它所需的明确配置、适配、认证、映射或验证；需确认双方边界。
- **从头实现**：项目开始时没有可依赖的对应对象，或证据不足以安全确认已存在；本次以新建边界处理，或先澄清。

确认材料应写明：要匹配的对象是什么、当前证据说明什么、项目开始时可依赖到什么程度、答案将如何改变本次交付。不要只问“是否已有”。

## 匹配规则

1. 先匹配同一可实施对象与责任边界，而非名称相似、同系统或相同业务主题。
2. 再确认现状证据与本次来源没有冲突；历史承诺尚未完成、未知或仅预计后续实现时，不可当作已存在。
3. 只有能指向一个具体 Task 实例的现状证据，才可支持修改或使用；能力级描述只可帮助理解范围，不能替代实例匹配。
4. 无法确认时提出精确问题或固定假设/设计边界，不用推测选择工作方式。
