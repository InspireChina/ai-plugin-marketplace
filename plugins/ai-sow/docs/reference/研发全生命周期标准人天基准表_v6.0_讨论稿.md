## 引用与计量规则

- Task 使用“工作类型 ID”引用基础表，不以序号或名称作为稳定关联键。
- 语义不变时 ID 保持稳定；实质交付边界变化时创建新 ID，不复用旧 ID 指代新对象。
- 简单、标准、复杂分别使用 0.6、1.0、1.5 系数。简单或复杂必须写出相对标准实例的具体差异。
- 同时包含多个独立页面、事务、数据域、源目标方向、资源栈或发布批次时必须拆分；ENG-RUNTIME 按“应用 × 单一环境”计量，ENG-PIPELINE 的多个环境可以是同一条应用流水线的复杂度维度。
- 开发型 Task 默认包含必要设计、实现、Unit Test、开发自测、基本联调、常规异常处理和评审修正。
- 调整必须明确被修改的既有交付对象；接入复用必须明确保持不变的共享能力，以及本项目实际完成的配置、映射、认证、权限、环境接入或专项验证。
- 同一交付物只计算一次；只有不同结果能够分别验收时才可拆成多行；普通依赖、调用和消费不生成 Task。
- 公司 AI 平台部门建设或提供的 Harness、模型网关、SSO、密钥托管、审计和运行平台不属于本表范围；项目直接使用这些既有能力不创建 Task。模型训练、微调、训练数据准备和模型制品管理也暂不纳入本版。
- 直接安装、启用或调用现成 Plugin、Skill、知识库或研发流程不创建 Task；只有项目团队形成可独立验收的扩展、技能资产、项目知识与上下文或研发流程时，才使用 AI4SE 类型。
- 翻译、语言审校、独立专业渗透/认证、长期培训运营、固定驻场、待命和工单 SLA 不属于本表研发基础单元；合同明确购买时走独立专业服务或容量估算。为这些服务实施的应用整改、环境准备或证据整理只有形成目录内独立交付对象时才按对应类型计量。
- - 表示该工作类型不适用该模式，不得用其他模式的人天值代替。

## 工作模式判定

工作模式只判断本次是否产生实际项目工作量：对象从无到有用“新建”，改变既有对象用“调整”，共享能力保持不变但项目仍需完成可独立验收的接入工作时用“接入复用”。已有测试、演练或评测资产不变而只是再次执行、复测或签署结果，不作为独立开发工作，不进入本表。

目录中的 REL-EXECUTION 和 REL-MIGRATION-EXECUTION 是有明确人员投入的生产发布或迁移执行工作类型，与已经取消的“执行型复用模式”不是一回事；仅待命、自动运行或无独立投入时同样不计。

| 工作模式 | 判定条件 | 必须存在的项目交付证据 |
|---|---|---|
| 新建 | 交付对象不存在，需要从无到有形成 | 新对象可运行、可审查或可执行，并通过该类型约定的验收 |
| 调整 | 本项目已有交付对象需要改变行为、结构、规则或目标 | 变更内容和影响范围可核验，并按交付对象性质通过评审、复核、演练或回归验证 |
| 接入复用 | 已有可复用能力保持不变，本项目形成独立的配置、映射、封装、认证、注册、环境接入或专项验证 | 项目侧接入物和验证结果可独立审查；仅依赖、导入或调用不计 |
| 不计 | 没有独立项目侧交付对象，只是普通调用、依赖使用、例行执行或主 Task 内部步骤 | 不创建独立 Task，工作量包含在对应主 Task 中 |

同一 Task 只选择一个工作模式。若共享能力需要被修改，同时项目还要完成接入，只有两部分能够分别验收时才拆成“共享能力调整”和“项目接入复用”；否则合并到主交付对象，不重复计量。测试、演练或评测资产没有任何变化时，重复执行、复测和签署不单列 Task。

## v6.0 复杂度判断规则

### S、M、L、X 的含义

| 档位 | 判断含义 | PD 计算 |
|---|---|---:|
| S（简单） | 同类工作中范围明显较小、规则直接、依赖和验证较少，并满足该工作类型 S 档条件 | 该模式基础 PD × 0.6 |
| M（标准） | 本类型最常见、边界清楚、约束常规的标准工作单元 | 该模式基础 PD × 1.0 |
| L（复杂） | 仍是一个可独立验收的工作单元，但规模接近单元上限，或存在明显增加设计、实现、协调、验证工作的约束，并满足该工作类型 L 档条件 | 该模式基础 PD × 1.5 |
| X（需拆分或另行判断） | 包含多个独立交付对象、关键事实不清，或超出本基础单元可承载范围 | 不直接计算；先拆分或澄清，确实不可拆时单独估算 |

0.6、1.0、1.5 是当前内部经验参数，仍需使用实际项目数据校准，不代表行业通用标准。

### 统一判断规则

1. 先确定工作类型和工作模式，再判断本行实际负责的交付范围。
2. 能够分别设计、实现和验收的交付对象必须拆成多行；只有共同形成一个完整结果、不能独立验收的内容才能合并。
3. 按本工作类型专属表中的主要计量维度，将实际事实与 S、M、L 条件逐项比较。
4. 任一维度达到 L，或命中本类型列明的复杂约束，整体按 L；所有主要维度均在 S 范围且没有更高约束时按 S；其余按 M。
5. 同一行的不同维度落在不同档位时取较高档，但不能用 L 包装本应拆分的多个交付对象。
6. “复杂”“严格”“重大”“跨团队”等形容词不能单独作为升级理由，必须说明具体数量、机制、限制条件或验收要求。
7. 超过 X 条件或关键事实不足时，先拆分或补充信息；单一对象确实无法再拆且超出标准范围时另行估算。
8. 等待、自动执行、重复运行、例行复测或仅签署结果，没有实际研发工作量时不创建 Task。

### 三种工作模式的复杂度范围

复杂度只衡量本次 Task 实际承担的工作，不按整个系统、平台或共享能力的总体规模判档。

| 工作模式 | 复杂度计算范围 | 不计入本行的内容 |
|---|---|---|
| 新建 | 从无到有形成该工作类型的完整交付对象 | 与该对象无独立交付关系的存量系统复杂度 |
| 调整 | 本次新增、修改、删除的内容，以及因本次变化必须完成的影响核验和回归 | 未发生变化、也不需要重新验证的存量内容 |
| 接入复用 | 本项目实际完成的配置、映射、封装、认证、注册、环境接入、权限设置和专项验证 | 保持不变的共享平台、外部能力或公共组件内部实现 |

共享能力本身需要修改，同时项目还需要接入时，只有两部分能分别形成交付成果并分别验收，才拆成“共享能力调整”和“项目接入复用”两行；否则只保留主交付对象，避免重复计量。

### 模式覆盖

| 适用模式 | 工作类型数 | 可用组合数 |
|---|---:|---:|
| 新建 + 调整 + 接入复用 | 26 | 78 |
| 新建 + 调整 | 51 | 102 |
| 仅新建 | 9 | 9 |
| 仅调整 | 2 | 2 |
| 合计 | 88 | 191 |

标记为 - 的模式不适用，不得创建该模式的 Task。26 个“接入复用”类型只计算项目侧实际工作；普通依赖、调用或使用既有能力不单独计量。AI4SE 的接入复用还必须形成可独立验收的项目参数、绑定、权限、适配或专项验证结果；只安装或启用现成资产不计。

## 与 v5.4 的继承及独立复核变更

- v6.0 是替代目录，不要求兼容回旧 37 单元；正式切换后，新项目只使用本目录。既有进行中估算如需迁移，必须整包重算，不允许同一估算混用新旧类型或复合单元。
- 相对 v5.4 的 71 类，本轮退役语义混合的 FE-COMPONENT 和只描述工具的 TEST-TOOL；以 FE-UI-COMPONENT、CO-TECH-COMPONENT、TEST-SUPPORT-ASSET 替代，并新增/明确数据存储模型、数据目录与血缘、人工测试、用户培训与参考、业务规则流程、技术参考、项目侧 AI4SE 工具扩展/Skill/知识上下文/研发流程、现有系统智能化能力/知识检索/业务流程/评测和软件安全性保障等类型。模型训练类暂不纳入，形成 88 类。全部参数仍待同边界实绩验证。
- v6.0 增加逐类型复杂度标准、相邻类型选择说明、模式覆盖审计和案例回归；当前只修改审视标准，进入模板前需单独批准。
- 基础表不使用 quantity；真实任务列表按一实例一行引用工作类型 ID。
- 共有 26 个类型适用接入复用，前提是形成可独立验收的项目侧接入物。测试、演练或评测资产不变时的重复执行不计；AI4SE 资产的标准安装、启用或调用也不计；其他类型同样不能因为使用既有工具、框架或重复内部步骤就改用接入复用。
- 生产支持容量、固定驻场、待命和工单 SLA 不按固定比例并入每条基准，合同明确时另行估算。

## 校准与变更控制

- 复杂度阈值和倍率应使用同边界、同模式的历史 Task 实绩校准；范围变化、等待和外部阻塞需单独标记。
- 偏差出现时依次判断：基础单元边界、工作模式、M 档基础人天、复杂度阈值、复杂度倍率，避免在错误层级修参数。
- 样本不足时保持“待校准”，不根据单个案例调整全局倍率。
- 新增工作类型、改变适用模式或调整 PD 属于独立批准事项，不能在复杂度案例复核中静默修改。
- 第三轮复核已消除所有 0.5 PD 组合：无稳定独立交付对象的 AN-ADR/调整、界面组件/技术组件“接入复用”被移除；其余低基准组合上调至至少 1.0 PD。当前最低 M 档为 1.0 PD。此修改只解决明显不可交付或最低投入不完整的问题，不代表 1.0 PD 已获历史实绩证明。
