- 状态：与 v6.0 独立复核修订候选稿配套
- 日期：2026-09-03
- 设计基线：[v6.0 复杂度标准设计](研发全生命周期标准人天基准表_v6.0_复杂度标准设计.md)

> 本文说明 v6.0 从哪些权威来源吸收了哪些原则，以及哪些参数仍然只是内部经验。引用标准用于约束测量方法、边界和校准过程，不表示外部机构认可本表的 88 类目录、具体 PD、数值门禁或复杂度倍率。

## 1. 结论摘要

v6.0 采用的依据链为：

```text
功能规模方法
  → 先固定测量目的、范围、分解层级和原子功能过程
非功能规模与质量模型
  → 把性能、安全、可靠性等强约束与功能数量分开
测量过程标准
  → 定义可观察指标、记录判定依据并验证测量有效性
成本估算最佳实践
  → 依赖技术基线、产品导向分解、风险和历史数据
组织历史实绩
  → 校准本表基础人天及 S/L 倍率
```

因此，v6.0 可以获得权威支持的是方法，不是参数：

- `X` 先拆分或澄清，再估算；
- 功能规模与非功能约束分开判断，避免重复计量；
- 调整只度量新增、修改、删除及必要回归范围；
- 每个工作类型使用与其交付对象相关的定量指标；
- 严格安全、可靠性、性能和合规约束不能被简单数量平均抵消；
- 估算规则和倍率必须用本组织实际人天持续校准。

以下内容没有外部标准直接背书：

- 88 个工作类型及其中文目录结构；
- 每种工作模式的 M 档基础人天；
- `S = 0.6`、`M = 1.0`、`L = 1.5`；
- 离散计数 2×、连续规模 10×、执行时长 6× 的 L/X 门禁；
- 每一行 S/M/L 的具体数值区间。

这些内容是内部标准，需要通过案例复核和历史实绩验证。

## 2. 功能规模与原子边界

### 2.1 ISO/IEC 14143-1:2007

[ISO/IEC 14143-1:2007](https://www.iso.org/standard/38931.html)定义功能规模测量的基本概念。其可吸收重点是：功能规模针对用户要求的功能进行测量，测量方法应保持概念一致。

在 v6.0 中对应为：

- 页面、业务操作、集成和数据流程按用户或外部系统可观察的独立结果划定；
- Controller、Method、代码文件和内部活动不是计量单位；
- 一个 Task 只能承载一个可独立验收的基础工作单元实例。

### 2.2 ISO/IEC 19761:2011 与 COSMIC

[ISO/IEC 19761:2011](https://www.iso.org/standard/54849.html)规定 COSMIC 功能规模测量方法的定义、约定和活动。ISO 页面显示该版本在 2025 年复核确认后仍为当前版本。

[COSMIC Measurement Process](https://cosmic-sizing.org/cosmic-sizing/intro/measurement-process/)进一步公开说明：

- 测量前先确定目的、范围、分解层级、功能用户和软件层；
- 功能过程由触发事件启动，并可用 Entry、Exit、Read、Write 数据移动表达；
- 功能规模按数据移动类型计量，不按运行次数计量；
- 修改规模只计算新增、修改和删除的数据移动；
- 正确识别功能过程是关键分解步骤。

在 v6.0 中对应为：

| COSMIC 原则 | v6.0 规则 |
|---|---|
| 先固定范围和层级 | 先检查是否为一个基础工作单元实例；多独立对象判 X |
| 功能过程由触发事件和结果界定 | 查询 API、业务操作 API、消息流程、批处理按独立业务事务或流程计量 |
| 按类型而非发生次数计量 | 基础表无 `quantity`；重复实例在任务清单中分行 |
| 修改只计算变化部分 | 调整模式只看实际变更、影响路径和必要回归，不看整个存量系统 |
| 功能边界与持久化/用户交互分开 | 业务 API、数据模型、同步或集成按不同交付对象分别计量 |

COSMIC 不能直接用于本表的部分包括：

- COSMIC Function Point（CFP）不直接转换为 PD；
- 数据操作复杂度、算法、组织协调和非功能约束不能仅靠数据移动数量表达；
- 智能业务能力、知识检索、非确定性智能流程、AI4SE 资产和智能质量评测不能由数据移动数量推导 PD；本表仅借用“先固定范围和结果”的原则，其专属类型、阈值和 PD 仍是内部标准；
- 工程平台、发布、事故处理、培训和移交等工作不能强行套用功能规模模型。

## 3. 非功能规模和质量约束

### 3.1 ISO/IEC/IEEE 32430:2025

[ISO/IEC/IEEE 32430:2025](https://www.iso.org/standard/86303.html)规定软件非功能规模测量，可与功能规模测量互补，并提供把非功能规模用于资源预测、成本估算和项目绩效管理的应用信息。它不直接给出本表的工作类型、PD、倍率或阈值，也不能替代组织生产率数据。

在 v6.0 中对应为：

- 功能数量与非功能约束分开记录；
- 性能、安全、可靠性、兼容性、运维等已经形成独立交付对象时使用相应工作类型；
- 仅作为某个功能实例的强约束时，用作复杂度升级条件，不再创建重复 Task；
- 不把非功能强约束换算成统一分值与功能数量相加。

### 3.2 ISO/IEC 25010:2023

[ISO/IEC 25010:2023](https://www.iso.org/standard/78176.html)提供产品质量模型，可用于质量需求定义、设计目标、测试目标、质量控制和验收。v6.0 吸收其质量视角，用于检查以下定性因素：

- 功能适合性；
- 性能效率；
- 兼容性；
- 交互能力；
- 可靠性；
- 信息安全性（security）；
- 可维护性；
- 灵活性；
- 安全保障（safety）。

这些质量特性不直接相加。若某一项形成不可忽略的设计、验证或上线约束，例如零停机、强监管、高敏感数据、跨地域容灾或正式无障碍审计，可以直接使单一实例进入 L；若约束本身形成独立交付结果，则使用独立工作类型。

### 3.3 IFPUG SNAP

[IFPUG Software Non-Functional Assessment Process（SNAP）](https://ifpug.org/ifpug-standards/snap)用于补充功能规模，强调非功能需求的规模及历史生产率对于资源预测的作用。

v6.0 只吸收两点：

1. 不应把全部开发差异都塞进功能规模；
2. 从规模到资源的转换必须依赖组织历史数据。

SNAP 点数不直接转换为本表 PD，也不作为另一套并行计算公式。

### 3.4 智能化应用、AI4SE 与安全评测边界

[ISO/IEC 5338:2023](https://www.iso.org/standard/81118.html)为使用机器学习或启发式组件的 AI 系统定义生命周期过程。v6.0 只借用“AI 交付需要覆盖与其生命周期结果相符的过程和证据”这一原则，把智能业务结果、业务知识检索、智能业务流程和独立质量评测分成可独立版本化和批准的结果；标准本身不规定本表的类型名称、单元边界、复杂度阈值或 PD。模型训练、微调、训练数据和模型制品管理暂不纳入本版。

[AI4SE 生命周期分类研究](https://link.springer.com/article/10.1007/s11334-026-00652-6)把 AI4SE 的应用范围覆盖到需求、架构与设计、编码、测试、维护、部署和运行监测等阶段。v6.0 不为每个生命周期阶段复制一套类型，而是按项目团队实际交付的成果分为四类：

- `ENG-AI4SE-EXTENSION`：可独立安装和版本化的 Plugin、MCP/工具适配器、Hook 或命令扩展；
- `ENG-AI4SE-SKILL`：可独立触发和验收的 Skill 或 Agent 研发职责；
- `ENG-AI4SE-CONTEXT`：可独立维护、更新和验证的研发知识域或项目上下文；
- `ENG-AI4SE-WORKFLOW`：可独立启动和验收的多步骤智能研发流程。

[DORA 2025](https://dora.dev/research/2025/dora-report/)把 AI 视为会放大既有组织和工程系统表现的因素，而非脱离交付系统单独产生价值的工具。本文据此明确计量边界：公司 AI 平台部门提供或建设的 Harness、模型网关、SSO、密钥托管、审计和运行平台不属于本表；项目普通使用 Agent、直接打开代码库、临时提示、标准安装、启用或调用现成 Plugin、Skill、知识库或研发流程也不创建 Task。只有项目团队形成可独立验收的 AI4SE 资产，才按上述四类计量。该研究结论只支持范围边界，不证明本表的类型划分或 PD。

[NIST AI 100-2 E2023](https://csrc.nist.gov/pubs/ai/100/2/e2023/final)提供对抗性机器学习攻击与缓解的分类；[NIST AI 600-1](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)给出生成式 AI 风险管理配置；[NIST SP 800-218A](https://www.nist.gov/publications/secure-software-development-practices-generative-ai-and-dual-use-foundation-models-ssdf)补充生成式 AI 相关的安全软件开发实践。v6.0 据此区分以下三类结果：

- 针对版本化样本、指标和判据，判断智能业务能力、智能流程或 AI4SE 资产质量与行为安全的正式结论，使用 `AI-EVALUATION`；被评对象可以引用评测结论，但不重复计算评测工作。
- 针对应用攻击面、认证、授权、数据流、漏洞和安全控制有效性的验证，使用 `TEST-SECURITY`；即使入口包含 AI，也不转移到 AI 行为评测。
- 针对人员、财产、环境或受控业务过程伤害形成危害、主张—论据—证据、残余风险及批准结论，使用 `GOV-SAFETY-ASSURANCE`；即使伤害控制使用 AI，也不转移到行为评测。

同一项不可分的资产或报告只按主验收结果选择一个工作类型；行为评测、应用信息安全验证和软件安全性论证能够分别形成独立结果并分别验收时，才可拆成多行。Skill 自带的示例和基础验证、Plugin 自带的单元验证以及流程内部的常规回归包含在对应主 Task 中；只有独立评测目标、评测集、指标、判据和签署结论同时成立时才另建 `AI-EVALUATION`。共用证据不得重复计算。上述来源支持范围和风险分界，不支持把某类风险直接换算为 L、倍率或固定人天。

## 4. 测量过程与证据

### 4.1 ISO/IEC/IEEE 15939:2017

[ISO/IEC/IEEE 15939:2017](https://www.iso.org/standard/71197.html)定义测量过程，要求根据组织的信息需要建立、计划、执行和评价测量活动。

截至 2026-09-03，ISO 页面仍把 2017 版列为已发布版本，但其生命周期状态已于 2026-08-05 变为“待修订”。本文当前映射仍以 2017 版为准；后续版本正式发布时必须重新复核，不能默认沿用。

在 v6.0 中对应为：

- 信息需要：判断当前基础工作单元实例相对 M 档是 S、M、L，还是不可估算的 X；
- 测量项：每个工作类型的状态、规则、映射、数据组、场景、环境、资源、依赖或验证矩阵；
- 测量结果：复杂度档位及 S/L 的实例事实理由；
- 评价：用实际研发有效投入人天检查档位与倍率是否有区分度；
- 改进：只根据可比样本和可泛化偏差修改标准。

## 5. 成本估算与历史校准

### 5.1 GAO Cost Estimating and Assessment Guide

[GAO-20-195G](https://www.gao.gov/products/gao-20-195g)将可靠估算建立在技术基线、产品导向工作分解、规则与假设、数据收集、估算方法、敏感性/风险分析和实际成本更新之上。

在 v6.0 中对应为：

- v6.0 候选目录的工作类型、计量单位、工作模式和标准交付对象构成待批准的 Task 级技术基线；v5.4 只用于来源追溯和可比历史样本校准；
- 一行一个基础工作单元实例构成产品导向分解；
- 复杂度理由记录偏离 M 的已知事实；
- X 阻止把边界不明或多对象范围直接估算；
- 案例复核记录规则变更、接受/拒绝建议及原因；
- 历史实绩用于更新内部参数，而不是只验证一次后永久固定。

### 5.2 NASA SWE-015

[NASA SWE-015 Cost Estimation](https://swehb.nasa.gov/spaces/SWEHBVD/pages/102695400/SWE-015%2B-%2BCost%2BEstimation)按软件等级和成本规模规定应建立、记录和维护的成本模型数量；其小型项目指导允许使用轻量类比或以专家判断锚定的工时估算，同时要求考虑关键成本驱动、验证模型适用性并记录假设和参数。

在 v6.0 中对应为：

- 基础人天和倍率是本地参数；
- 专家判断必须落到工作类型专属定量/定性标准和实例事实；
- 不能用“复杂”“工作量大”“技术难度高”等不可复核理由替代成本驱动因素；
- 相似历史任务只在基础单元边界、模式和交付约束可比时用于类比。

### 5.3 NASA SWE-142

[NASA SWE-142 Software Cost Repositories](https://swehb.nasa.gov/spaces/SWEHBVD/pages/102695500/SWE-142%2B-%2BSoftware%2BCost%2BRepositories)要求成本库保存计划与实际工作量/成本、主要里程碑日期、关键成本参数以及项目描述信息，用于后续估算、偏差分析和组织学习。

v6.0 要求历史样本至少保存：

| 字段 | 用途 |
|---|---|
| 工作类型 ID | 确定基础工作单元 |
| 工作模式 | 区分新建、调整和有实际项目侧交付物的接入复用；纯调用、重复执行或例行复测不计 |
| 复杂度与理由 | 保存估算时使用的成本驱动事实 |
| M 档基础人天与倍率 | 重现估算输入 |
| 实际研发有效投入人天 | 计算估算偏差 |
| 范围变化、返工、等待和外部阻塞 | 排除不应归因于复杂度标准的偏差 |
| 是否中途拆分或合并 | 判断样本是否仍与基础单元边界可比 |

## 6. 从权威原则到 v6.0 决策算法

| v6.0 决策步骤 | 依据 | 目的 |
|---|---|---|
| 先检查结构性 X | COSMIC 范围/分解层级；GAO 产品导向 WBS | 防止多独立对象或不明确范围进入估算 |
| 按工作模式确定计量范围，再检查数值 X | COSMIC 修改规模；技术基线 | 新建看完整新对象，调整看变化部分，接入复用只看项目侧实际配置、映射、认证、环境接入和专项验证；数值门禁不使用共享能力或存量对象总体规模 |
| 使用工作类型专属定量锚点 | ISO 功能规模概念；ISO 15939 测量项 | 使不同类型使用与交付对象相符的尺度 |
| 单项强约束可升级 L | ISO 32430；ISO 25010 | 防止安全、可靠性等强约束被简单因素抵消 |
| 智能化应用与 AI4SE 结果分开 | ISO 5338；AI4SE 生命周期分类研究；DORA 2025；NIST AI 100-2、AI 600-1、SP 800-218A | 区分智能业务能力、业务知识、业务流程、项目侧 AI4SE 资产、AI 行为评测和应用安全控制验证；排除公司 AI 平台和普通工具使用，避免遗漏或重复计量 |
| S 必须全部满足 | 测量一致性与可复核性要求 | 防止凭主观印象下调估算 |
| 其余默认 M | M 是标准实例 | 减少不必要的专家自由度 |
| 用历史实绩校准 | ISO 15939；GAO；NASA；IFPUG | 验证标准与倍率的实际预测能力 |

## 7. 倍率参数状态

| 档位 | 当前倍率 | 状态 | 结论 |
|---|---:|---|---|
| S | 0.6 | 内部经验参数，待校准 | 外部标准不直接背书 |
| M | 1.0 | 标准基准 | 由每个工作类型和模式的 M 档基础人天定义 |
| L | 1.5 | 内部经验参数，待校准 | 外部标准不直接背书 |

倍率是否合理必须与基础人天一起检查。例如，某类调整模式的 M 档基础人天已经明显低于新建，不能仅通过 S 倍率再次机械压低而不检查实际范围；同样，严格监管或零停机造成的投入可能并非统一 1.5 倍可以覆盖。

样本不足时维持“待校准”，不根据少数案例修改全局倍率。出现稳定偏差时，先判断是基础单元边界错误、M 档基础人天错误、复杂度阈值错误，还是倍率错误，再修改唯一对应层级。

## 8. 适用限制

本文不声称 v6.0 已成为 ISO、COSMIC、GAO、NASA 或 IFPUG 的实现或认证成果。v6.0 是组织内部的类比估算基准，外部标准只用于增强以下质量：

- 边界一致性；
- 功能与非功能因素分离；
- 指标可观察性；
- 判定可复核性；
- 历史校准可追溯性。

任何正式报价仍需结合明确范围、技术起点、团队能力、交付环境、合同风险及经过批准的项目模板参数。
