# Dev / TL 全生命周期标准人天基准表 v5.1（讨论稿）

- 状态：迭代讨论稿
- 日期：2026-09-02
- 适用范围：Developer / Tech Lead 实际承担的软件交付工作
- 计量方式：一行 Task 对应一个独立基础工作单元，不使用数量字段
- 人天单位：PD

> 本版本吸收 [v5.0 讨论稿](Dev-TL全生命周期标准人天基准表_v5.0_讨论稿.md) 的八案例复核结论，
> 仍不替代当前 SOW v1.3，也不是插件模板的计算权威。

## 公共计量规则

| 参数 | 定义 |
|---|---|
| 新增 | 从无到有形成新的可验收交付能力或成果。 |
| 修改 | 改变本项目既有交付能力的行为、规则、结构或正式成果。 |
| 适配 | 既有能力主体保持不变，本项目交付配置、映射、封装、认证、环境接入或专项验证。普通依赖引入和普通调用不计。 |
| 简单 | 标准 PD × 0.6；逻辑直接、依赖少、风险低，并写明相对标准实例的具体差异。 |
| 标准 | 标准 PD × 1.0；常规企业软件工程任务。下表 PD 均为标准复杂度基准。 |
| 复杂 | 标准 PD × 1.5；规则、依赖、异常路径或技术约束明显增加，并写明具体差异。 |
| X / 拆分 | 同时包含多个独立页面、事务、数据域、系统、环境、资源栈或发布批次，或者边界仍不清晰；必须先拆分或澄清。 |

开发型 Task 默认包含必要设计、实现、Unit Test、开发自测、基本联调、常规异常处理和评审修正。
只有形成独立正式交付成果的方案、自动化测试、联调或验证才能另行计量。

## v5.0 → v5.1 变更摘要

- 新增 8 类：国际化与本地化、应用工程初始化、配置与功能开关、共享数据模型与契约、正式集成联调、
  共享工程平台、生产故障诊断与恢复、系统或应用退役。
- 合并“生产上线技术准备”和“生产上线实施方案”为“生产发布与切换方案”。
- 收窄文件传输、独立数据加工和基础设施资源栈边界；把外部系统集成扩展为跨系统业务集成。
- 调整可复用组件、跨系统集成、指标数据集、测试支撑工具、RCA 和发布方案的基准 PD。
- 将原“功能开发”分类拆成“功能与接口、应用共性能力、集成与数据、身份安全与治理”，分类不参与查表。

War Room 待命、专职驻场、固定班次、多人并行切换和 24×7 支持属于服务容量，不按本表固定 PD 估算。
