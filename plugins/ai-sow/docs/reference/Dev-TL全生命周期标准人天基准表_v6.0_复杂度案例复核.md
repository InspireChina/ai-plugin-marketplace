## 1. 案例共同假设

- 需求、有效起点、目标方案和验收结果已经明确；若这些事实缺失，相关 Task 应判 X，而不是使用本文示例档位。
- “接入复用”均假定共享主体保持不变，并且项目侧有可独立验收的配置、映射、认证、权限、租户或专项验证工作。
- 每个 S/L 理由说明相对 M 的实例事实；M 只在本文展示判断依据，正式任务不保存 `complexityRationale`。
- 案例事实是用于验证规则区分度的代表性输入，不构成特定客户承诺。

## 2. 第一轮：按交付对象拆解并判断复杂度

| 支付修复发布方案 | REL-PLAN | 新建 | 1 个组件、1 个团队、8 个步骤；允许短时停机和标准回滚 | S | 所有主要指标满足 S，无 M/L 强约束 |
| 支付修复技术执行 | REL-EXECUTION | 新建 | 1 个组件、5 个步骤、1 个团队；允许短时停机 | S | 一次新的简单执行结果 |
| 支付故障手册更新 | HAND-RUNBOOK | 调整 | 更新 4 个场景、2 个组件、2 类角色，增加排障和恢复步骤 | M | 只看变化章节和验证范围，落入 M |

## 3. 第一轮问题与建议处置

| ID | 发现或建议 | 处置 | 规则变化及理由 |
|---|---|---|---|
| R1-01 | 接入复用若仍按共享平台内部阶段、接口或资源数量判断，会把不属于项目的复杂度计入 | 接受 | 新增接入复用替换量表，只计算九类项目侧工作、配置/映射项和验证路径 |
| R1-02 | `ENG-RUNTIME` 计量单位是“每应用 / 环境”，原 M 描述含“多环境差异”，与原子边界矛盾 | 接受 | M/L 改为同一环境内部规模；多个独立环境判 X 并拆分 |
| R1-03 | 数据量对不同行业的处理成本差异大，绝对记录数不能单独决定复杂度 | 接受 | 明确记录数只是内部初始锚点；窗口、单条成本、质量和恢复条件可升级，最终依赖历史校准 |
| R1-04 | 为多语言项目新增“翻译文案”Dev / TL 工作类型 | 拒绝 | 翻译和语言审校属于内容/专业服务；工程侧已有机制、页面/模板适配和验证类型，不应重复计量 |
| R1-05 | 把 CI/CD、IaC、基础设施等全部归为“应用级通用技术能力” | 拒绝 | 分类按交付对象而非出现层级；应用共性、流水线、模块、资源栈、平台和运行接入已有独立边界 |
| R1-06 | 根据本轮案例立即把 L 倍率从 1.5 提高 | 拒绝 | 案例只能验证规则能否解释事实，不能替代实际人天分布；倍率继续标记待校准 |
| R1-07 | 为测试数据准备新增独立工作类型 | 拒绝 | 单场景数据包含在测试 Task；只有形成跨场景可复用工具/数据域时才使用 `TEST-TOOL` |
| R1-08 | 正式渗透测试也直接使用 `TEST-SECURITY` L | 部分拒绝 | 应用内专项验证可为 L；需要独立专业团队认证或正式渗透时判 X，转为独立专业服务范围 |

第一轮修订没有新增类型、改变模式或调整 PD。

## 4. 第二轮：相邻类型与三种模式一致性复核

### 4.1 相邻类型边界

| 对比组 | 复核结论 | 案例证据 |
|---|---|---|
| 业务 API / 跨系统集成 | API 对单系统内业务事务负责；集成对一个已批准系统方向负责 | 案例 C 的订单 API 与案例 D 的 CRM 集成各自独立，没有按“都调用接口”合并 |
| 数据导入 / 同步 / 迁移 | 导入是一次业务输入结果；同步是持续系统间一致性；迁移是历史数据从旧起点到新目标 | 案例 D 使用同步，案例 G 使用迁移和独立演练/执行，没有重复使用导入 |
| 应用共性 / 工程平台 | `CO-*` 交付应用内机制；`ENG-*` 交付流水线、IaC、资源栈、共享平台或运行接入 | 案例 A 使用 `CO-I18N`，案例 F 分别使用五类 `ENG-*` |
| 研发实现 / 正式验证 | 开发 Task 含 Unit Test 和基本联调；`TEST-*` 只计独立正式测试资产或证据 | 案例 C 的 API 与 API 回归分开验收；案例 D 另列正式端到端技术验证 |
| 迁移能力 / 演练 /生产执行 | `DATA-MIGRATION` 形成能力；`REL-MIGRATION-DRYRUN` 形成演练证据；`REL-MIGRATION-EXECUTION` 形成生产结果 | 案例 G 三者交付对象不同，按一次能力、一次演练批次、一次生产批次分行 |
| 事故恢复 / RCA / 整改 | 恢复处理当前故障；RCA 形成因果结论；整改修改原业务对象 | 案例 H 不在 RCA 中重复恢复动作，接口整改使用 `FE-COMMAND-API` 调整 |

### 4.2 模式一致性

| 工作模式 | 第二轮检查 | 结论 |
|---|---|---|
| 新建 | 测试、演练、发布执行和 RCA 即使使用既有工具，也是在形成本次新的独立结果 | 案例 C、G、H 均保持新建，不误判为接入复用 |
| 调整 | 只计算已存在对象的实际变化、影响路径和必要回归 | 案例 A 页面/模板、案例 F 平台/IaC、案例 H 接口/手册均未把整个存量对象计入 |
| 接入复用 | 共享主体不变；只计算项目侧九类工作和验证 | SSO、测试平台、流水线、运行、可观测与权限案例均排除提供方内部规模 |

第二轮没有改变核心档位定义、工作类型、适用模式或 PD。接入复用量表已经能够解释全部 23 个可复用类型：各类型仍使用自己的项目侧强约束，提供方内部指标一律排除。

## 6. 稳定性结论

| 门禁 | 结果 | 证据 |

| 71 个工作类型都有专属 S/M/L/X | 通过 | 标准正文 71 行 ID 唯一且齐全 |
