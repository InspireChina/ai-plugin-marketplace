# Dev / TL 全生命周期标准人天基准表 v5.4 模式复核

- 日期：2026-09-02
- 复核对象：[v5.4 模式校准稿](Dev-TL全生命周期标准人天基准表_v5.4_讨论稿.md)
- 复核范围：`新建 / 调整 / 接入复用` 的互斥性、标准交付对象的对应关系，以及 71 个工作类型的模式参数

## 复核结论

- “新增 / 修改 / 适配”不宜继续作为正式名称。“新增”和“修改”偏变更动作，“适配”既可能是修改主体，也可能只是接入既有主体，三者不在同一判定层面。
- v5.4 使用“新建 / 调整 / 接入复用”。判定核心是：是否存在保持不变的可复用主体，以及本项目是否形成可独立验收的接入物。
- 标准交付对象需要与模式对应，但不应复制成三套对象目录。每行保留一个“标准交付对象”，再由“模式化完成标准”说明新建、调整和接入复用分别需要提交什么证据。
- 71 个工作类型无需新增或合并；本轮需要调整的是模式参数。保留接入复用的类型从 55 个收紧到 23 个，其余 32 个类型的接入复用 PD 改为 `-`。
- 留出案例未发现新的类型缺口，也未发现需要立即调整的新建、调整或保留接入复用的 PD 数值。PD 仍需历史项目数据校准。

## 案例一：技术分析与方案

场景：支付服务商升级，先形成影响结论，评审后又改变切换范围。

| 任务 | 类型 | 模式 | 判定与交付证据 |
|---|---|---|---|
| 首次分析支付接口、数据、故障恢复和发布影响 | AN-IMPACT | 新建 | 形成一份新的影响范围、风险、建议和结论 |
| 评审后将一次切换改为分批切换，修订同一份分析 | AN-IMPACT | 调整 | 同一交付对象发生目标变更，修订内容和影响可核验 |
| 仅引用去年同类项目的分析报告 | 不单列 | 不计 | 没有形成新的项目结论，也没有修改既有项目交付对象 |
| 为一个明确技术未知开展验证实验 | AN-SPIKE | 新建 | 每次探索产生新的实验和技术结论，不存在“复用一次探索结果”的模式 |

结论：分析和方案可以新建或调整；引用既有结论只是输入，不构成接入复用。

## 案例二：页面、API 与共享组件

场景：建设订单查询功能，并使用企业统一地址组件。

| 任务 | 类型 | 模式 | 判定与交付证据 |
|---|---|---|---|
| 创建订单查询页面 | FE-VIEW | 新建 | 新页面及其查询、结果呈现通过验收 |
| 为既有订单页面增加筛选条件 | FE-VIEW | 调整 | 既有页面行为改变并完成回归验证 |
| 从其他系统复制页面脚手架后形成新订单页面 | FE-VIEW | 新建 | 页面本身是新的业务交付对象，不能因使用模板改计接入复用 |
| 创建企业统一地址组件 | FE-COMPONENT | 新建 | 形成稳定接口、示例、文档及独立验证 |
| 修改统一地址组件的校验接口 | FE-COMPONENT | 调整 | 组件主体被修改，并验证兼容影响 |
| 组件主体不变，在订单应用中完成注册、主题和封装 | FE-COMPONENT | 接入复用 | 项目侧接入物可独立审查和验证 |
| 仅在代码中导入已经配置好的组件包 | 不单列 | 不计 | 普通依赖或调用没有独立项目交付对象 |

结论：页面和业务 API 只保留新建、调整；组件只有在存在项目侧接入物时才可使用接入复用。

## 案例三：企业身份认证接入

场景：新应用接入企业统一身份平台，身份平台和标准连接器不改动。

| 任务 | 类型 | 模式 | 判定与交付证据 |
|---|---|---|---|
| 从无到有开发一套身份认证集成能力 | IN-IDENTITY | 新建 | 新认证流程、用户关联和身份交互结果通过验收 |
| 修改既有应用的账号映射和会话处理 | IN-IDENTITY | 调整 | 既有集成主体发生行为变化并完成回归 |
| 使用不变的企业 IdP 和连接器，完成应用认证配置、用户映射和会话接入 | IN-IDENTITY | 接入复用 | 共享主体不变，项目侧配置、映射和验证结果可验收 |
| 已由平台自动完成接入，项目不产生任何配置或验证物 | 不单列 | 不计 | 没有供应商可独立交付的工作单元 |

结论：身份和跨系统集成是接入复用的典型场景，但普通 API 调用不是。

## 案例四：系统多语言支持

场景：已有订单系统增加中文、英文和德文支持，企业已有统一国际化框架。

| 任务 | 类型 | 模式 | 判定与交付证据 |
|---|---|---|---|
| 企业原本没有国际化机制，从无到有建设资源加载、Locale、回退和格式化机制 | CO-I18N | 新建 | 形成完整的国际化基础能力并通过机制级验收 |
| 既有国际化机制增加新的回退规则和格式化行为 | CO-I18N | 调整 | 共享主体被修改，需验证原有语言兼容性 |
| 国际化框架不改，在订单应用中配置 Locale、语言资源和回退规则 | CO-I18N | 接入复用 | 项目侧资源、配置和机制验证结果可独立验收 |
| 修改订单列表、详情和编辑页的文案布局 | FE-VIEW / FE-EDIT | 调整 | 页面交付对象发生变化，不能全部归入 CO-I18N |
| 修改发票和通知模板以输出不同语言 | DATA-DOCUMENT | 调整 | 文档模板及生成结果发生变化 |
| 建立多语言兼容性正式验证场景 | TEST-COMPAT-A11Y | 新建 | 形成新的验证方案、执行证据和缺陷结论 |

结论：应用共性能力只承担机制级工作；页面、文档和正式验证仍按各层交付对象拆分。若多个应用分别接入同一框架，每个应用都可有一个 CO-I18N 接入复用 Task，但不得按页面或语言数量重复计量。

## 案例五：数据同步与权限治理

场景：在已有数据平台上建立客户主数据同步，并接入统一权限平台。

| 任务 | 类型 | 模式 | 判定与交付证据 |
|---|---|---|---|
| 使用现成调度平台创建新的客户同步管道 | DATA-SYNC | 新建 | 同步管道是新的业务交付对象；平台被复用不改变该判断 |
| 调整客户字段映射和冲突处理规则 | DATA-SYNC | 调整 | 既有同步对象发生规则变化并完成对账回归 |
| 将项目注册到不变的共享数据平台，完成租户、路由、配额和权限接入 | ENG-PLATFORM | 接入复用 | 平台主体不变，项目侧接入物可独立验收 |
| 从无到有设计并实现项目权限模型 | GOV-FUNCTION-ACCESS | 新建 | 新的角色、资源和操作规则通过验证 |
| 使用统一权限平台的既有模型，只配置项目角色、资源映射和验证 | GOV-FUNCTION-ACCESS | 接入复用 | 共享权限能力不变，项目规则和映射属于接入证据 |

结论：使用共享平台不等于数据 Task 使用接入复用；应分别判断“业务数据对象”和“平台接入对象”。

## 案例六：测试自动化与测试工具

场景：为订单接口建立自动化验证，并使用企业统一测试平台。

| 任务 | 类型 | 模式 | 判定与交付证据 |
|---|---|---|---|
| 创建订单创建接口的自动化测试场景 | TEST-API | 新建 | 新脚本、数据、断言和执行证据通过评审 |
| 接口契约变化后修改既有测试场景 | TEST-API | 调整 | 既有验证对象被修改并重新执行 |
| 将项目注册到不变的测试平台，完成环境、数据和报告配置 | TEST-TOOL | 接入复用 | 项目侧工具配置或封装可以独立验收 |
| 在新版本上重复执行完全不变的测试场景 | 不单列 | 不计 | 重复执行不是接入复用；若合同购买独立测试执行容量，应另行定义服务计量方式 |

结论：验证场景没有接入复用模式；可复用的是测试工具，新的业务验证场景仍按新建计量。

## 案例七：CI/CD、IaC 与基础设施

场景：新应用使用企业流水线模板和 IaC 模块部署一套标准资源栈。

| 任务 | 类型 | 模式 | 判定与交付证据 |
|---|---|---|---|
| 从无到有开发企业流水线模板 | ENG-PIPELINE | 新建 | 新流水线能力和执行结果通过验收 |
| 修改既有流水线模板的制品签名逻辑 | ENG-PIPELINE | 调整 | 模板主体被修改并完成兼容回归 |
| 模板不改，为新应用配置制品、环境、审批和执行验证 | ENG-PIPELINE | 接入复用 | 项目侧参数和运行证据可独立验收 |
| 从无到有开发可复用 IaC 模块 | ENG-IAC | 新建 | 新模块、变量接口和计划结果通过验收 |
| 模块不改，为项目提供变量、状态和依赖配置 | ENG-IAC | 接入复用 | 项目侧 IaC 接入物可审查并通过计划验证 |
| 按标准资源栈模式，仅绑定账号、网络和项目参数后部署 | ENG-INFRA-STACK | 接入复用 | 资源栈模式不变，项目实例和部署结果可验收 |
| 在标准模式外设计一套新的定制资源栈 | ENG-INFRA-STACK | 新建 | 形成新的资源组合、依赖和部署结果 |
| 修改项目既有资源栈的拓扑或容量规则 | ENG-INFRA-STACK | 调整 | 既有栈发生结构或目标变化并完成验证 |

结论：CI/CD、IaC、基础设施、运行平台和可观测平台都可能使用三种模式；关键不是“是否使用平台”，而是共享主体是否保持不变、项目侧是否有独立接入物。

## 案例八：发布、生产处置与交接

场景：一个版本上线后发生故障，恢复后更新运行手册。

| 任务 | 类型 | 模式 | 判定与交付证据 |
|---|---|---|---|
| 为本次 Release 形成发布计划 | REL-PLAN | 新建 | 每个 Release 产生新的计划和就绪结论，不能复用上次 Release 的执行结果 |
| 上线前调整同一份发布计划 | REL-PLAN | 调整 | 同一 Release 的计划对象被修订并重新确认 |
| 执行本次正式发布 | REL-EXECUTION | 新建 | 本次部署、冒烟和健康检查是新的独立执行结果 |
| 诊断并恢复本次生产故障 | OPS-INCIDENT-RECOVERY | 新建 | 每次故障形成新的恢复结果和诊断证据 |
| 复用运行手册中的命令完成恢复 | OPS-INCIDENT-RECOVERY | 新建 | 使用既有手册只是输入，不把事故执行改成接入复用 |
| 根据事故教训更新既有运行手册 | HAND-RUNBOOK | 调整 | 手册交付对象发生变化并通过可执行性检查 |
| 原样转发一份已有手册 | 不单列 | 不计 | 没有形成新的或调整后的交接成果 |

结论：发布、事故和复盘以每次独立执行结果计量，不存在接入复用；手册和交接材料可新建或调整。

## 案例九：共享组件同时修改并接入

场景：订单应用需要使用统一地址组件，但组件缺少海外地址能力。

| 拆分后的任务 | 类型 | 模式 | 独立交付对象 |
|---|---|---|---|
| 为统一地址组件增加海外地址模型和校验接口 | FE-COMPONENT | 调整 | 被修改的共享组件、接口和回归结果 |
| 在订单应用注册升级后的组件并完成主题、表单绑定和应用验证 | FE-COMPONENT | 接入复用 | 订单应用侧注册、封装和验证结果 |

只有当两部分可以分别交付、分别验收时才拆成两个 Task；若修改和接入由同一不可分割实现完成，应合并为一个主 Task，避免重复计量。

## 71 行参数复核

| 复核项 | 结果 | 结论 |
|---|---:|---|
| 工作类型总数 | 71 | 与 v5.3 一致，无新增、删除或改 ID |
| v5.3 有适配 PD 的类型 | 55 | 口径过宽，包含页面、数据、验证、发布等不能形成复用接入物的类型 |
| v5.4 保留接入复用 PD 的类型 | 23 | 均能够形成独立项目侧配置、映射、注册、封装、环境接入或专项验证 |
| 取消接入复用 PD 的类型 | 32 | PD 改为 `-`，不得借用新建或调整参数 |
| 新建、调整 PD | 未改 | 本轮只校准模式语义，不混入数值调参 |
| 保留的接入复用 PD | 未改 | 现值继续作为讨论基线，等待历史数据校准 |

保留接入复用的 23 个类型如下：

| 范围 | 工作类型 ID |
|---|---|
| 共享组件与集成 | FE-COMPONENT、IN-INTEGRATION、IN-IDENTITY |
| 应用共性能力 | CO-I18N、CO-CONFIG、CO-ACCESSIBILITY、CO-PERF-RELIABILITY、CO-BCDR、CO-SECURITY-PRIVACY、CO-MULTITENANCY |
| 治理能力 | GOV-FUNCTION-ACCESS、GOV-DATA-ACCESS、GOV-DATA-SECURITY、GOV-AUDIT |
| 测试工具 | TEST-TOOL |
| 工程与平台 | ENG-BOOTSTRAP、ENG-PIPELINE、ENG-IAC、ENG-INFRA-STACK、ENG-PLATFORM、ENG-RUNTIME、ENG-OBSERVABILITY、ENG-ALERT |

## 最终判断

v5.4 的模式结构可以进入稳定候选：三种模式已经互斥，标准交付对象与模式化完成标准形成明确对应，应用、数据、测试、CI/CD、基础设施、发布和生产场景均能落入唯一口径。本轮不建议增补工作类型或调整保留参数；下一步应使用真实任务清单和历史工时做数值校准，而不是继续扩充目录。
