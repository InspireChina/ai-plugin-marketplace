## 引用与计量规则

- Task 使用“工作类型 ID”引用基础表，不以序号或名称作为稳定关联键。
- 语义不变时 ID 保持稳定；实质交付边界变化时创建新 ID，不复用旧 ID 指代新对象。
- 简单、标准、复杂分别使用 0.6、1.0、1.5 系数。简单或复杂必须写出相对标准实例的具体差异。
- 同时包含多个独立页面、事务、数据域、系统、环境、资源栈或发布批次时必须拆分；边界不清时标记 X。
- 开发型 Task 默认包含必要设计、实现、Unit Test、开发自测、基本联调、常规异常处理和评审修正。
- `-` 表示该工作类型不适用该模式，不得用其他模式的人天值代替。

## 工作模式判定

| 工作模式 | 判定条件 | 必须存在的项目交付证据 |
|---|---|---|
| 新建 | 不存在可直接复用的交付主体，需要从无到有构建主体能力或形成一次新的独立执行结果 | 新对象或新执行结果可运行、可审查或可执行，并通过该类型约定的验收 |
| 调整 | 本项目已有交付对象需要改变行为、结构、规则或目标 | 变更内容和影响范围可核验，并按交付对象性质通过评审、复核、演练或回归验证 |
| 接入复用 | 已有可复用主体保持不变，本项目只需形成独立的配置、映射、封装、认证、注册、环境接入或专项验证 | 项目侧接入物和验证结果可独立审查；仅依赖、导入、调用或重复执行不计 |
| 不计 | 没有独立项目侧交付对象，只是普通调用、依赖使用、例行执行或主 Task 内部步骤 | 不创建独立 Task，工作量包含在对应主 Task 中 |

同一 Task 只选择一个工作模式。若共享能力需要被修改，同时项目还要完成接入，必须按独立交付对象拆成“共享能力调整”和“项目接入复用”两个 Task；若无法独立验收，则合并到主交付对象，不重复计量。

## v6.0 复杂度判断规则

### 档位与倍率状态

| 档位 | 统一含义 | 当前倍率 | 参数状态 |
|---|---|---:|---|
| S | 同类实例中明显低于标准范围，主要定量指标全部满足 S，且没有 M/L 定性约束 | 0.6 | 内部经验参数，待历史实绩校准 |
| M | 边界清楚、规模和约束处于本类型最常见范围的标准实例 | 1.0 | 基准参数 |
| L | 仍是一个独立实例，但规模接近单元上限，或命中一项不可忽略的强约束 | 1.5 | 内部经验参数，待历史实绩校准 |
| X | 多个独立实例、边界不清、关键前提缺失，或应先完成专题分析/设计 | 不适用 | 不进入正式估算 |

倍率仍由项目模板管理；本文不成为第二计算权威。各行数值区间是内部初始锚点，不是 ISO、COSMIC、GAO、NASA 或 IFPUG 给出的通用阈值。

### 统一判定顺序

```text
1. 先检查 X：多独立交付对象、边界不清或关键前提缺失时停止估算。
2. 按工作模式确定当前 Task 的实际计量范围。
3. 对照本工作类型的定量锚点和定性条件。
4. 命中任一 L 强约束时判 L，不允许其他简单因素把它平均为 M。
5. 仅当主要定量指标全部落入 S，且没有 M/L 条件时判 S。
6. 其他边界清楚且未命中 X/L/S 的实例判 M。
```

不使用跨维度加权总分。严格安全、监管、零停机、恢复目标、跨地域连续性等单项约束不能被“字段少”“页面少”等因素抵消。

### 工作模式的复杂度范围

| 工作模式 | 复杂度计量范围 | 排除范围 |
|---|---|---|
| 新建 | 新交付对象从无到有形成标准交付结果所需的完整范围 | 与本对象无独立交付关系的存量系统复杂度 |
| 调整 | 本次新增、修改、删除的内容，受影响路径，以及完成调整必须执行的回归 | 未变化且无需因耦合重新验证的整个存量对象 |
| 接入复用 | 本项目侧的注册、配置、封装、映射、适配、认证、租户设置、权限设置和专项验证 | 保持不变的共享平台、外部能力或公共组件内部实现 |

接入复用时，如果专属标准中的阶段、接口、资源、组件等指标描述的是共享主体内部结构，不使用这些数字；改用本项目侧实际交付物判定：

| 接入复用档位 | 项目侧定量锚点 | 定性边界 |
|---|---|---|
| S | 1 类项目侧工作；≤5 个配置、映射或绑定项；1 条验证路径 | 标准认证、网络和权限，无专项协调 |
| M | 2～4 类项目侧工作，或 6～20 个配置、映射或绑定项；2～3 条验证路径 | 含认证、权限、租户、环境差异或跨团队联调中的一项或多项 |
| L | ≥5 类项目侧工作，或 >20 个配置、映射或绑定项；≥4 条验证路径 | 复杂安全/网络、强合规、受限外部环境、严格可用性或联合窗口任一项 |
| X | 项目侧实际包含多个可独立交付的应用、租户、资源栈、集成方向或能力单元 | 按基础单元边界拆分，不用 L 合并 |

“项目侧工作”只取注册、配置、封装、映射、适配、认证、租户设置、权限设置、专项验证九类；同一类中的多项明细不重复增加类别数。接入复用先应用本表，再应用工作类型行内的项目侧特有强约束，取较高档。

共享能力本身需要修改，同时项目还要接入时，拆成“共享能力调整”和“项目接入复用”两个 Task；普通依赖、导入、调用或按既有约定执行没有独立项目侧交付物，不创建 Task。

### 定量、定性与原子边界

- 定量锚点衡量同一实例内部的状态、规则、字段、映射、步骤、环境、资源、依赖或验证矩阵；不是数量乘法。
- 数据量阈值统一指该 Task 的业务记录数/批或/次，是跨行业初始锚点；严格窗口、单条记录处理成本、数据质量和恢复要求可以升级档位，历史实绩校准后才能调整阈值。
- 一个数据域内紧密相关对象可以作为复杂度因素；不同数据域、系统方向、独立页面、独立流程、资源栈或发布批次必须拆分。
- 数量落入 S 但命中 M/L 定性条件时，按较高档。
- 数量超过 L 且可以拆为独立对象时判 X；不能合理拆分且仍是单一原子结果时，使用该行明确的 L 开放条件，不临时创造例外。
- 事实不足以判断时判 X，不默认 M。
- S/L 的复杂度理由必须记录实例事实及相对 M 的偏离；M 不保存理由。

## 继承 v5.4 的边界

- 保持 71 个工作类型 ID、名称、分类、计量单位、适用模式、M 档基础人天、标准交付对象、模式化完成标准和说明不变。
- v6.0 只增加复杂度判断规则、权威依据、模式覆盖审计和案例回归，不修改当前模板。
- 基础表不使用 `quantity`；真实任务列表按一实例一行引用工作类型 ID。
- 只有 23 个能够形成独立项目侧接入物的类型适用“接入复用”；其他类型不能因为使用了既有工具、框架或平台就改用该模式。
- 生产支持容量、固定驻场、待命和工单 SLA 不按固定比例并入每条基准，合同明确时另行估算。

## 校准与变更控制

- 复杂度阈值和倍率应使用同边界、同模式的历史 Task 实绩校准；范围变化、等待和外部阻塞需单独标记。
- 偏差出现时依次判断：基础单元边界、工作模式、M 档基础人天、复杂度阈值、复杂度倍率，避免在错误层级修参数。
- 样本不足时保持“待校准”，不根据单个案例调整全局倍率。
- 新增工作类型、改变适用模式或调整 PD 属于独立批准事项，不能在复杂度案例复核中静默修改。
