# 输入阅读、用途与历史范围

本页负责输入的语义分析；登记和 JSON 形状见 [编写参考](generate-authoring.md#登记读取和分析)。工具的物理覆盖不等于材料充分，历史条目也不自动证明生产能力。

## 全输入分析的产物

以本期义务组织主题，覆盖业务、技术/NFR、交付三个视角；没有相应义务时不造工作。每个主题在已有 analysis 与 `input-review.md` 中说明：

- **本期目标与依据**：验收意图、目标方案、公共能力及消费者、交付成果、责任和排除。
- **现状与 gap**：历史已知范围、本期变化，或有充分依据的已满足/空 gap 结论。
- **输入问题及去向**：影响推进的基础缺口、可隔离的局部未知、实际答复和采用结论；被引用规则的未明部分也在这里记录。
- **读取范围与限制**：实际采用的原文、未读面及其影响。

这些是已有工作记录的内容，不新增业务 Schema 或评审阶段。只有 draft/tech note、缺 PRD/HLD 或关键基础未读时，不能得出“本期无工作”。

## 引用中的缺口

原文说“已定义”“按既定规则”“符合现有规范”，只说明它依赖一份约定。按**实际可用的验收依据**选择出口：

| 当前依据 | 如何用于 SOW |
|---|---|
| 本次材料或确认答复已直接给出足以验收的结果与限制 | 简明表达这些事实，保留来源；不为材料未写版本号制造问题 |
| 验收须遵循另一份规则，已取得其适用内容、名称及实际版本 | 在 AC 简明引用该名称/版本及必要范围，详细内容留原规范 |
| 仅提到规则存在，决定验收的内容或所用版本仍未取得 | 保留已知交付结果，把具体未明部分列为局部待确认；“已有定义”的陈述本身不能关闭该缺口 |
| 缺口已使目标、基础方案或责任无法界定 | 进入本页有限澄清/补料出口 |
| 只是实现背景，不影响交付结果或边界 | 保留必要来源即可，不因缺实现手册新增待确认 |

同一缺失约定影响多项时合并问题，说明缺什么、影响什么、当前采用什么；不按措辞逐条提问。查询条件、迁移映射、权限或发布判据都用同一原则。基础已足够界定的首稿不因局部规则缺口反复找资料。

生成对象后，将未明部分绑定实际 Story/AC，沿 [备注与问题](generate-slices.md#备注与问题的目标) 输出，使相关行显示待确认。已知 AC 仍保留，未取得的规则不写成已确认前提；如果该条 AC 完全无法成立，保留相应字段缺口。只有实际补足内容/版本或用户明确改变该验收承诺，才能由 clarify 处理对应问题；无关定档决定不替代验收依据。

## 读取入口和证据

先登记不可变原件，再按目录、相关主题和必要邻域读内容；实际 source_ref 由区域响应取得。UTF-8 文本和 XLSX 的读取表示、身份及硬上限查 [读取表示与边界](tools.md#读取表示与边界)，目录原型见 [原型输入](prototype-inputs.md)。不支持的格式给具体补料要求，不安装 PDF/DOCX/OCR 或转码服务。

目录仅用于导航。分页跨越一个业务条目时，继续读齐表头、合并锚点、跨行说明及相邻限制；附注和隐藏内容按其相关性读取，不因隐藏而省略。大正文使用返回的附件和地址，零命中、未读和解析限制保留原范围。

## 边界、分页和用途

首次覆盖可以正常分页，沿实际 next_cursor；来源或 selector 变化时明确开始新查询。页数不计作澄清轮次，也不代表全部语义已分析。

一文件可承担多个用途，但每种用途必须有实际区域支持，不能只贴 PRD/HLD 两个标签。XLSX 首登 `use_regions=[]`，实际读取后再用 [区域助手](python-client.md#用实际读取结果登记用途区域) 登记。新增用途复用物理读取，相关新分析使用新的 topic_version_id；旧主题的含义不被自动扩大。

往期 SOW 用于估算 as-is，其余本期资料和 draft 用于 to-be；旧模板/标准只作历史内容，当前估算规则来自项目绑定模板。

## 历史理解与有限补问

先区分历史实际范围、附注、标准目录和示例，保留取消/排除/未交付/未来范围的限定。历史索引只保存原有标题、说明、来源、层级及已知实例事实，缺 AC/Task/type_hint 不补造；部分重叠的条目分别保留。

API/事件同名或同类型只是候选线索。结合已知系统、对象、读写/触发含义和适用边界判断实例；这些不是强制补齐的历史字段表。按用户给的往期 SOW 建立估算现状，不另设生产核验。

| 匹配结果 | 本期处理 |
|---|---|
| 相关读取后没有候选 | 默认新建，不制造泛化复用问题 |
| 有具体候选，实例及本期适用性未明 | 默认新建，留下具体候选与匹配范围的待确认；同根因多目标合并 |
| 同一实例及适用性已有依据 | 判断已满足、调整或接入复用，不例行重复确认 |

`inspect/topics` 的 uses/historical_label 查询用于定位稀疏历史及零命中范围，语义仍由 Agent 判断；选择器见 [登记与查询](tools.md#i12-登记与查询)。补充历史只复核相关候选和原零匹配范围。

## 有限澄清与退出

- **提问**：影响目标、基础方案、责任或输入冲突的事项合批问一轮，最多补问一次。先采用已答部分；补问能改变推进结论才使用剩余额度。
- **调查**：输入、历史、原型共用至多一次追加调查，目标集合提前限定。首次正常覆盖/分页不占追加次数，纯定档未知直接交给生成的 M+待确认出口。
- **结束**：用户不知道、需另备整份资料、无实质进展或到限时提前退出；基础不足给具体补料清单，只有局部缺口则带问题出稿。

等待前保存实际问题、答复原话、采用/仍缺事实、主题关联、最终去向及已耗次数。新材料只读受影响范围；压缩、重启、换片或用户仅说继续不刷新额度。无答复不推定批准。
