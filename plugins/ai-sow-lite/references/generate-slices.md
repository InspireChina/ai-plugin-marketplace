# 联合生成、公共归属与合并

骨架、片内生成和合并共用本页专业规则。输入充分性与历史判断见 [输入分析](input-analysis.md)，序列化和工具调用见 [候选编写](generate-authoring.md)。这些是 Agent 的判断职责，不增加程序门禁或独立评审阶段。

## 目标与验收属于谁

按目标组织 Epic → Feature → Story。一个 Story 交付一个可说明的成果；独立角色目标、成果或可独立验收边界才构成拆分理由。同一目标的正常、失败、权限边界通常在同一 Story，不能按页面章节、AC 条数或 Excel 行高拆分。

**SOW 中的验收条件，是对某项交付范围完成后必须满足的、可验证的业务结果和关键边界的简明约定，用于判断该项交付是否符合约定。**

它回答“交付后能做什么、达到什么结果、有哪些必须满足的限制”。用简短条目表达，无需 Given / When / Then 或完整测试步骤。可用句式：在［必要条件］下，支持［业务能力］，产生［可验证结果］，并满足［关键限制］。读者应能判断通过或不通过，避免“功能正常”“页面友好”“接口开发完成”。

| 交付项 | 写法示例（不为项目补充规则） |
|---|---|
| 工单提交 | ① 必填信息及业务校验通过后，由草稿转为待审核。② 校验失败时提示原因，保留已填内容，状态不变。 |
| 工单查询 | ① 支持按工单号、状态、创建时间筛选并分页展示。② 列表、总数及详情访问受组织数据权限约束。 |
| 审批后自动下单 | ① 审批通过后发起下单，成功后关联订单号。② 下单失败不改变审批结果，可查看失败状态并自动重试。③ 重复触发或重试不产生重复订单。 |

只保留决定交付是否达成的结果和关键限制。已约定的关键阈值不能删改；字段、报文、状态码、参数和测试步骤留在实际来源中，不逐项复制到 AC，也不转塞备注。简明化不删除实施工作或增加 Story/Task，页面/API 共同服务一个目标时，AC 表达共同结果及必要差异，Task 按实际工作单元拆分。

涉及“已定义条件、既定映射、现有规范”等引用，按 [引用中的缺口](input-analysis.md#引用中的缺口) 判断依据是否真实具备。将分析时留下的缺口绑定到本片实际 Story/AC；不能只保留模糊 AC 或给另一个 Task 留问题。Excel 写全简明 AC 和实际问题，不用 details.md 等外部指引替代正文。

业务 Story 验收业务结果；技术 Story 验收提供的能力及关键使用限制；交付 Story 验收可检查的成果和责任边界。公共能力建设只验收、计量一次，业务消费处写实际效果。独立 NFR 成果可单列，局部 NFR 归适用 Story，项目级约束留主题/依据。

从输入主动识别迁移、演练、上线准备和外部依赖。资产建设与实际执行分别判断，只有各自形成标准中的独立成果才分项计量。外部承担的生产执行、数据准备或验收保留为必要前提/排除。SIT/UAT 适用性由模板计算，不自动产生测试执行、部署、PoC 或设计工作；基础方案不足不能改建 Spike 来出稿。

## 备注与问题的目标

| 内容 | 写入位置与来源 |
|---|---|
| 已知验收行为、结果和关键限制 | Story.acs；来自已确认输入，不在备注重复 |
| 省略会误解交付边界、且 AC 未表达的已确认范围/责任/外部前提 | Story.notes；仅取 PRD/HLD 明述或用户真实答复的必要结论，通常为空 |
| 非新建工作方式、非 M 复杂度的采用原因 | Task.classification_basis.rationale，fields 标明维度；连接本期事实、既有实例及实际标准，不另抄 notes |
| Task 必要且有依据的其他补充说明 | Task.notes，通常为空 |
| 未知且影响范围、验收、分类或责任的事项 | pending_items 的 question、current_handling 和准确 targets；不重复抄入 notes |

历史 SOW 不证明当前责任或已确认复用；原型支持实际观察到的行为，与文档冲突则记录问题。客户已明确承担且足以界定本期工作的资源，不因尚未实际到货就新增催办问题，也不声称已就绪。已确认说明只保留结论，不复制来源段落、分析过程或问答历史。

问题按真实影响落行：

- Epic/Feature 问题投影到受影响 Story 行；AC 问题标明哪条 AC。相关 Story 行的校验结果为待确认。
- Task 问题只落 Task 行。同根因还影响 Story 范围或 AC 时，Agent 显式追加对应 targets，不自动上卷。
- 同一缺口可绑定多个实际目标；当前处理如实区分已明确与未明确，不能把所需前提写成已具备。
- resolved/superseded 只保留项目历史，不留 Excel 备注。采用答复后把仍有用的结论放 AC、必要 notes 或分类依据，不留“已确认”流水。
- 无 Story 的未拆明 Epic/Feature 由投影器追加范围行，Story/AC/人天留空；不为显示缺口伪造对象。

投影器合并备注和问题，并仅展示适用的非新建/非 M 原因，去除完全相同的正文。新建/M 原因不额外展示，默认 M 的未知仍通过原问题表达。安全别名、来源路径等机械说明不由 Agent 预写。

## Task 的实际单位和分类

先识别本片实际交付对象和成果，再匹配项目绑定模板。`inspect/standards` 空 selector 取目录，按片合批读取候选类型的单位、成果、模式、包含边界和规模门槛。复用有效读取；只有具体歧义才比较相邻类型，不逐 Task 强制找 challenger。

每个 Task 按标准基础单元计量。两个独立查询目标不能仅因同类型合成一个单位；多个 AC 描述同一交付对象也不各建一份实现。

| 工作方式 | 判断依据 |
|---|---|
| 新建 | 本期新对象；现有平台承载新业务对象不等于接入复用 |
| 调整 | 有依据的同一实例发生实际变化，只估本次变化及必要回归；SOW 文本改稿不算实施调整 |
| 接入复用 | 已知实例确实适用于本期，只估项目侧适配；消费者标准已包含的普通配置/调用不另计 |

方式必须是当前标准允许的值。分类依据同时连接本期事实和实际标准行，说明成果/单位/模式/档位；不能只看类型名或“旧项目”。

## 未知的有限出口

| 缺口 | 当前处理与绑定 |
|---|---|
| 仅复杂度无法从已读材料和标准识别 | 立即 M + 该 Task.complexity 待确认，说明未知量与当前口径；不再搜索、回读、重试或追问定档 |
| 有具体历史候选，实例适用性未明 | 新建 + Task.work_mode 待确认，保留候选与匹配范围；同根因合并 |
| 其他局部字段未知 | 按合同留 null 或空 AC，绑定真实字段；未知和明确不适用分开 |
| 已知多个独立标准实例 | 按已有边界有限拆分，不能因同类型合并计量 |
| 已知超标准单元但无法拆明 | Epic/Feature/Story 对象级问题，unestimated_work=true；已有 Task 不冒充覆盖剩余工作，M 不掩盖已知 X |
| 目标、基础方案或责任不足以界定本期 | 保存输入补料要求，不替用户选方案 |

已有 S/M/L 依据不被默认值覆盖。标准 X 先判断能否按已知边界拆成独立单位，Task 只接受 S/M/L。局部未知随初稿交付，未拆明义务须在摘要/问题中可见。

## 一次语义整合

从骨架覆盖和有关联的 Task 检查归属，不做全量两两评审。重点看公共建设/消费者、集成/内部同步、迁移/内含核验、IaC/普通配置、测试资产/执行：同成果不因类型名不同重复计量，不同成果也不因同来源删除。

合并时确认本期义务各有候选或明确缺口，输入问题各有解决依据或实际目标，项目级约束和外部责任有去向，跨片关系与 AC 归属正确。公共范围变化只修直接依赖片。正式模型不包含业务层级 slice_id；full check 验证引用完整性，业务充分性仍由 Agent 负责。

## 有界返修和恢复

| 环节 | 上限与退出 |
|---|---|
| 正常首次覆盖 | 每个已登记目标首次处理一次；有限分页可继续，不用返修额度截断大项目 |
| 同范围重新分片 | 最多一个批次，不反复拆片扩大目标 |
| 自动返修 | 同候选最多一轮，全请求最多两个批次，先到限即停；片内、跨片、机械错误按根因合批 |
| 工具/Excel 重试 | 同操作/根因最多一次，并占上述总额度；无实际修法、同根因再失败或无进展即停 |
| 响应丢失/中断 | 至多一轮结果查询恢复；已生效返回原版本，事实仍不明或持续繁忙则保留退出 |

每批先写有限目标与修法，结束记录结果和消耗，复用有效前序。不把每次 CLI 调用当一轮，也不把故障改称待确认来绕过检查。render/有限编辑工具已记录的额度先复读 checkpoint，不重复扣除；纯专业次数由 Agent 保存。

恢复读 activity-record、checkpoint、current 和有效候选，继承已耗次数；取消即结束，未知计数不归零。换 UUID、换片、重启或仅说继续不增加额度；真实新增目标/材料只定向续接并记录关联。已有 current 的 generate 不重写首版，现版修改使用 Clarify；Clarify 另遵守其具体计划与确认合同。
