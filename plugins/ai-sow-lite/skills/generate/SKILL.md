# 生成本期 SOW

由一个主 session 完成输入分析和片内 Story/AC/Task 联合生成，交付同一有效版本的 Excel、摘要和待确认事项。资料足够就推进，初稿不设审批或定稿阶段。专业范围、依据、分类与去重由 Agent 判断；工具只处理读取、身份、引用、模板投影和可靠保存。不启动 subagent，不调用模型 SDK 或选择模型。

## 开场与接收

复用用户已给的信息。开场只核对新/旧项目、PRD、HLD 路径；旧项目另需往期 SOW，原型可选。缺必需材料时立即列具体缺件并结束本次推进，不以长问卷、Epic/Feature draft 或零工作版本代替完整输入。非原型材料当前支持可读 UTF-8 文本和 XLSX。

从**当前已加载的本文件位置**定位 `<plugin-root>`：`skills/generate/SKILL.md` 所在目录向上两级。项目目录使用用户项目，插件副本拥有全部运行依赖。首次执行读 [命令与编写](../../references/generate-authoring.md) 的启动和登记部分；使用 `<plugin-root>/scripts/bootstrap.sh` 或 `<plugin-root>/scripts/bootstrap.ps1` 自举，随后直接使用该副本隔离 Python 调用 `<plugin-root>/scripts/lite.py`。沿用一个逻辑 request_id，不把每次工具调用变成新请求。

登记原件和项目身份，保存缺件/可读性结论。已有项目先查看请求和 current：重复调用优先恢复已有结果；本入口只创建首版，不覆盖已有有效版本。压缩续接沿用原候选、依据及已耗次数。

## 全输入分析

读取 [输入分析](../../references/input-analysis.md)，按目录和相关主题覆盖 PRD/HLD、旧项目历史、实际补充输入及未读面，复用已有有效读取。历史用途、稀疏条目、实例匹配及有限澄清以该参考为准。目录原型及已有观察按 [原型输入](../../references/prototype-inputs.md) 登记资源、实际观察和附件；观察目标与路径由本主session决定，复用已有适用记录。运行条件或观察能力不足时保留限制，影响基础充分性才要求补充材料，不能把源码或模拟成功当成真实后端证据。

在本请求 work 中形成 `analysis.json` 及简短 `input-review.md`：必要依据与主题、稀疏 as-is、业务/技术/交付三类本期 gap、外部责任/排除、已读和未读范围、输入问题及覆盖。登记工具保存不可变分析。由 Agent 判断目标、基础方案、责任是否足以继续；读取完成或 Schema 通过本身不表示充分。

## 按需澄清

只问分析后仍影响推进的输入事实、冲突和决定，按业务/技术/交付关联合批。依照输入参考的首轮加最多一次补问，保存实际问答、采用/仍缺事实、问题去向和已耗次数。充分时直接继续；两轮后仍缺基础就列补料清单结束，局部未知移交生成。未答复、用户离线或仅回复背景均不表示批准；也不要求用户批准骨架或初稿。

## 骨架与分片

进入拆解时读 [联合生成与合并](../../references/generate-slices.md)。从有效 gap 按目标、依据、责任及公共建设/消费关系组织 `skeleton.json` 和 `slice-index.json`，不预先生成全量 Story/AC/Task 再分片。

骨架保留 Epic/Feature 的 ID、标题、依据、预期责任及公共归属；片索引含 `slice_id`、目标对象/主题、公共边界引用、`candidate_path`、完成/限制摘要。它们仅为本请求工作文件，不是新增稳定领域模型。每个本期义务应有片或明确局部缺口；片数、先后和大小由实际关联决定，不按页数或固定 Task 数切分。

## 片内联合生成

每片使用其主题/原文定位、骨架邻域、公共边界及相关标准，联合形成来源 AC、实际 Task 单元、分类和待确认。标准按片合批查询、分页续读并复用有效结果；专业判断按联合生成参考执行。

复杂度无法识别时立即 M+待确认，不再为定档搜索、回读或补问。相关历史候选实例不明时按新建+具体待确认；基础方案缺失仍走补料出口。已知超界工作不能涂成 M。

将本片候选写到 `slices/<slice-id>/`，必要时按 [编写参考](../../references/generate-authoring.md) 组织三份业务 JSON、依据与候选引用并做 slice 检查。旧片正文留在文件里，新片只带必要引用。跨片未决关联先保存在 work，以骨架对象/主题和关系含义定位，不能猜正式 Story ID。

## 合并与交付

完成各片后做一次语义整合：核对骨架义务、公共归属、关联 Task 的包含边界、跨片验收及输入问题去向；绑定正式引用，只修改实际冲突范围。此时才形成首份完整 `merged/candidate.json`。局部已知未拆明工作保留对象级问题；有充分分析依据确认全部本期 gap 为空时才允许“本期无新增工作”，不造占位层级。

沿联合生成参考的有界返修规则记录修正，完整 `check` 无诊断且允许 render 后，调用 I1 `render` 和 `apply`。真实计算、核验或保存失败必须返回诊断与可恢复文件；不能当业务待确认交付假成功。模板是计算唯一权威，Agent/Python 不编造或计算人天、倍率、公式及取整，不手改正式 XLSX 或 current。

成功后只返回有效版本、Excel、摘要、待确认文件及关键未决事项；有 details 时一并链接，不在聊天重复整份 SOW。有效版本以 apply/recover 的事实为准。未生效时明确保留位置、失败或补料原因。观察记录可按编写参考在实际活动/等待/交付边界合批标记；未知耗时/token 保持未知。

## 有限执行与续接

输入补充调查和提问的边界由输入参考维护，生成/返修/恢复边界由联合生成参考维护。每批是有限目标集合，不是一次工具调用；不以换片、重开请求或压缩刷新额度。把活动、已耗次数、进展、未决和候选位置存回工作文件及已有 checkpoint。文件化只减少后续注入，不宣称清空聊天历史；计数仍不可恢复时停止，不按零重新生成。

面向用户的说明及业务自由文本用简体中文；Schema 属性、枚举、ID、路径、标准名和公式保留合同原值。工作目录可能含客户衍生资料，不写入插件安装包或公共仓库。
