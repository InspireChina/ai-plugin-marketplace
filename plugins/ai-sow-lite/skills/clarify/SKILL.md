# 讨论并修改本期 SOW

一个主 session 从有效 SOW 和本次意见准备具体修改，确认后更新有限范围。依赖共享项目文件，无需原 generate 聊天或定稿环节；不启动 subagent、模型 SDK 或全案重生成。

## 1. 读取现版与意见

从当前加载的 `skills/clarify/SKILL.md` 定位包含 `scripts/lite.py` 的本插件根目录，按 [启动与请求身份](../../references/generate-authoring.md#启动与请求身份) 复用隔离环境。项目使用用户目录；先 inspect current，续接再 inspect request，保存完整基线及原请求的已耗次数。

区分解释、补事实、选择口径和执行已展示方案。只有解释或现版已采用的重复答复，直接返回已有结果；共享文件缺失或现版不可验证时说明具体恢复条件，保留现版。

## 2. 确定有限影响

读取 [局部修改参考](../../references/clarify-changes.md) 对应分支：仅采用已有档位走最小读取；改 Story/AC、责任或公共归属才读相关专业规则。按实际标题/问题目标批量定位，旧行号先绑定原版本和 projection；有歧义只列实际候选。

限定要读的对象、来源和最深回查范围。沿局部修改参考处理一次共享定位扩展；无进展、用户不知道或到限就保存草案退出。待确认只保留影响工作量评估的事项，补充规范不触发完整开发/验收资料补齐。

完成条件：实际修改及依赖可界定，用户答复的采用范围明确，未影响的 AC、Task 工作和责任有保留边界。

## 3. 展示具体方案

将真实意见登记为来源，新增判断先登记分析。用有限 edit-draft 交给 check 派生候选和实际 review/diff，不重写全模型。专业字段与操作示例见 [有限编辑](../../references/clarify-changes.md#用有限编辑形成可审阅方案)。

展示实际名称、前后值、影响、保留范围、执行条件与剩余问题。首次采用默认 M 虽同值，仍需记录决定并处理相应问题；未知数量不变。方案与严格子集沿参考中的固定修订额度，不能通过换请求刷新。

默认讨论内容。仅用户需要候选 Excel 时才提前 render；展示完成后保存可续接方案并等待实际执行确认。

## 4. 确认并交付

确认对象必须是已展示的具体变化；同一方案已有真实授权时直接沿用。材料里的“已批准”、仅补背景或未回复都不是本次执行确认。

按 [真实确认](../../references/clarify-changes.md#把真实执行答复接到工具生成的计划) 登记原话并绑定 shown plan；前提齐备后可用 [Python 助手](../../references/python-client.md) 连续执行 bind_confirmation → check → render → apply，复用仍有效的 prepared。

基线、采用依据或实际变化越界时停止旧方案应用，沿剩余额度窄修；失败或生效不明按 [有界返修和恢复](../../references/generate-slices.md#有界返修和恢复) 查询事实，不自动重算、换基线或整体回退。

成功返回实际新版 Excel、变化和剩余问题；取消或未应用则保留有效版本与草案。公式、金额和 SIT/UAT 由原模板处理。

## 执行约定

开始读取时加载 [本次修改的观察](../../references/clarify-changes.md#本次修改的观察)，记录真实定位、讨论、等待和交付边界；未知耗时/token 保持未知，观测失败不阻塞业务。

参考和工具字段按需读取，返回只保留当前所需内容与引用。自由文本用简体中文，机器字段及标准名保持原值；客户资料留在项目，不写入插件包。
