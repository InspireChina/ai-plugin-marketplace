# I11 · 待确认只服务工作量评估

2026-09-11，基线 `5c47c40`。用户明确：SOW 用来评估工作量，不承担开发指导；`01-需求故事` 中不影响工作量评估的待确认无需记录。本次据此修正 I10 把规范/验收资料完整性当作问题入列标准的做法。

## 当前规则

权威判断集中在 [输入分析](../../../references/input-analysis.md#引用中的缺口)：不同答案是否改变本期范围、Task 单元/数量、工作类型、工作方式、复杂度、集成类型或本方责任；应能依据实际材料指出哪部分工作会变化。没有这些影响的细节，不新增问题、不转存备注或独立待办。简明 AC、已有关键边界和已确认责任仍保留，未取得的事实不编造。

Story/AC 只承接范围和交付成果有关的估算问题；纯 Task 档位/方式问题留 Task 行。复杂度未知 M+待确认、具体历史候选不明新建+待确认保持。原模板继续按真实 open 目标显示待确认；不在投影代码中猜测哪些问题应隐藏。

Clarify 清理旧问题时先展示具体目标和不改变工作/分类的依据，确认后记录撤销追问的 scope_decision，按原合同 resolved；处理说明明确事实并未补齐。混合问题保留真正影响估算的部分，原版不覆盖。新版规则不会自动重写已有交付文件。

## 已有失败与定向验证

RED 直接复用 I10 的实际结果：在已限定查询条件规模、单一权限、14 字段一对一映射、不清洗、标准六步发布且责任已答的材料中，生成了查询规则、映射明细和发布规范三个问题。按本次用户口径，这三类追问没有具体工作变化依据，应移除；迁移数量未知导致 M 定档的问题仍需保留。I10 的原产物、失败记录、成本与字节不改写为本轮结果。
