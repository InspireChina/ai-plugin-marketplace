# I4 输入与复杂修改验证

本记录区分物理/保存机制、真实原型观察和从原始材料生成的专业结果。场景目录与阶段状态以 [P04](../implementation/P04-scope-and-performance.md) 为准；执行取舍见 [自主决策](implementation-decisions.md)。

## I4.1 原型、多用途输入和 BA 草稿

原型采用用户明确给出的目录包。登记一次保存排序清单、所有普通资源的原字节和摘要；读取器不运行代码或规划点击。上限为2048成员、16层、50 MiB。目录枚举和读取绑定已验证的目录句柄；平台缺少必要能力时明确拒绝，不降级为可能越界的读取。文本和Excel的既有来源路径保持兼容。

观察沿用现有合同，保存实际入口、前置、动作、结果、限制与必要附件。原始观察 JSON 不重写；附件采用为不可变文件，原 work 路径保留为原始记录说明。同源多个主题复用观察，新增观察需要新主题版本；完整检查核对原始分析、主题拆分、登记引用、资源和附件。交付的待确认来源说明显示具体包内路径/行号，或观察编号/附件/区域；判断结果沿依据回溯。程序能核对身份与字节，不能证明观察或专业判断为真。

### 真实观察

自包含 [原型夹具](../../../tests/fixtures/prototype/package/index.html) 使用本地模拟数据及自己的临时服务。独立观察者在 Codex 内置浏览器执行静态与动态观察，首批6个目标，加一次清除/刷新观察；20次页面操作之外另有最初打开。保存17份可访问性状态和6张真实截图，退出后关闭本次页面并停止自己的服务。没有全局关闭浏览器或终止其他服务。

实见列表与详情同文案按钮属于不同路由；模拟成功只更新本地页面，不能证明后台实现。取消后的迟到响应保留了已隐藏的结果区并更新迟到提示；重叠查询间隔16毫秒，最终采用较新结果，**没有强制逆序完成**，不宣称穷尽迟到情况。静态存在但无法进入的审批分支记录未观察；详情缺少的运行行为仍按PRD义务处理，不据此删除需求。

原观察者仅将已勾选控件改为未勾选，得到一次变化计数。控制器另开独立页面作明确反例：初始已勾选/计数0，设置相同值后可访问性状态完全相同；再取消勾选，计数变1。调用成功不等于事件触发。原观察的“清除再刷新”只证明清除后的状态重置，不能证明刷新会清掉非空备注。这些限制随真实记录保留，后续生成可采用已有观察，无需为验收重演全部路径。

### 已修复接缝与 TDD

独立审查发现两项P1：一是完整检查已经接受的原型来源在导出消费处仍被拒绝，静态源码还错误显示清单名；二是目录检查后被实际替换为包外链接时可能摄入外部普通文件。均先用消费者或真实目录替换复现，再修对应接缝，没有增加专业返修阶段。

来源标签及旧失败重试首轮为4失败/1通过；标签修复后测试自身错误期待CLI抛异常，产生3失败/2通过。CLI本应将意外异常转为诊断，因此只修测试边界记录，最终5通过。该测试经过真实登记、分析、检查与投影，在Office入口主动停止；不是一次成功Office或空模型语义验收。目录边界首轮10失败，修复后新旧原型消费者46通过。

内部导出实现修订为`lite-render-v3`，投影合同仍为`lite-projection-v1`。旧失败记录可在原请求中消耗原有一次重试额度；旧成功文本记录必须完整核验才能复用。旧版本、尝试记录和额度不删除重置，模板原字节不变。

### 阶段结果

完整PRD/HLD、仅有Epic/Feature的BA草稿和实际观察共同进入独立生成会话，已形成2 Epic、3 Feature、5 Story、13 AC、5 Task和4项局部待确认。BA的两项Feature有效保留，两个独立查询API与运行部署说明从HLD主动补充；所有Task在缺少具体规模时采用M，没有重新调查规模。PRD要求的正文和详情局部状态没有因缺动态观察而被删除。Parent逐项核对实际AC、Task、问题与原材料；完整check已采用5份资源、2份观察和12份附件。

同一XLSX的历史与draft用途使用不同真实区域，机械测试证明原件只登记一次，采用分析分别记录。仅draft加tech note不足的真实退出复用[I2记录](I2-generate.md)，不再重跑相同负例。多历史修订/跨系统实例判断的更广语义组合不由本例推出。

定点复审通过，Reviewer独立21项无Office测试通过。Parent近邻156项含真实Office通过；完整Lite594通过、12跳过，包含真实复制交付消费者；旧插件388通过、4跳过，旧独立副本setup/generate通过；根测试42通过，仓库验证器及diff检查通过。逐项口径见[脱敏观察](I4.1-input-observations.json)。完整检查不是跨平台或所有专业变化的正确率。

真实render/apply已交付首版。Parent独立复核56个manifest文件/依赖摘要，其中22个为该原型清单、资源、观察、登记与附件依赖；两份观察的定位亦可从pending-items.md回查。没有新加Excel辅助列。等字节副本经Finder在Excel 16.112.3打开，无修复提示；实看Story/AC、备注后的SIT/UAT及Task分类/公式列。关闭未保存，原版与副本摘要仍相同。Excel自己的打开面板曾未启用Open，取消后换正常Finder打开成功，没有借修复功能修改文件。

另从真实已分析/形成3片草稿的快照接续独立会话，用户明确撤回PRD/HLD的本期用途，并说明暂时无法给出核心业务/技术/交付边界。会话更新受影响主题和工作索引、保留旧原件及分片，停止出稿；current和版本目录仍空。没有把旧范围继续采用、当作零工作、或用M和大量问题掩盖全案基础不足。已耗追加1批/返修1批未重置，没有新调查、问卷或Office。该停止变体补充晚期基础不足；默认M的局部未知正例由实际原型初版共同提供。

原型使用会话还暴露两个非业务接缝：一次标记误填活动名称而非UUID，正确降级后只记录真实后续边界；一次给不可读serve.py拼造text_lines位置，分析登记拒绝，删除不实定位、保留未读限制后在一批已有返修内完成。没有通过忽略来源检查放行。记录物理未读资源时应保留其目录/限制，不伪造可读行号。

I4.1范围已完成；更广历史组合、复杂改稿和性能口径仍由后续记录限定，不将本次语义样例推广为所有材料的正确率。

## I4.2 复杂修改

本阶段增加专业r1/r2之外的固定返修/子集保存槽，保持同一请求、原基线和有限次数。首次专业方案加最多一次修订；每候选一次机械返修、请求共享两批、每根因一次；每专业方案最多一个严格子集。相同稿复用，失败稿保留。工具核对具体差异、身份、引用和前提，业务独立性仍由Agent判断。

### TDD、审查与机械组合

独立审查首先发现两个接缝：确认的永久依赖错误包含临时work/实时索引；实际选择答复追加后，纯子集重算读取版本使合法定向读取失效。前者Red为1失败/1通过，后者Red为1失败/6通过；修复分别2通过、7通过。原显示方案的read_set与原输入快照由严格子集继承，选择器、边界、条件保持；原完整候选仍完整复核。稳定来源/分析/历史保留，原显示字节随有效版本归档，不能靠删前提放行。定点独立复审9项通过、无未解决finding。

[组合回归](../../../tests/test_change_combinations.py)覆盖拆分/合并、未变AC/Task身份、精确lineage、部分答复及问题revision、未拆明工作补齐或明确退出、返修次数与子集槽、实际输入追加与过期拒绝。新增历史使原零匹配范围读取失效，旧计划停止，程序不自行改Task模式。新历史专业判断复用[I2](I2-generate.md)的稀疏实例、明确实例和无gap正反例；不将机械失效测试称为新一次专业历史分析。拆合与未拆明去向用完整文件变体验证，不声称每种拆合都另跑了宿主。

真实子集消费者经过check、一次Office、apply，再追加后续输入并recover，证明新旧版本、原显示方案归档和稳定依赖仍有效；这补充了只调confirmation_files的初步测试。I3的原模板/基线/候选失效、重复答复与M同值新决定消费者继续复用，不扩大授权。

### 真实公共能力、PoC、周期核验与生产责任

使用[三组原始意见](../../../tests/fixtures/clarify/cases/shared-periodic-production/feedback.md)和已有真实交付基线，独立Clarify会话自行分析，未收到预制新模型/ID/分类或期望答案。先展示完整具体方案，再收到真实选择：**采用A和C，B暂不采用**。

A在唯一公共查询客户端增加可选场景参数，只有资料页实际传入，公告默认映射不变；页面适配和公共版本/必要验证包含在各自原Task，仍为尚待实施的新建。额外明确购买的离线AbortSignal PoC单列Story/Task，保留正常返回和取消后迟到两种受控情形、结论和不能支持的边界，按已读标准S，不扩张为架构重做。

B的实际专业候选区分一次性迁移内含核验和独立每日对账程序，保留一个源目标、14字段、差异/无差异报告及客户提供的运行前提；记录总量未知立即M+独立问题。**B只验证到专业方案**，选择后不包含其Feature/Story/Task或新增问题，没有B的Office交付声明。

C保留发布方案，另加一个生产环境/组件/团队/窗口的部署执行及需要时标准整体回滚。六步执行匹配发布执行M，六步方案仍按方案类S；生产资料迁移、独立迁移演练与正式验收保持客户边界。没有因既有流水线改成复用，也没有增加培训、平台或实际生产操作授权。

实际原方案60项diff，严格子集49项（含引用与业务变化），专业revision仍1。新版7 Story、9 Task，仅增加PoC与部署执行；公告Story/Task、两个API与原迁移内容保留，原迁移M问题原字节未变。Parent逐项核对输入、具体候选与最终内容，复核50个manifest文件/依赖摘要和全部旧版文件，原完整shown-plan按字节归档；没有可变work或实时索引成为永久依赖。

会话实际消耗两次机械返修：首次登记反馈用了错误文件位置；另一次自写阅读核验误把未采用B对象的名称视为review必需文本。前者改实际路径，后者核对真实diff/读取/文件hash；均保留记录，没有改专业值、提高限额或重开请求。一次Office和一次apply成功。

同字节副本通过Finder在Excel 16.112.3打开，无修复提示；实际查看公共库、PoC、生产执行Story的AC/备注及备注后的SIT/UAT、Task分类与公式显示。关闭未保存，原副本hash相同；窗口放大后恢复。没有改模板或估算口径。

### 独立持续同步变体

使用[实时集成原始PRD/HLD与后续意见](../../../tests/fixtures/clarify/cases/README.md)，初版执行者只先收到PRD/HLD，实际交付一个新建/M/外部集成Task及六条AC，取数与映射内含，没有独立同步Task。首版完整来源和文件摘要核对后，才提供新增独立日级同步意见，按Clarify形成具体方案。

方案保留原实时集成及六条AC，只将有关“无独立同步”的备注限定为原成果内部；新增一个独立版本、调度、启停、维护、验收的DATA-SYNC成果。六字段原值映射、另一个既有批量端点、批次标识、成功/失败及人工重试、说明/自测均含在该成果，不另计集成或公共映射平台，没有编造跨Story依赖。

实际分类为**新建/S，集成类型不适用**。当前模板S标准为单对象、≤20字段、单向、日级间隔、允许人工补偿；每日记录量不属于该行的分档维度。因此未知记录量留作问题，不错误扩大“识别不出复杂度才默认M”的授权。原实时规范/订单口径/样本问题仍open，候选合计两项问题；不补造吞吐或完成时限。

Parent读取实际分类依据与模板标准，核对原Task的分类/六条AC及全部旧版文件保持。此次**新增同步只验到已检查专业方案**，未收到执行确认，不运行第二次Office、不改变现版；保留这一边界，不以方案当已交付。

### 复杂历史、关键冲突与输入权威

[合成输入](../../../tests/fixtures/generate/cases/history-conflict-and-input-authority/README.md)包含系统A原SOW及仅替换查询Story的增补、较新的独立系统B同名API、R1与R2发布事件，以及PRD只读和HLD/原型审批冲突。独立会话读取全部文本和原型源码：A取消的API不能作为复用依据，报表不是实时服务；增补不删除其余A历史，B不因较新或同名取代A，R1发布不抵扣R2新交付。

会话把审批是否纳入、查询服务责任和缺失的授权/审计基础方案合批提出。实际收到“现在无法决定，先保留”后保存原件、分析、问题和答复，沿同一请求退出，无骨架/候选/Excel、无check/render/apply，追加调查及返修均0。没有用新建或默认M补造基础方案。

原型仅静态显示生产POST及权限/审计意图，未开浏览器或调用后端，没有伪造动态观察。材料中的导出全文及假批准语句未被视为操作授权，测试哨兵文件未生成。该受控原型没有真实可写后端，所以这里只证明此输入下的权限判断和来源处理，不宣称测试了真实生产安全或所有注入形式。
