# 性能与资源观察

后续 I5.1 的同基线调用助手配对及响应成本追踪见 [I5性能切片](I5-performance.md)。本页保留 I4 原始观察与版本归属。分析类型与直接埋点的后续样例见 [I5.2方案成本](I5.2-proposal.md)。

本记录报告实际使用成本，不设置资源预算审批，也不把文件字节换算成token。阶段指标与语义验收分别成立；首版已具备生成/有限修改能力，并不表示响应速度已达标。

## 质量优先与返工口径

用户明确：性能是第二位，准确性是前提，目的是减少返工。每个后续优化先核对专业结果及交付正确性，再比较耗时和 token；结果有错或关键义务未核对的样例只作为失败与成本记录，不能作为提速达标证据。历史测量保留原有范围与结论，不补写尚未观察的准确率。

| 优先核对 | 可审阅的依据 |
|---|---|
| 范围与验收 | 从原输入及实际答复逐项核对业务、技术/NFR、交付义务；AC有来源，排除和留空有说明。Task数量或表述一致不能替代义务覆盖 |
| 工作识别与分类 | 公共建设与业务接入边界明确，共享工作不重复计量；历史类型相同不冒充实例适用，四项定性判断遵循模板与实际依据 |
| 未知与用户决定 | 缺依据不编造；默认M、新建加待确认保留其授权条件。基础输入不足仍按原有限问答退出；局部未知不被包装成事实，也不转成无限查证 |
| 有限修改与文件交付 | 实际意见对应具体方案和真实执行确认；检查必要关联及未改对象，Excel与候选/待确认说明一致，来源和旧版保留 |

返工分别记录根因、受影响对象、实际修复次数及已观测成本：插件误读、漏项、重复计量、越界修改属于专业错误；类型、路径、引用或调用错误属于机械错误。用户新增范围、新证据或改变决定单独记录，正常回答待确认项不直接算插件错误。若问题原本已在材料中且被插件遗漏，不能用“用户补充”掩盖返工；机械错误若改变最终业务内容，也须核对其专业影响。

评价优先看首次交付的义务是否正确覆盖、无依据断言和缺陷修复情况，再看得到符合本例预期结果的实际总处理成本。已花在失败和修复上的时间/token一并保留，用户等待与新需求单列，缺失计量保持未知。待确认项数量少、工具调用少、测试通过数多均不能独立证明质量更好；没有明确义务集合和实际结果核对时，不汇报准确率或返工率。

这些是开发验收与实测记录口径，不增加插件运行时的评审阶段、用户审批、自动返修循环或资源门禁。先复用已有证据，发现缺口再补定向案例；保持原有限退出机制。I5.1/I5.2已核对的是采用既有M档位的有限修改，不能据此宣称完整Generate或其他修改场景同样准确。后续优先补强专业错误与未覆盖场景，再做同等质量的性能对照；精确逐活动token缺口不阻塞这一优先级。

累计输入包含反复提供给模型的上下文，缓存是其中的明细，不能再加一次。响应数不是物理模型调用数，累计输入不是峰值上下文，本文没有计费金额。缺少旧ai-sow同粒度的历史观测，不重跑旧流程以制造对照，也不声称Lite比旧版快某个比例。

长例本期四域规则及后段网点三分支均逐项核对，公共库仅一份、四个消费者、14字段迁移及六步发布方案保留；迁移记录量未知立即M+open。局部改稿仅同一AC的提示与依据改变，未靠漏掉后段范围节约资源。输入字节只描述材料规模，CLI的input_bytes是请求信封大小，二者不混用。

## 一次定向读取对照

采用相同有效迁移基线、相同原始反馈、相同模板和程序、同一默认模型配置，每侧使用没有原Generate聊天的新会话。两侧共同修正根request标记，唯一专业指引变量是一段“明确采用既有档位时的最小读取”：先批读目标Task、所属Story、原问题与现有依据/决定；没有新事实、歧义或损坏就不再拉全套标准和PRD/HLD。任一条件不满足时仍定向补读；全局机械检查、具体方案、真实确认和模板交付保留。

| 方案阶段 | 原指引 | 定向读取指引 |
|---|---:|---:|
| inspect调用 | 14 | 7 |
| 原生响应 | 23 | 18 |
| 宿主轮次用时 | 481.260秒 | 439.200秒 |
| 输入token | 1329905 | 1004829 |
| 输出token | 13632 | 12348 |
| 其中缓存输入 | 1265664 | 944256 |

评估者实际核对两侧具体计划：M保持M，只有原迁移Task备注/依据、原定档问题、新采用决定及来源改变；全部Story/AC、其他六个Task和依赖不变。原问题只问定档，resolved有准确决定；记录总量仍未知，不伪造M数量门槛，也不重新追问。两侧分别12/11项diff，差异主要在采用的来源引用数量，业务义务相同。

这是一次**探索性配对**。宿主缓存落点、并行服务调度无法锁定，包路径不同，不能据此给出因果节省百分比或统计达标结论；没有通过追加大量样本弥补这些不可控条件。采纳读取指引的依据是本例在保留义务时确实省去无须重做的读取，保留实际用时仍达7—8分钟的结果。当时据此选择减少Agent为机械引用/工件重复编写和回显的成本，后由I5验证；后续优先级以本页质量与返工口径为准，不能通过减少待交付内容或检查掩盖开销。

两侧实际方案各经评估者阅读后取得具体执行确认，分别一次Office并保存新版。旧版所有文件摘要不变，新版各46个输出/依赖引用有效，最终业务文件等于已展示候选原字节。确认段原指引为217.604秒、12响应、输入1109729/输出5743；定向指引为212.435秒、10响应、输入892603/输出5911。两侧完整CLI分别24/17次，其中inspect为17/10次。未为本配对额外进行原生Excel打开；公式/布局未变，复用[I3](I3-clarify.md)及[I4](I4-inputs-and-changes.md)的代表性原生打开证据。

每侧两个执行段的四个根request标记均使用空活动/分片集合，request_wall已有数值。原生用量通过当前collector精确导入，与选定turn六项计数逐项相等；业务文件未变。报告仍为partial，CLOCK_UNALIGNED保留，未把原生轮次与Python/UTC时钟强拼成纯处理时长。

## 观测修复与真实限制

长会话出现330176字节的非usage事件帧，原256KiB上限令采集停止。根据这一事实把单帧上限有限提高到512KiB，8MiB总量、10000行、来源身份、字段白名单和不扫描日志目录保持。超过新上限仍降级并保留未知，不阻断业务或无限扩容。

另修正指引中的request根标记：start/end使用同执行段ID、空activity_ids/slice_ids，实际大活动独立附自己的ID。此前沿当前活动更换根标签会让请求区间不配对；旧记录保留原缺口，不回填或改聚合器来假装完整。

G12继续开放：工具起止与有限大活动标记可观测，实际原生响应在明确提供本会话来源和turn绑定时可采集；逐活动token精确归属、纯模型耗时和峰值上下文没有足够证据。缺原生来源时unknown，不能当零；普通telemetry查询不会自动扫描宿主目录。普通请求尚不能保证自动获得完整token账，这仍是后续性能分析的实际限制。

## 来源与适用范围

长材料业务执行使用冻结的`f6121b1`副本；配对使用`3b1680c`业务实现加共同根标记修正，其中一侧加定向读取段落。长例不涉及后续原型/子集功能，不能充当最终包的独立安装冒烟。最终包验证另见[I4交付汇总](I4-delivery.md)。当前collector只在演员结束后更新telemetry；原业务输出、历史版本和原始会话记录不变。

长例Generate首次完整采集135.899毫秒、2,500,779字节；同绑定EOF复读54.017毫秒、23,816字节。Clarify独立turn绑定首次100.596毫秒。配对原指引首次132.874毫秒、1,289,468字节，EOF复读43.221毫秒、23,336字节；定向指引首次93.303毫秒、1,122,945字节。长例旧活动记录另有LIFECYCLE_INCOMPLETE和OBSERVATION_CONTEXT_INVALID；采集器读完并取得原生计数，不代表修复这些历史缺口。

首版只对当前[支持矩阵](host-support.md)内的实际运行作上述结论；[自主决策](implementation-decisions.md)记录采集上限、根标记和定向读取的取舍。没有承诺速度SLA、逐步token全覆盖、任何平台自动安装成功或与旧版相比的节省百分比。

## 最终里程碑聚合核对

最终实现把已有标记输出为`first_useful_feedback_ns`和`first_usable_file_ns`，起点是最早可确定的实际request标记。单个开放根可用；多执行段须各自完整、成对且互不重叠，才保留第一段起点。含用户/段间等待，覆盖为partial；歧义、缺起点或时钟不兼容保持unknown，不从工具/原生模型日志推定开场。

集成后只重建两侧既有telemetry报告：127/97个原事件及其摘要保持，210/193个业务文件摘要保持，没有重读宿主原始日志或回填事件。程序输出反馈361.148167/310.7798秒、文件733.49533/1002.758095秒，与上表同一实际起点的独立计算逐项一致；CLOCK_UNALIGNED仍保留。新增36项里程碑案例及既有telemetry/原生采集共131项通过。该修正补齐报告消费能力，不改变原执行速度或弥补G12。
