# 连续实施中的自主决策

用户已授权：在既有分支持续完成 Lite 整体开发，每个 I1.4 这样的实施任务完成后提交一次；需要抉择时采用合理的最小方案，并保留可审阅记录。此授权不等同于向远端推送、发布版本或安装到日常宿主。

各项状态和证据仍以 [实施计划](../design/implementation/README.md) 及对应验证记录为准。本表记录实际发生的取舍，不把普通编码细节逐条升级为设计决策。

|---|---|---|
| AD01 / 全程 | 沿用现有主目录和 codex/ai-sow-lite-design 分支；从 I1.5 接续，不重复 I1.1—I1.4 | 符合用户指定目录。每阶段仅提交已验证的范围，保留可逐提交 review 和撤回的边界；I1.4 提交为 e05ebe0 |

### 用户明确：准确性优先于性能

此项来自用户直接指示，不是新增自主决策：先保证准确性以减少返工，性能居次。后续先核对业务/技术/交付义务、依据、工作分类与单一计量、有限修改和最终文件，再比较同质量成本；专业错误、机械错误与用户新增/变更需求分别记录，失败成本保留。具体口径见[质量与返工](performance.md#质量优先与返工口径)。

本次复核I5.1/I5.2差异：调用助手仍委托原六操作，原检查/确认绑定未移除；直接埋点只处理观察，未修改专业合同和模板。既有演练只证明其记录范围内的结果，不能用719项测试或单一M确认样例宣称普遍语义准确。此次仅同步设计及验收优先级，不新增运行时门禁、无限复验或模型调度，也不撤销默认M、新建加待确认的授权。
