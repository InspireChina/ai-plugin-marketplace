# 连续实施中的自主决策

用户已授权：在既有分支持续完成 Lite 整体开发，每个 I1.4 这样的实施任务完成后提交一次；需要抉择时采用合理的最小方案，并保留可审阅记录。此授权不等同于向远端推送、发布版本或安装到日常宿主。

各项状态和证据仍以 [实施计划](../design/implementation/README.md) 及对应验证记录为准。本表记录实际发生的取舍，不把普通编码细节逐条升级为设计决策。

| 编号 / 阶段 | 决定与理由 | 影响、代价与验证 |
|---|---|---|
| AD01 / 全程 | 沿用现有主目录和 codex/ai-sow-lite-design 分支；从 I1.5 接续，不重复 I1.1—I1.4 | 符合用户指定目录。每阶段仅提交已验证的范围，保留可逐提交 review 和撤回的边界；I1.4 提交为 e05ebe0 |
| AD02 / 全程 | 开发阶段继续 TDD 与独立审查；测试失败归因后修正对应范围，未改机制复用已有精确源码证据 | 不把每阶段变成从头全量专业演练。明确要求的完整套件、真实 Office 或独立副本验收仍执行；不能把旧快照冒充修改后验证 |
| AD03 / I1.5 | 复用 I1.3 原生 Excel 打开/保存/重开证据，只为独立副本及真实包中断新增验证 | 本项未变可见布局/模板时不重复人工开关 Excel；若改变投影或布局则补相应原生检查。Windows 未实跑则保留未验证，不扩大支持声明 |
| AD04 / 全程 | 使用开发子 agent 分工和独立审查；产品 generate/clarify 仍按一个主 session 串行完成 | 子 agent 只属于开发与隔离验收手段，不成为插件运行时依赖。语义验收每次从只含输入/必要指引的新上下文开始，期待与预制业务模型留在评估侧 |

| AD05 / I2.1，已决定待实施 | 除输入读取器外，允许最小扩展现有 validation 的来源核对接缝 | 实际代码目前仅接受 text_lines；若只增加 XLSX 阅读而不接来源核对，生成候选仍无法采用历史 Excel。读取器负责确定性区域摘录，校验器复用相同结果核对 hash，不复制第二套解析器或增加语义判定 |

| AD06 / I1.5 | 本项核对真实首版中全部已支持的原件/分析/模板依赖，观察附件和业务历史链分别在 I4.1、I3.3 接实际交付验证 | I1 的观察登记尚不支持，首版 Generate 也无已应用基线；不为勾选笼统依赖清单伪造这些工件，亦不提前实现 I3/I4。后续阶段必须补实际链路，I1.5 报告明确此范围 |

| AD07 / 连续实施审查 | 每个 I 编号独立审查本次差异及必要接口，发现问题定点复核；整体分支审查统一在 I4.3 收尾执行一次 | P01—P04 是同一次整体开发的分组，不在每个分组边界重复审查全部历史代码。阶段集成与真实使用验收仍执行；跨阶段风险最终统一复核，降低重复阅读成本 |

| AD08 / 文档维护 | 实施进度集中在实施目录、任务勾选及阶段验证记录，概要/专题目录引用这些权威入口 | 避免每阶段在多个概览重复复制测试数字和下一步，降低状态漂移；领域设计和已有证据仍保留，用户可从目录追到对应实现和提交 |

| AD09 / I1.5，后续 I3.3 | 接受审查的非阻断 Minor：现阶段记录实际收到的审计收据；I3.3 扩展完整使用周期时补逐 CLI 进程/操作与收据对账、启动/退出 stderr 检查 | 本次实际31份收据、零越界，代码已证实各调用继承审计环境；但数量门槛不能独立证明没有单个漏交。当前不把它称为全系统完整追踪，后续加固仅在测试支持层完成，不改业务运行时 |

尚未发生的技术取舍不预先当作已决定；后续按阶段追加依据及后果，重大范围变化明确标出。
