# I8 · 简明 SOW 验收条件

用户在I7结束后给出新的定义，直接替换旧写作口径：

> SOW 中的验收条件，是对某项交付范围完成后必须满足的、可验证的业务结果和关键边界的简明约定，用于判断该项交付是否符合约定。

AC回答交付后能做什么、达到什么结果、有哪些必须满足的限制。默认简短条目，不必Given/When/Then，不展开完整测试步骤；简洁仍须能够判断通过或不通过。规范引用注明实际版本，未知不猜。

## 本次调整

专业规则统一在 [generate-slices](../../references/generate-slices.md#目标与验收属于谁)，generate和clarify共同使用。删除促使Agent展开字段、状态码、允许值、重试参数和前态矩阵的写作要求；这些详细约束继续留在PRD/HLD/明确版本的规范及已有证据中。真正界定交付承诺的结果和关键限制仍写入AC，必要的性能目标不因精简而改变。

业务、技术、交付Story均按该定义表达；不新增实体、字段、条数上限、评审阶段或自动改写规则。精简AC不改变Story范围、Task工作或定档，也不把移出细节转塞备注。同步02领域说明、D04及两个入口；I7计划和rubric标为历史口径，旧输入、评测、模型及Excel保留。

## 实际材料的表达对照

以下是主任务基于既有合成资料的一次有限写法核对，供检查粒度；不声称已应用到正式Excel，也不计作新的E2E。来源为[二期PRD](../../tests/fixtures/e2e/greenfield-brownfield/phase2/PRD.md)（CC-P2-PRD，业务讨论稿1.0）和[二期HLD](../../tests/fixtures/e2e/greenfield-brownfield/phase2/HLD.md)（CC-P2-HLD，方案讨论稿1.0），保留其原件版本，不伪称为正式批准版。

### 工单状态变化告知服务商

1. 工单状态发生变化且当时已分配服务商时，自动通知对应服务商协作系统；未分配的历史变化不补发。
2. 发送失败可查看原因并自动重试；持续失败支持授权人员补发。
3. 重复发送或补发不产生重复业务更新，通知仍对应原状态变化及当时的服务商。
4. 通知不包含手机号或内部备注，发送与补发结果可追溯。

对应P2-B06/P2-T06。报文七字段、HTTP状态码和重试间隔留CC-P2-HLD方案讨论稿1.0第6节，不逐项复制；接收系统实现仍由客户/第三方负责，既有TicketOpened不变。可用未分配却外发、重复更新、补发改归属等结果直接判断违反约定。

### 保修方案初始迁移脚本与非生产自测

1. 可将保修方案文件导入目标保修数据，字段与清洗规则符合CC-P2-HLD方案讨论稿1.0第8节；非法数据不导入并报告原因。
2. 重复执行不重复导入，相同记录跳过，冲突记录不覆盖；可核对成功、跳过和失败结果。
3. 支持按批次回滚，仅处理本批且未被后续修改的数据；发现后续修改时停止并交由客户处理。
4. 交付可执行脚本及非生产自测结果，生产执行、核验与回滚由客户负责。

对应P2-B08/P2-T08。十字段的逐项长度/格式、两条映射、数据库处理次序不展开为AC。非法数据入库、重复导入、冲突覆盖或删除后续修改数据均能直接判失败；迁移范围与责任仍明确，数量未知和M档位保持。

### 更新二期上线与回退方案

1. 更新既有方案，覆盖本期页面、接口、状态通知和保修迁移，交接版本、配置、脚本及非生产验证结果。
2. 方案明确上线前提、失败判断及回退安排；回退后一期基本功能保持可用。
3. 方案区分应用/数据回退与外部已接收事件的对账处理，生产执行责任由客户承担。

对应P2-B09/P2-T09。备份检查步骤、具体暂停/恢复顺序与窗口细节留方案及来源中；不把“交付方案”升级为供应方生产上线服务。缺少本期迁移、未说明外部事件处置或责任混淆均不符合约定。
