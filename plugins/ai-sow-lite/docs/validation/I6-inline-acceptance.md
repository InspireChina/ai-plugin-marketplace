# I6.2：验收条件与待确认事项回到原表

本增量按用户对 I6.1 的反馈收敛交付。I6.1 的附表方案作为历史记录保留，不再代表当前行为。

## 行为与专业边界

- Excel 只有原模板四表。完整 AC 写入 `01-需求故事` 的验收条件列；不生成片段、完整说明表或外部正文入口。
- open 问题的实际问题及当前处理写入目标行备注，以 `待确认：` 开头。普通备注通常为空；不自动添加依赖、分类依据、证据 ID 或任务清单。
- AC 问题标明该行的 AC 序号；父级问题落到其范围内的 Story 行。尚未拆明的 Epic/Feature 使用原表范围行，只有实际父级标题与问题，不伪造 Story/Task 或人天。Task 问题只影响自身行。
- 校验公式先保留空行判断，再判断待确认前缀，否则沿用原校验。已解决/被替代的问题退出 Excel，项目历史 JSON/Markdown 继续保留。正常备注里的“无需待确认”不会触发状态。
- AC 按验收成果组织，由 Agent 判断层次及独立目标；没有 AC 条数门禁、自动摘要或按条数拆 Story。具体规则见 [联合生成](../../references/generate-slices.md)。
- 全文在原单元格保留；长内容的显示行高最多 409pt。超过 Excel 单格 32767 个 UTF-16 单元或存在非法字符时返回对象/字段诊断，使用既有有限修复额度，不截断原文。

独立审查补出两项边界：CRLF/CR须规范为LF后判断实际容量；范围行及安全别名的溢出须指向真实问题/标题字段。5个反例先失败后修正，内联与自包含的26项非Office测试通过。旧v5 Clarify预览在既有一次额度内重投影的用例也先失败后通过，保留原预览与current。复制交付的旧统计曾硬编码details=True，已改为按实际prepared引用报告，真实copy生成及Clarify回归通过。

## 原样例的专业修正

原样例四个业务Story各有15—18条AC，将详细控件配置、测试排列与共享机制混在业务验收中。七个独立目标仍成立，本次保留Story，不按条数强拆。AC分别按匹配、结果、原文、反馈、公共机制或交付成果整理为4/4/4/5/4/4/3条，共28条；11个Task的归属和估算驱动字段不变。普通Task备注清空，两个交付Story仅保留客户/平台责任例外；原迁移规模问题继续open。

86条旧AC均保留具名去向，来源摘录哈希23/23通过，原11个版本文件及2个材料文件字节未改。关键对照包含网点三句固定文案、20条分页、公共库独立建设及实际消费、1对象组14字段迁移、6步发布及客户生产责任。具体控件配置/测试排列继续作为输入与分析依据，未把它们全部复制成SOW AC，也未转塞备注。

这是基于原材料的人工专业修正和当前投影器复算样例，不是一次新的 generate/check/render/apply 链路或新提示效果评测。
