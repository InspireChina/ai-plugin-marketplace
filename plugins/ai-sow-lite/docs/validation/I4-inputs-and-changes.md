# I4 输入与复杂修改验证

本记录区分物理/保存机制、真实原型观察和从原始材料生成的专业结果。场景目录与阶段状态以 [P04](../design/implementation/P04-scope-and-performance.md) 为准；执行取舍见 [自主决策](implementation-decisions.md)。

## I4.1 原型、多用途输入和 BA 草稿

原型采用用户明确给出的目录包。登记一次保存排序清单、所有普通资源的原字节和摘要；读取器不运行代码或规划点击。上限为2048成员、16层、50 MiB。目录枚举和读取绑定已验证的目录句柄；平台缺少必要能力时明确拒绝，不降级为可能越界的读取。文本和Excel的既有来源路径保持兼容。

观察沿用现有合同，保存实际入口、前置、动作、结果、限制与必要附件。原始观察 JSON 不重写；附件采用为不可变文件，原 work 路径保留为原始记录说明。同源多个主题复用观察，新增观察需要新主题版本；完整检查核对原始分析、主题拆分、登记引用、资源和附件。交付的待确认来源说明显示具体包内路径/行号，或观察编号/附件/区域；判断结果沿依据回溯。程序能核对身份与字节，不能证明观察或专业判断为真。

### 真实观察

自包含 [原型夹具](../../tests/fixtures/prototype/package/index.html) 使用本地模拟数据及自己的临时服务。独立观察者在 Codex 内置浏览器执行静态与动态观察，首批6个目标，加一次清除/刷新观察；20次页面操作之外另有最初打开。保存17份可访问性状态和6张真实截图，退出后关闭本次页面并停止自己的服务。没有全局关闭浏览器或终止其他服务。

实见列表与详情同文案按钮属于不同路由；模拟成功只更新本地页面，不能证明后台实现。取消后的迟到响应保留了已隐藏的结果区并更新迟到提示；重叠查询间隔16毫秒，最终采用较新结果，**没有强制逆序完成**，不宣称穷尽迟到情况。静态存在但无法进入的审批分支记录未观察；详情缺少的运行行为仍按PRD义务处理，不据此删除需求。

原观察者仅将已勾选控件改为未勾选，得到一次变化计数。控制器另开独立页面作明确反例：初始已勾选/计数0，设置相同值后可访问性状态完全相同；再取消勾选，计数变1。调用成功不等于事件触发。原观察的“清除再刷新”只证明清除后的状态重置，不能证明刷新会清掉非空备注。这些限制随真实记录保留，后续生成可采用已有观察，无需为验收重演全部路径。

### 已修复接缝与 TDD

独立审查发现两项P1：一是完整检查已经接受的原型来源在导出消费处仍被拒绝，静态源码还错误显示清单名；二是目录检查后被实际替换为包外链接时可能摄入外部普通文件。均先用消费者或真实目录替换复现，再修对应接缝，没有增加专业返修阶段。

来源标签及旧失败重试首轮为4失败/1通过；标签修复后测试自身错误期待CLI抛异常，产生3失败/2通过。CLI本应将意外异常转为诊断，因此只修测试边界记录，最终5通过。该测试经过真实登记、分析、检查与投影，在Office入口主动停止；不是一次成功Office或空模型语义验收。目录边界首轮10失败，修复后新旧原型消费者46通过。

内部导出实现修订为`lite-render-v3`，投影合同仍为`lite-projection-v1`。旧失败记录可在原请求中消耗原有一次重试额度；旧成功文本记录必须完整核验才能复用。旧版本、尝试记录和额度不删除重置，模板原字节不变。

### 阶段结果

完整PRD/HLD、仅有Epic/Feature的BA草稿和实际观察共同进入独立生成会话，已形成2 Epic、3 Feature、5 Story、13 AC、5 Task和4项局部待确认。BA的两项Feature有效保留，两个独立查询API与运行部署说明从HLD主动补充；所有Task在缺少具体规模时采用M，没有重新调查规模。PRD要求的正文和详情局部状态没有因缺动态观察而被删除。Parent逐项核对实际AC、Task、问题与原材料；完整check已采用5份资源、2份观察和12份附件。

同一XLSX的历史与draft用途使用不同真实区域，机械测试证明原件只登记一次，采用分析分别记录。仅draft加tech note不足的真实退出复用[I2记录](I2-generate.md)，不再重跑相同负例。多历史修订/跨系统实例判断的更广语义组合不由本例推出。

定点复审通过，Reviewer独立21项无Office测试通过。Parent近邻156项含真实Office通过；完整Lite594通过、12跳过，包含真实复制交付消费者；旧插件388通过、4跳过，旧独立副本setup/generate通过；根测试42通过，仓库验证器及diff检查通过。逐项口径见[脱敏观察](I4.1-input-observations.json)。完整检查不是跨平台或所有专业变化的正确率。

真实render/apply已交付首版。Parent独立复核56个manifest文件/依赖摘要，其中22个为该原型清单、资源、观察、登记与附件依赖；两份观察的定位亦可从pending-items.md回查。没有新加Excel辅助列。等字节副本经Finder在Excel 16.112.3打开，无修复提示；实看Story/AC、备注后的SIT/UAT及Task分类/公式列。关闭未保存，原版与副本摘要仍相同。Excel自己的打开面板曾未启用Open，取消后换正常Finder打开成功，没有借修复功能修改文件。

另从真实已分析/形成3片草稿的快照接续独立会话，用户明确撤回PRD/HLD的本期用途，并说明暂时无法给出核心业务/技术/交付边界。会话更新受影响主题和工作索引、保留旧原件及分片，停止出稿；current和版本目录仍空。没有把旧范围继续采用、当作零工作、或用M和大量问题掩盖全案基础不足。已耗追加1批/返修1批未重置，没有新调查、问卷或Office。该停止变体补充晚期基础不足；默认M的局部未知正例由实际原型初版共同提供。

原型使用会话还暴露两个非业务接缝：一次标记误填活动名称而非UUID，正确降级后只记录真实后续边界；一次给不可读serve.py拼造text_lines位置，分析登记拒绝，删除不实定位、保留未读限制后在一批已有返修内完成。没有通过忽略来源检查放行。记录物理未读资源时应保留其目录/限制，不伪造可读行号。

I4.1范围已完成；更广历史组合、复杂改稿和性能口径仍由后续记录限定，不将本次语义样例推广为所有材料的正确率。
