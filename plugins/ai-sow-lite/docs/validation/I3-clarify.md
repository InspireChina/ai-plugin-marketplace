# I3 · 文件独立的局部修改验证

状态：I3.1 的有限编辑、确认绑定与真实修改交付已通过回归和独立审查；clarify Skill 的真实讨论和完整使用周期仍由 I3.2/I3.3 验证。阶段范围见 [P03](../design/implementation/P03-clarify.md)，自主取舍见 [决策记录](implementation-decisions.md)。

## 验收边界

- 讨论时保留当前有效 SOW；只在取得具体方案的实际执行确认后应用。
- 确认既有默认 M 可以只改变依据、决定和问题状态；真正已采用的重复答复不创建空版本。
- 对原文的误读修正只影响相关 AC/备注及必要依据，不改变 Task 的实施方式，也不要求用户重新提供已有证据。
- 每项实际变化均按稳定对象身份和字段核对；相同字段、不同新值不能复用确认。当前版本改变时拒绝旧候选，不尝试合并。
- Excel 沿用原模板计算。测试分别说明受控业务数据、机械故障、真实 Office 与新会话专业行为，不相互替代。

## 有限编辑的机械规模检查

在上述交付副本的模型上受控扩充至 307 个 Task，只提交一个 Task 的定档及对应依据、问题、决定等 7 项明确编辑。检查工具构造完整候选，并核对其余 306 个 Task 及顺序保持不变。

| 测量 | 实际字节数 |
|---|---:|
| 模型侧有限编辑 JSON | 2,957 |
| 工具返回信封 | 1,362 |
| 程序复制形成的三份业务候选文件 | 457,894 |

这是 [有限编辑测试](../../tests/test_clarify.py) 的机械扩容夹具：扩容内容由测试构造，没有宣称真实 Agent 拆出 300 项新工作，也没有为这一规模另跑 Office。字节数不是 token；完整文件复制是程序 I/O，不能称作 Agent 重生成。该检查证明局部编辑无需向模型回显完整候选，真实新会话耗时和 token 在后续使用验收中单独记录。

## I3.1 已接通的行为与 TDD

`check` 接受有限编辑稿，由程序复制基线并派生实际差异、读写集合、候选和可读方案。未知地址、矛盾编辑、隐式级联、过期基线及越界变化合批诊断；未改字段和存续数组顺序保留。问题、决定、分类依据、来源采用及 lineage 都进入实际差异，不能仅用“字段允许修改”放行不同的新值。

最初公开调用以 `OPERATION_UNSUPPORTED` 失败，再逐项补通候选构造与消费链。后续实际 Red 暴露了嵌入 AC 结构、确认字节变化、登记来源缺失、非法方案修订、摘要尾随换行、退出对象引用、未拆明义务被静默删除和归档合同等问题，均在相应范围修复后转绿。测试夹具中的错误键名、路径和初始目录问题单独归因，不记成产品缺陷。

展示方案保存为不可变文件，确认记录绑定该文件、实际答复原件与摘录，以及全部具体变化。首次有效核对会绑定确认文件的精确字节；后来换文件或改字节会失败。方案采用的输入快照允许经核对的追加登记，但旧条目及其顺序必须一致；全输入成员查询会因追加失效，明确限定输入的查询仅在所选结果未变时可继续。确认答复不会被自动加入业务事实。

新版归档包含计划、展示计划、候选、prepared 及可复核的确认记录。相同候选、模板、基线与计划内容保持有效时，确认及新的检查引用不会要求再次 Office。原件或业务依赖变化仍拒绝，不能用预览缓存跳过检查。

## 独立审查与最终回归

独立审查发现一项 P2：机器计划已绑定条件、未决事项和回查边界，但可读方案未展示这些内容。公开 `check/edits` 反例复现后，在原投影中补齐这些字段及已有对象/问题的可读名称，空集合明确显示“无”。两个新增变体由 Red 转 Green；定点复审关闭该项，结论为 Spec PASS、Quality APPROVED，剩余问题为零。

完整 Lite 套件在该可读投影修正前为 **522 通过、12 跳过，470.09 s**。修正只增加可读投影及两项测试，独立复审通过还原后的文件摘要确认其余实现精确未变；修正后执行 **215 项定向回归通过，34.59 s**，三项真实 Office 用例复用上述未改变机制的证据，不重复计算。Reviewer 另复跑三项聚焦测试，全部通过。

修正后的独立副本完成真实 Generate 交付、幂等与恢复，一次 Office，31 份 Python 审计收据、零越界，并清理自身临时目录。这仍是既有 Generate copy smoke；I3.3 才补实际历史依赖链和逐进程收据对账，不将当前数量记录称作全系统追踪。

仓库根 42 项测试和验证器通过。旧插件锁定同步、388 项 Skill 测试与151项插件测试通过，4项跳过；独立副本 setup/generate 均成功并清理自身目录。`git diff --check` 通过，原模板与旧插件源码保持不变。
