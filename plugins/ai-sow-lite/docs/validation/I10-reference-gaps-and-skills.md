## 文本归属

| 文档 | 保留职责 | 读取时机 |
|---|---|---|
| generate / clarify SKILL | 入口、阶段目标、完成条件和停止出口 | 入口加载 |
| input-analysis | 输入语义、引用依据、历史与充分性 | 生成分析；修改需补读时 |
| generate-slices | Story/AC、Task、备注/问题归属和共享返修规则 | 片内生成/合并；相应局部修改 |
| clarify-changes | 依赖边界、有限编辑、部分答复和真实确认 | 修改的实际分支 |
| generate-authoring / python-client | 精确字段、实际响应映射和机械调用 | 首次编写或对应操作 |
| tools | 程序协议、格式表示、限制和诊断 | 指定操作/诊断查询 |
| prototype-inputs | 资源包和实际观察 | 确实采用原型时 |

新规则修改既有主责段落，其他位置保留入口和链接；历史实现轮次、验证脚手架留开发记录。Skill 主文不承担完整工具手册，行数也不能衡量长段落的阅读负担。两主文与全部运行参考分别报告实际字符/字节变化，不把减少字节换算成 token 或性能收益。

引用判断复用现有模型和问题字段，不新增词法匹配、AC 评分器、规范 IR、评审阶段或循环。只提供规则名称不等于已经给出验收依据；直接给出了具体规则不强求材料自身版本；实现背景不制造缺口。未提供的局部规则直接绑定 Story/AC，真实补充只解决其对应目标。

## 实际验证

### Generate 已完成

在新的产品副本和主会话中分析固定材料，实际提出一次责任问题后才提供冻结答复。输出 1 Epic、3 Feature、5 Story、7 Task，AC 分布 4/3/3/2/2。查询、公共客户端、迁移资产及发布准备有来源；生产执行和正式验收仍属客户，公共建设与迁移核验单计。

最终保留四个 open 问题：查询条件/权限/错误提示约定、迁移映射与核验标准、迁移数量、发布规范。查询、迁移规范和发布规范的验收依据缺口绑定实际 AC，受影响 Story 行均显示待确认；迁移复杂度问题只在对应 Task 行。公共库未因“沿用标准实现”被要求补实施手册，其行上的问题来自公共错误提示约定。

首轮不是零返修：补答分析第一次缺少已引用旧依据，被 EVIDENCE_MISSING 拒绝；补入实际已有依据后继续。首次 render 因查询行多条备注超过可见高度被拒绝；消费者在原请求第二个返修批次合并重复问题、缩短当前处理，并重新安排已有范围说明，保留全部 Story/AC ID 和完整 Task 对象。随后一次 render 重试完成，没有新请求、模板变更或全案重生成。查询 AC 仍较密，有限样例不证明所有写法均已最佳。

真实 Office 产物为四表、1304 公式，缓存、结构和引用复读无机械错误。Microsoft Excel 打开无内容恢复提示；100% 检查查询和发布行，AC/备注完整，待确认状态实际可见。查看后原版 10 份归档产物保持原字节。

### Clarify 验证边界

在另一个新会话共享项目，仅提供实际《资料与公告查询台发布规范》v1.0，先展示计划、审阅后再给确认。

冻结预期原写“发布行可通过”，在 Clarify 开始前修正为“只解决发布规范问题，行状态取决于全部剩余目标”。原因是生成结果已把迁移核验依据问题明确绑定到发布的第二条 AC；补发布规范并未补迁移映射。这里遵从用户的“任一待确认影响该行，行就待确认”，不删实际目标来适配测试预期。原预期和修正记录均保留；消费者未获得该预期或额外业务答案。

实际确认前已核对展示的方案、候选及 current；确认后发布的业务 JSON 与该候选原字节一致。新版仅补发布第一条 AC 的实际规范名称、v1.0、Go/No-Go 结果及回退边界，解决发布规范问题并增加一条采用决定。Excel 可见值仅 `01-需求故事!D9` 和 `E9` 改变。

所有 Task、其他 Story/AC、发布第二条 AC 及其余三个问题完全保持；1304 个公式表达式和缓存结果均相同。`J9` 继续显示待确认，因为未答的迁移核验依据仍影响发布第二条 AC。这是准确保留剩余问题，不是把部分答复当全部通过。本次 clarify 没有产品拒绝或返修。

新版已在 Microsoft Excel 打开并确认实际版本路径，无打开恢复提示；随后定位发布行时界面连接超时，重置连接后仍无法完成新版行截图，不能宣称新版视觉复核通过。结构、完整文本、两格差异及缓存已独立复读；初版原生截图仍有效。没有强退用户 Excel 或另行重算来绕过该限制；查看后两版共 25 份归档产物字节均保持。
