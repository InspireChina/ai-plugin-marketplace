# HLD

## H-B1

前端两页和后端两个查询事务均为本期新增，打包为一个部署组件。平台方已经提供目标存储结构、只读访问层、入口鉴权和运行环境，支持上述两类查询；本期不修改这些资产。每个 API 仅对其对应数据对象查询，不另接外部系统。

## H-N1

新建一个应用级公共查询客户端程序库，独立版本管理，提供 query、cancel、normalizeError、bindRequestState 四个公开接口，供两个页面模块使用；包括示例、基础兼容说明和独立验证。沿用标准实现，不承担 UI 渲染、历史版本兼容、插件扩展、跨应用治理或额外安全/性能专项。

## H-N2

公共程序库实现统一错误转换、手动重试调用及迟到响应处理。两个页面只接入公开接口并验证本页行为；程序库构建及其独立验证只交付一份。不得在页面 Task 中重复计入公共实现。

## H-D1

原资料库被目标存储替代。资料域为单一源目标组合、一个对象组、14 个已确定字段一对一映射，质量基线明确，不要求清洗、持续同步或双写。新建迁移资产，包含装载及字段/记录核验；允许整体回滚，无零停机或独立停机时长门禁。记录条数未提供。生产数据由客户掌握，插件和本期开发人员不直接访问生产取数。

## H-D2

本期发布为同一个部署组件、一个执行团队、一个已确定窗口；现有发布规范给出六个步骤、标准回滚及 Go/No-Go 判据。需要形成对应版本的发布与切换方案，使用上述既定规范，不新设计发布策略。本期是否负责该方案、迁移资产及生产执行，待责任人确认。

## H-D3

迁移资产验证通过的字段/记录核验结果供发布方案引用。迁移独立演练、生产迁移、部署执行、正式验收测试活动及培训由客户已有团队承担，本期开发 Task 自身必要验证仍包含在相应工作中；最终责任以本次澄清为准。
