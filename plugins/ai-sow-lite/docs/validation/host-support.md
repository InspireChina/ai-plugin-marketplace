# 宿主观测验证

状态：I1.1 探针、I1.4 工具观测和 I2.3 原生 usage 接入已完成，回归及独立审查通过。首次 Generate 的完整响应观察和工具记录已核对，仍不代表逐活动 token 或物理调用均可精确获得。G12 保持开放。

## 已取得的实际证据

2026-09-09，在当前 Codex 桌面宿主启动不继承开发历史的受控 Agent，仅向它提供合成 PRD/HLD 和本轮分析指引。记录生产者为 `0.153.4`，实际模型为 `gpt-6-astra`、原生 effort 为 `xhigh`；命令行安装版本为 `0.149.0`，两者不能混用为同一接口承诺。

只按工具返回的探针会话身份定位其记录，在 1 MiB 上限内读取；仅保留计量、生命周期、模型身份及检查结论，剔除会话/响应原生身份、绝对路径、消息正文、工具参数和输出。不会把兼容读取升级为默认扫描其他会话。

原有 EX06 只识别 `token_count`。本轮同时观察到 `token_usage_record`，带 thread_id、turn_id、session_id、root_turn_id、response_id，以及本响应、turn、thread 三组计数。完整首轮的6个响应身份均不同，逐响应加总与每条记录的 turn 累计值相等；total=input+output，cached/reasoning 分别不超对应输入/输出。没有把累计值与逐响应值再相加。数值与脱敏记录见 [探针观测](I1.1-probe-observations.json)。

首轮原生 `task_started` 与 `task_complete` 成对，记录145106毫秒；该时长含宿主及工具等待，不能称纯模型执行时间。输入累计187218、输出4059、合计191277 token，其中 cached input 176640；缓存是输入明细，不能再加到合计。累计 input 不是峰值上下文，也不是计费金额。

候选阶段另有8条响应，原生轮次时长438454毫秒，输入430222、输出13870、合计444092 token，其中 cached input 388352。两轮共14条响应的逐项加总持续与原生 turn 计数一致；没有重复响应或冲突数值。两轮之间等待合同实现的间隔不算模型工作或已知用户等待，分别报告，不拼成连续处理时长。

两轮共12次实际工具调用，模型提交参数的 UTF-8 字节数合计46269，工具返回合计107820；这不是 token 数，未按字节估算 token。输入原件仅3777字节，Schema 文件71475字节，最终 model/pending/candidate/decisions 四文件合计40241字节。早期输入与结构准备的成本已经可见；仅凭这些总量不能把耗时全部归到某一种原因。后续先比较紧凑合同读取及机械依据登记，保持同样义务和来源覆盖，不以减掉内容宣称提速。

## 当前结论与局限

- 当前合成轮次的完整响应序列及算术关系有实测；新响应身份为后续去重提供线索。重试、更正、计数重置、多来源和跨宿主升级语义尚未实证，不能直接宣称物理调用账本完整。
- 活动 start/end 是实际写入标记。一条模型响应可能跨越标记与多个专业动作，仅凭响应结束时间不足以精确拆出每步 token；活动归属仍未验证。
- 这是包含宿主背景、输入阅读、分析和写文件的早期实验；没有完整 Lite generate、Excel 导出或局部 clarify，没有与旧版同口径对照，不能据此宣布性能达标或改善。
- 同一请求跨两个实际处理轮次已观察；取消、迟到、用户等待及实际 Skill 生命周期在 I2.3 继续，运行时事件聚合的 I1.4 证据见 [I1 验证](I1-reliable-delivery.md)，合成源声明不提升当前宿主能力。

[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 定义 turn 开始/完成与 usage 通知；它不为本地 transcript 格式提供稳定承诺。本次只是生产者版本绑定的实际观察，没有另起 App Server、修改宿主配置或启用 OTel。
