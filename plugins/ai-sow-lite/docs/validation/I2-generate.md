## Three-scope 前置演练

以 EX01 的原始 PRD/HLD 文本制作独立临时项目；被测 Agent 不继承开发聊天，不获得设计案例、预制候选或 expectations。当前仅给专业边界指引，真实 Skill 与全部机械通道尚未实现。使用新项目、无历史 SOW、无原型的输入。

输入分析正确识别两页及查询 API、独立公共客户端及消费方边界、资料迁移内含核验、发布方案与外部执行责任。保留只读查询、不得自动重试副作用操作、迟到响应、排除平台重建等限制，没有追问记录条数来定档。

实际合批提出两项输入问题：本期交付责任，以及禁止直接访问生产前提下开发验证数据和核验结果的提供责任。第一项按 EX01 的 A1 答复；第二项是本次演练实际发现的有效输入缺口，评估者显式补充“客户提供脱敏样本和非生产环境，本期开发团队自测并提供核验结果，生产执行仍由客户负责”。它不是从原 HLD 推断出的既定事实。

续接原 Agent 后，自主生成2个 Epic、3个 Feature、5个 Story、7个 Task、3项依赖；条数只记录实际结果，不作为固定拆解要求。业务查询、公共技术能力及迁移/发布交付均有对应工作；公共程序库只建设一次，两页面各自接入；迁移核验内含，未增造平台、PoC、正式验收或生产执行。迁移为 M，1项复杂度问题保持 open；两项输入问题按实际答复 resolved。

可见 AC/备注保留查询行为、手动重试、迟到响应、只读范围、外部提供资产、迁移回滚和发布责任。副作用自动重试禁令完整保存在来源依据中，可见备注写为“不新增自动重试要求”；I2 应进一步核对关键否定约束在输出中的直接表达，不能仅依赖依据文件可回查。缺少资料查询到迁移的显式依赖边，但迁移 AC 保留历史资料可查义务；I2 的关系覆盖演练仍需核对这种修改导航缺口。

首次机械核对发现两项程序处理问题：macOS 项目根别名与已解析路径不一致被误判越界；单文件 source locator 显式指定已登记路径被一概拒绝。按错误归因修复校验器并补测试，不要求 Agent 重写业务。修复后复核 exit=0、diagnostics=[]、valid_for_render=true、unknowns_count=1；原候选、业务、原件和模板字节完全未改，没有 current 或 Excel。实际程序进程约107.13毫秒，非性能统计基准。该结果不代表完整 generate 或全部语义验收已通过。
