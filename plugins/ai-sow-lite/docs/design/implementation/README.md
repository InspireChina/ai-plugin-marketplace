P00 不作为额外开发增量：P01 按消费者实现它的交付合同，P02 增加输入分析，P03 增加变更方案，P04 扩展已承诺的组合。不要先把所有 Schema、兼容层和报告器写完再跑第一个例子。

任务依赖为：

```text
I1.1 合同/真实夹具 → I1.2 输入/版本保存
                         → I1.3 Excel 投影 → I1.5 独立交付验收
I1.1 → I1.4 工具计时/事件 ──────────────────┘
I1.5 → I2.1 文本/XLSX → I2.2 generate → I2.3 宿主与真实基线
I2.3 → I3.1 精确变更 → I3.2 clarify → I3.3 串行新会话/恢复
I3.3 → I4.1 原型/draft、I4.2 复杂修改 → I4.3 支持/性能/交付准备
```

这是开发依赖，不是插件运行时的 Action 图。当前设计采用单主 session；实施任务也没有默认创建子 agent、新任务或 worktree 的要求。

首个正式里程碑仍是 I1 的小型合成候选填写原模板并输出真实 Excel 和同版待确认说明。I1.1 中前置最小真实候选和宿主 usage 探针，只在 work 观察专业输出负担与实际计量能力；完整可靠性交付条件不变。I1 达标进入 I2 的真实材料生成，复用探针结果并补实际通道证据。P00 只随当前消费者实现，不先完成完整保存/投影/监控后才测专业效果和 token 可得性。

## 2. 每项任务怎样关闭

每项先写能观察失败的最小测试或演练输入，完成对应实现，再按文中的命令验证。机械测试检查文件、值、引用和生效事实；语义演练检查输入义务及依据，不要求 agent 复刻样例措辞、片数或 Task 数。关键公式必须真实 Office 重算，布局改动必须原生打开。

验证记录放在实施时新建的 `docs/validation/`，使用合成或脱敏数据，记录代码/模板/夹具身份、平台、命令、结果和限制。每个增量一次简短汇总即可，失败修复记录归同一项，不新建一套审批文档。实际客户输入、聊天和完整工具输出只留项目本地。

任务完成后更新 D09 的证据状态及相应支持声明，不删除失败场景或降低语义覆盖来通过验收。没有跨平台环境时标未验证；没有逐活动 usage 时记录真实可得粒度，保留验证目标。基础 Excel/保存失败不能标作可接受的业务未知。

设计已提交为311fee2，现按用户要求开始实施。实施遵守用户授权范围：未经要求不提交 Git、不发布、不安装到用户宿主；独立临时目录的测试副本属于验证工件。

## 3. 本计划主动不增加的结构

不增加 Python 领域阶段运行器、`next/submit`、全量 IR、独立实施对象、逐 AC—Task 映射、数据库服务、每片审批或 token 预算门禁。文件协议控制有效结果与有限修改；Skill 保持专业自由和 D04B 的退出约束。

首版选用的解析与估算能力保持 D00：Python 3.12、uv 0.11.7、jsonschema 4.26.0、openpyxl 3.1.5、pytest 8.4.1，以及已经验证的 Office 方法。没有重新选择 PDF/OCR 解析栈或模型执行框架。
