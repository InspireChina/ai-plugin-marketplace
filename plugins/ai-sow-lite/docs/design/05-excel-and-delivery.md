## 1. 可独立手工填写的基础模板

模板位于 [assets/sow-template.xlsx](../../assets/sow-template.xlsx)，以用户选定的文件为基础，整理为无需插件即可手工填写、估算的工作簿。只保留可见业务字段、计算结果、估算标准和参数；没有隐藏行、隐藏列、折叠列或隐藏工作表。原有标准人天、系数、工作方式和复杂度规则保持原值。

当前模板 SHA-256：`7b96f9d2d6f6f6175c4d99d875ee3cf0743df3d6884d64258271993432299919`。唯一兼容旧模板为 `6abc55d44bc66476a60c2251e18c0dfdb66709e07539c246dfdec3a0373f5332`；仅在内存从新版资产复制校验列 prototype/A2 说明，保留旧项目模板原字节及 hash，prepared/projection 绑定实际项目 hash。其他模板拒绝，不自动重建项目。

| 工作表 | 已核对内容 |
|---|---|
| `01-需求故事` | `SOWStoryTable`：需求、子需求、故事、验收条件、备注、SIT适用、UAT适用，以及任务列表、故事人天和校验结果 |
| `02-任务清单` | `TaskTable`（A:L）：所属故事、任务名称、工作类型名称、工作方式、复杂度、集成类型、备注，以及计算和校验列 |
| `03-工作量汇总` | `ProjectSummaryTable`：直接开发、SIT 支持、UAT 支持与总开发人天；`ProjectParameterTable`（A12:C20）直接保存 8 项可见参数 |
| `90-估算标准` | `TaskStandardTable`（A:R）：88 个工作类型、三种工作方式标准人天、交付边界、复杂度细则及 SIT/UAT适用，全部可见 |

估算标准的第 3 行统一为同一分组表头样式，Q3:R3 合并为“适用范围”，与复杂度分组一致。S/M/L、X / 拆分条件、主要计量维度和模式适用说明均留在 `90-估算标准`，以可见列展示；冻结前三列及前四行，横向阅读时保留类型身份和表头。

手工使用时，先填写故事，再在任务表选择所属故事、工作类型名称、工作方式、复杂度及适用的集成类型。白色业务输入列可编辑；灰色计算列保留公式和保护。当前预留 60 行故事、200 行任务，超出范围的扩行与保护仍需单独验证。标准和参数直接保存在其可见位置，公式和下拉直接引用它们。

已移除隐藏原始目录、重复展示数据、隐藏参数镜像、内部元数据、任务工作类型 ID 派生列和 UAT 辅助列。标准目录保留可见的工作类型 ID，便于人工识别条目。agent 使用的内部关联、来源定位、版本信息和写入适配单独设计；本模板不预埋隐藏 agent 字段，也不将这些字段作为手填的前提。

本稿从模板读取这些事实，不另存一份可独立修改的标准目录或参数表。模板中保留的“待校准”状态不被复制操作改成已校准；运行 agent 不因此改数或新增校准审批。

## 2. agent 只做四项定性匹配

| 字段 | 匹配依据与填写规则 |
|---|---|
| 工作类型名称 | 按可见标准中的交付对象、模式化完成标准、说明及模式适用说明匹配目录名称 |
| 工作方式 | 实例适用及本期变化明确时按模板判断；无相关候选默认“新建”；只有类型/业务相关候选但实例未定时按“新建”并附复用待确认；不以项目类型统一赋值 |
| 复杂度 | 现有材料可判断时匹配 S/M/L；无法判断默认 M 并附待确认，不追加定档补证；触及 X/拆分条件时，按有依据的工作边界拆分或提出缺口，不直接填一个 X 档人天 |
| 集成类型 | 仅集成类 Task 依据边界选择“内部集成”或“外部集成”；非集成 Task 留空；集成属性未知也留空但必须关联待确认项 |

标准中的规模维度是判断依据。agent 可以识别输入里明确的规模与行为，但不能反向编造数量或前提去匹配档位。分类输出是定性的；M 档标准人天、复杂度系数、任务人天、SIT/UAT 支持及取整汇总均由模板处理。

工作方式对照 as-is/to-be：无相关候选默认“新建”；存在具体复用候选但实例/适用性未定，也先按新建并保留待确认，不无限调查候选。只有实例适用及变化边界有依据才按标准选调整/接入复用或扣除已满足工作。未读、读取失败或本期基础不足不能靠默认口径消除。复杂度无法识别独立采用默认 M 并附问题；类型或集成属性缺依据仍留空，也不自行估人天、调系数或猜测方案。找不到合适目录项时先在片内检查工作边界；仍不适配则留空并记录标准匹配问题。已有依据但尚未拆成可计量 Task 的局部工作以 D02 `unestimated_work` 标记，在工作簿待确认表中说明保留的业务范围。该标记不进入公式、金额状态或交付金额门禁。

## 3. 最小业务字段如何落入模板

| 业务内容 | 模板位置 | 谁提供 |
|---|---|---|
| Epic / Feature | `01-需求故事` 的“需求 / 子需求” | agent 从输入组织 |
| Story 标题 | “故事” | agent 从输入整理 |
| Story AC | “验收条件” | 从输入提取；按模板每条一行，不新造义务 |
| Story 备注 | “备注” | 对象特有的有依据说明、边界和工作簿内待确认入口 |
| Task 所属关系 | `02-任务清单` 的“所属故事” | 手填时选择已有故事；未来工具从内部关系映射 |
| Task 六项专业内容 | 任务名称、工作类型名称、工作方式、复杂度、集成类型、备注 | agent 形成名称、做匹配并填写有依据内容 |
| Story SIT/UAT适用 | 模板只读公式列 | 根据关联 Task 的工作类型标准自动计算，不属于 Story 专业输入 |
| 任务列表、各级人天、系数及校验 | 模板现有计算列 | Excel 自动计算；未来工具须保留公式 |

模板用故事名称关联任务，且校验故事名称与任务名称的唯一性。内部稳定 ID 仍用于修订；工具不能依靠同名模糊关联把工作算入错误 Story。同名、长名或含特殊匹配字符的名称采用 D06 的机械安全别名，原名完整保留在既有备注。别名只区分身份，不增加业务含义，也不通过改写 COUNTIF/SUMIF 修复原模板。

业务、技术和交付需求均使用上述 Epic/Feature/Story/Task 列表达，不另增三套工作表或要求用户填写需求类型。独立公共能力的建设 Task 归属其技术 Story，业务接入 Task 归属相应业务 Story，迁移与上线等工作归属相应交付 Story；依赖保留内部可定位关系，不自动追加备注。需求归类不决定工作方式或 UAT，仍逐 Task 依据实际变化和模板标准处理。

## 4. 留空是显式业务状态

| 情况 | 字段与用户视图 |
|---|---|
| 已有充分依据 | 正常填入并按模板计算 |
| 有相关复用候选，但实例/适用性未定 | 工作方式填新建，目标 Task 备注以“待确认：”写问题与当前处理；不将候选当已采用，也不另建一份复用 Task |
| 复杂度无法识别 | 默认 M 并附待确认；不因档位未确认反复找证据 |
| 后期类型、必要集成属性或 AC 没有依据 | 该字段留空，实际目标行备注写具体问题及当前处理；说明需要什么事实或决定 |
| 非集成 Task 的集成类型 | 按模板留空；内部记录不适用，不误报信息缺失 |
| 合法局部未知可能影响模板结果 | 保留空字段并定位问题；Office 原样计算，插件不解释或改写其金额结果 |
| 基本范围或验收意图大面积缺失 | 不拆解、不把空表当 SOW；返回资料要求和已完成分析 |
| 投影造成结构损坏、引用错误或公式丢失 | 作为插件故障处理，不伪装成待确认项 |

待确认项不只对应空白。复用问题即使 `work_mode` 已填新建仍保持 open；备注以“待确认：”写候选适用问题及当前新建处理。金额结果不会自动关闭问题，问题状态也不驱动计算。

AC 原列全文、问题目标、未拆明父项范围行、必要备注、历史状态及物理限额统一按 D06。正常 notes 为空，依赖/分类依据/Task 列表/证据 ID/外部路径不自动进入备注。新输出不生成 `details.md`，`details=[]`；同版 `pending-items.md` 保留历史与锚点。

“必填项缺失”等模板提示不能统一当作要求 agent 反复补值的门禁。若它对应已识别的局部业务缺口，输出应清楚表达待确认；若实际是漏写已知内容，则修复投影。不能为了通过校验猜值，也不能把非法分类当合法空缺。

## 5. SIT/UAT 由模板按任务类型自动判定

本节只记录既有 SIT/UAT 行为；投影器保留原公式，不另设三态规则，也不让问题状态或 `unestimated_work` 改写结果。

`90-估算标准` 的每个工作类型都有“UAT适用”标准值。按该类型实际交付的内容判定，与项目类型、工作方式、复杂度和插件阶段无关。当前 88 个类型中 41 个为“是”、47 个为“否”。

| 标准归类 | 任务类型示例 |
|---|---|
| 适用：直接交付系统功能及其应用公共能力 | API、页面、业务流程、业务集成、应用公共组件、权限与审计、数据处理、智能业务能力 |
| 不适用：分析、试验、验证、工程支撑或交付执行 | 各种设计与 ADR、PoC、Spike、测试、工程平台、环境与部署、发布、运维、培训和文档 |

例如 API 实现适用，API 自动化测试不适用；应用级公共组件适用，共享工程平台不适用；可重复使用的数据导入功能适用，一次性历史数据迁移不适用；实际存储结构实现适用，只有数据契约定义的工作不适用。各行的具体标准以模板为准，插件不复制第二份类型判定表。

| Story 关联任务情况 | 公式结果 |
|---|---|
| 任意一个 Task 类型适用，即使另有类型未明的 Task | 是 |
| 有 Task，且所有 Task 类型均已确定为不适用 | 否 |
| 尚无 Task | 空白 |
| 没有适用 Task，且至少一个 Task 类型缺失或无效 | 空白 |
| 无 Story 的行 | SIT/UAT 空白；真正空行的校验为空，问题范围行校验为待确认 |

SIT 标准保存在 Q 列（`TaskStandardTable[SIT适用]`），UAT 在 R 列（`TaskStandardTable[UAT适用]`）；SIT 按分类“系统集成”标记，当前为 IN-INTEGRATION、IN-IDENTITY 两类是，其余 86 类否。Story 的 F/G 列分别为 SIT/UAT，位于 E 列备注之后，只要任意关联 Task 适用即为是；全已知不适用才为否，没有任务或不能判定则空白。两列直接将关联 Task 的工作类型名称与可见标准匹配、汇总，无需隐藏 Task 辅助列。两列均锁定，移除是/否下拉，禁止手动修改或由生成器覆盖。Table 保留首行计算公式元数据，未来扩展行时必须延续公式和保护。

工作类型未明时，待确认项针对缺失的分类依据；不会另问用户“SIT/UAT 是否适用”。SIT 标志不改变原支持人天口径，仍按 Task 内/外部集成与复杂度计算，不能把整 Story 开发人天作为 SIT 基数。Clarify 补入或更正 Task 类型、归属后，由公式重新计算相关 Story。UAT 支持人天仍使用模板现有 Story 汇总口径，本次没有改成仅按适用 Task 人天计取。

## 6. 复用既有 Excel 能力与 Lite 适配边界

Excel 的读写、公式保留、扩行、Office 重算与复读优先参考 ai-sow 已跑通的实现和测试；技术依据见 [D00](detailed/D00-technology-stack.md)。迁入 Lite 时验证原四张表、名称别名、输入与公式保存、原列全文/目标行备注/校验优先级及超容量扩行，并确认独立插件副本可运行；既有测试适用的部分作为后续实现依据。

**金额边界。** 原模板如何处理空白、零、支持人天、取整和汇总，都保持其现有公式语义。插件不新增缺值保护、估算完整性判定、完整/部分/不可算标签、金额差额算法，也不修复或替换原模板公式。`03-工作量汇总` 的结构、说明和参数保持原样，不新增 C 部分金额列或其他汇总。Office 缓存原样保存；文件检查只证明输入、引用、公式和交付文件保存正确，不证明估算范围或金额完整。

**备注中的假设。** 模板说明文字允许备注展示“假设”；Lite 仍遵守用户规则，不自行生成前提或方案。输入本来存在的尚未确定内容须保留其性质，并作为待确认项处理，不能转成已确认事实。

## 7. 检查、交付与使用

生成器保留模板结构、公式、数据验证、样式、保护和汇总关系，容量内保留预留区域，超容量时扩展必要数据行。普通文本安全写入，不把以 `=`、`+`、`-` 或 `@` 开头的内容当作公式。长文本在原列保留全文，单格 32767 UTF-16 超限返回字段诊断，行高最多 409 点，不覆盖公式列或改变业务语义。

检查对象关系、分类合法性、来源 AC、已知内容是否遗漏、留空是否有原因、跨片重复计量及文件可读性。Office 在独立目录按原公式计算并保存；复读验证输入、引用、公式、结构和缓存保存，不另设金额判定。详细边界见 [D06](detailed/D06-excel-projection-and-delivery.md)。

手工模板回归位于 [test_template_uat.py](../../tests/test_template_uat.py)，独立于插件流程。检查标准覆盖、可见布局、输入与公式保护、Table 计算列元数据，以及标准和参数不依赖隐藏数据。使用 LibreOffice 实算混合任务、未知类型、任务重分类、归属变更、特殊字符名称、末行数据、三档复杂度、内外部 SIT 支持、汇总和不适用工作方式；没有该引擎时实算测试明确跳过。

Table 计算列元数据沿用模板的 A1 引用写法，与对应首行单元格公式一致。曾在这里写入 `[@…]` 简写，单元格计算与 LibreOffice 测试通过，但 Microsoft Excel 打开时要求修复；因此公式实算不能替代原生文件打开验证。精简后的模板结构已通过 Microsoft Excel 正常打开、保存后重开、手工输入、适用/不适用/未知三种结果实算、SIT/UAT 与总人天汇总，以及尝试覆盖只读 UAT 单元格的保护验证。未来生成器扩行的端到端验证仍待实现。

模型、`pending-items.md`、主要说明和 Excel 保存为同版结果。生成时完成必要文件检查，成功返回后无需定稿或再次导出。单人串行 generate/clarify 在生效前仍核对预期版本；不匹配返回 `BASE_STALE`，不自动迁移候选或复用跨基线确认。失败候选不覆盖上次有效版本，中断后按 D07 幂等恢复。Clarify 补入已确认事实后重新投影，Office 按原模板计算，未答项继续保留。

Excel 独立查看不等于无损回导；后续 clarify 仍需项目 JSON、依据和版本目录。现阶段不以任意手改 Excel 的无损回导为产品目标。若用户已有 draft，可作为辅助输入读取并与必需材料对照，详见 [10](10-draft-inputs.md)。
