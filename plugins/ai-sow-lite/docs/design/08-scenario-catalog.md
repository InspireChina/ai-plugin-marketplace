# 08 · 异常场景与验收目录

[返回总览](README.md)

本目录是设计期预期行为，不表示测试已经实现或通过。场景按两个入口、输入分析、文件交付与观测组织；先识别最早发现位置，再决定适合的验证层级。验收须观察实际内容与行为，不能只验证出现某个提示词。

每个案例记录：触发条件、最早可识别位置、用户是否参与、保留成果、允许改动范围、回查与续接位置、退出条件，以及时间/token 观测是否完整。用户问答边界以 [01](01-workflow-and-user-input.md) 为准，clarify 修改边界以 [04](04-bounded-change-and-recovery.md) 为准。

本轮按 Q1/Q2 调整原 ID 的验收范围，保留 163 项映射。正常使用为单人串行 generate/clarify；异常基线变化只验证 `BASE_STALE` 保护退出，不验证并行改稿成功或跨基线自动复用确认。AN27/AN28、FS13、OB11 仍是未来片内 worker 优化的条件实验。

金额及 SIT/UAT 结果全部交给既有模板和 Office。输出只复制原模板、填写白色输入，超容量按原公式原型扩行并保留语义；四张表不新增列、Sheet、汇总、参数或公式体系，模板资产哈希保持原值。待确认事项独立生成同版 `pending-items.md`，在既有备注引用；超长原文完整保存在按需 `details.md`，在可写单元格注明，不覆盖公式列。场景检查输入、文件、引用和公式保存，不以金额或其缓存判定业务完整、部分或不可算。

## 1. Generate 接收与问答

| ID | 场景 / 最早识别点 | 期望处理与验收结果 |
|---|---|---|
| IN01 | 项目类型或材料已在用户请求中给出 / 开场 | 开场完成确定新旧项目、收集必要输入；已有类型和材料直接复用，仅补缺项，不附加固定用途、范围或决策人问卷 |
| IN02 | 只有一句想法、空文件或纯模板 / 接收 | 快速指出缺失的业务材料与用途，不大量探索后伪造完整 SOW |
| IN03 | 没有原型，但 PRD/HLD 等必需材料齐备 / 接收 | 原型可选，不因此阻断；新老项目对应的必需材料不能豁免，之后仍分析内容充分性 |
| IN04 | 用户提供很多材料，其中部分不可读 / 分析 | 登记全部输入，记录相关性和读取缺口，不把读取失败当成无相关内容 |
| IN05 | PRD、HLD 与原型范围冲突 / 综合分析 | 自行调查后集中提出需要用户裁定的关键差异 |
| IN06 | 用户回答改变已完成分析 / 分析后问答 | 更新适用事实和关联结论，不只把答案附在聊天里，也不全量重分析 |
| IN07 | 问题包只回答一部分 / 分析后问答 | 保留已答项，继续澄清仍阻止推进的关键缺口；基础未补足不进入生成，不填默认值 |
| IN08 | 答案说明基础资料实际上严重不足 / 分析后问答 | 具体说明需补充内容，本次退出，不强行拆解出稿 |
| IN09 | 关键事实未补足，用户暂不回答 / 分析后问答 | 保留分析并说明仍需内容，不用条件假设或局部结果越过基础缺口，无沉默批准 |
| IN10 | 后期发现只能由用户决定的局部事实 / 分片生成 | 对应字段留空，关联同版 pending-items.md 并在既有备注引用；不猜前提、方案或分类，不新开逐步骤问答 |
| IN11 | 后期发现全案基础信息大面积不足 / 形成结果 | 停止推进，返回缺口和已完成草案；不能靠大量空白或待确认标签制造成功初版 |
| IN12 | 用户拿到初版后直接离开 / 返回 | 已有可用 Excel 和必要说明，请求结束，没有待定稿或后台必要检查 |
| IN13 | 老项目未提供往期 SOW / 接收 | 明确要求补充，不因已有 draft 或原型就豁免；新项目不强制要求往期 SOW |
| IN14 | 第一轮回答后仍缺少几个关键事实 / 分析后问答 | 还有一次补问且预期可获实质答案时合并补问，只复核相关分析；最多两轮主动提问，到限仍缺基础则补料退出，不能带缺口向下推进 |
| IN15 | BA 只提供 Epic/Feature 与少量 tech note / 接收分析 | 识别有价值的骨架，但仍要求 PRD、高阶设计和老项目往期 SOW；不从标题编造 AC |
| IN16 | 新项目主动提供适用往期 SOW，或老项目有全新能力 / 工作方式判断 | 项目类型决定必需材料；相关历史构建 as-is，每个 Task 单独匹配；无历史的新项目允许空 as-is，旧项目缺历史不能冒充空基线 |
| IN17 | 同一 Excel 包含历史工作和用户整理的本期 draft / 登记与分析 | 区分物理格式、材料类型及已明确用途，复用有效读取并分别分析；历史内容不自动进入本期，也不替代内置模板和标准 |
| IN18 | 分析后问题包要求用户批准拆解、选择 Task 分类或确认出稿 / 提问前 | 仅保留与输入有关的业务、技术、交付事实、歧义、冲突和决定；例如确认迁移责任；仅缺定档条数直接按 M 并带出问题。无输入问题直接推进，不审批分析摘要或专业结果；clarify 的具体修改方案确认独立保留 |
| IN19 | PRD/HLD 在同一文件中，或历史/draft 混合在一个工作簿 / 登记与充分性 | 按角色及实际区域登记一个物理版本，不按文件数索取重复件；角色标签不能替代缺失内容，历史/draft/规则用途不得混用 |
| IN20 | 非原型只给 PDF/DOCX、扫描件或其他不支持格式 / 接收 | 要求相关可读文本（默认 Markdown）或 XLSX，不安装解析器、OCR 或自动转换；必需材料未可读先补料，其他充分材料已覆盖的可选附件说明未分析限制，不冒称读过 |
| IN21 | 输入主动问答已两轮，仍有问题 / 分析后问答 | 不再第三轮主动提问；基础不足列补料清单退出，只有局部缺值/复用候选则随 SOW 交付；回复存在不自动延长轮数 |

## 2. 专业分析与拆解

| ID | 场景 / 最早识别点 | 期望处理与验收结果 |
|---|---|---|
| AN01 | 原型使用假数据、模拟成功 / 原型探索 | 区分观察、源码及真实系统事实，不据此认定后端可复用 |
| AN02 | 出现未预登记的菜单、动态状态或交互 / 探索 | agent 在目标和授权范围内自主继续，不因缺 Action 枚举停摆 |
| AN03 | 原型无法运行或部分 JS/CSS/关联资源加载失败，但源码可读 / 分析 | 按资源包使用可得证据，明确未验证页面和交互，不伪造浏览观察，也不因未观察到就断言不存在 |
| AN04 | 往期 SOW 中跨表、转置或附注被提取遗漏 / 输入读取 | 保留原件定位与未处理区域，对相关内容补读或标明缺口 |
| AN05 | 往期 SOW 与明确取消/未交付说明冲突 / as-is 分析 | 往期 SOW 直接构建估算 as-is；只处理具体反证和适用范围，必要时澄清；不增加逐条历史交付核验 |
| AN06 | Task 类型不适配、复杂度信息不足或超过标准 / Task 判定 | 类型不适配或已知 X 按有限范围处理；无法识别复杂度默认 M 并附问题，不追加补证、不自造标准人天 |
| AN07 | 多个 Story 共用测试、迁移或集成工作 / 拆解 | 公共义务有覆盖和单一计量归属，不漏项、不重复收费 |
| AN08 | Story/AC/Task 需要联合拆合 / 形成交付 | 联合调整必要对象，保留义务和新旧身份关系，不逐层反复退回 |
| AN09 | 语义相同但词面不同、核对者有表达偏好 / 必要检查 | 按实际含义判断，不为凑关键词反复修审；真实业务未知不伪装错误 |
| AN10 | 材料超上下文或摘要漏掉反例 / 分析与交接 | 使用主题索引、关键前提和原文定位；必要补读，不能以省 token 为由抹掉冲突 |
| AN11 | 大 Feature 需要拆片，或强关联内容跨 Feature / 切片选择 | 按实际关联和规模组织，不强制一个 Feature 一片、一次调用或一个 worker；业务归属仍清楚 |
| AN12 | 各片都通过局部检查，但漏掉骨架中的一个目标 / 合并 | 对照全局范围检查覆盖，定位缺失片或明确未交付范围；片数完成不代表范围完整 |
| AN13 | 后一片发现公共义务需要补正骨架 / 片内分析 | 界定关联骨架元素和片集合，仅复核受影响内容；无关已完成片保持有效，不重写全项目 |
| AN14 | 来源没有某条 AC，agent 按经验补了异常规则或阈值 / 片内检查 | 去掉无依据内容，字段按来源填写或留空并关联问题；不能让模板完成标准代替项目 AC |
| AN15 | 模板标准含规模门槛，输入没有规模事实 / 定性匹配 | 不编数量去匹配档位；复杂度默认 M 并附问题，不为定档回头找规模；规模若改变范围/方案基础则在分析后澄清 |
| AN16 | 同一页面/API 工作支持多条 AC，一条 AC 又涉及多项工作 / 片内拆解 | Story/AC/Task 联合形成，按模板交付边界拆分；不按 AC 数量建 Task，不把已包含的异常表现再次计量 |
| AN17 | HLD 明确要求专题设计或 PoC，但没有对应业务 AC / 片内拆解 | 按本期依据和模板边界判断工作是否单列，保留来源；不因缺少直接 AC 关联删除有效工作或编造 AC |
| AN18 | 两项工作针对同一 API，或同一工作在不同材料中名称不同 / 拆解与合并 | 对照变化内容、包含边界和计量归属判断，不能只按对象名称合并或排除重复；不要求先建实施对象清单 |
| AN19 | 轻量提取未包含本片需要的规则，原件仍可定位 / 分片或 clarify 定位 | 补读相关章节并更新关联结论，保留反例与缺口；不要求全量重建 IR，资料是否足够仍按业务判断 |
| AN20 | 输入内容、解析方式或使用用途变化，已有读取和分析可部分复用 / 接收或补读 | 分别核对物理解析与用途分析的适用性，只更新受影响部分；不因文件名相同复用过期结论，不把新用途标为已分析 |
| AN21 | PRD/HLD 有 NFR 或公共能力要求，但没有现成技术 Epic/Feature/Story / 全输入分析与骨架 | 主动识别有依据的技术交付并组织层级，记录来源及为何构成本期工作；不因没有标题遗漏，不自行选择未知架构 |
| AN22 | HLD 明确独立公共能力被两个业务功能使用 / 骨架与分片 | 技术 Story 承担公共建设、只计一次；业务 Story 保留各自功能及必要接入，记录依赖；接入 Task 不重复包含公共建设，工作方式逐项判断 |
| AN23 | NFR 仅约束某业务功能，或历史 as-is 已满足 / 范围分析 | 保留本期有依据的局部变化、验证或接入，不默认新增公共服务；已有且无需工作不制造 Task，不因技术 Epic 为空就判漏技术范围 |
| AN24 | 历史数据保留目标与存储替换方案隐含迁移/核对，或材料明确迁移、上线准备 / 全输入分析与骨架 | 不依赖现成标题，主动形成有依据的交付层级；本期工作与外部责任分开，未知方案和责任按澄清/留空规则处理，不默认包办 |
| AN25 | 技术或交付 Story 可识别，但性能指标、迁移核对标准或上线条件不明确 / 分析或片内检查 | AC 使用 HLD/交付材料或用户答复中的依据；缺项澄清或留空，基础不足先补材料，不套通用阈值，也不强写终端用户故事 |
| AN26 | 原型显示权限或审计交互，但 HLD 缺少目标方案依据 / 全输入分析 | 记录技术需求线索，结合 PRD/HLD 的 to-be 与往期 SOW 的 as-is 对照；不从界面编造后端方案，零匹配默认新建也不能补足缺失方案，关键输入事项在分析后澄清 |
| AN27 | 切片写回文件后仍在同一长会话，或新子 agent 完整继承父历史 / 工作包准备 | 不把减少新注入等同清空历史；核对宿主压缩/精简启动，按相关目标传递依据与限制，不回灌全部探索输出 |
| AN28 | 不同片读取同一 HLD，或公共建设与消费方需要联合拆 SOW / 分片安排 | 首版由同一专业 session 串行处理；未来片内 worker 实验按语义前提和写集合判断独立性，已明确公共边界才可评估并发；跨片正式 ID 待提供方返回再绑定，不涉及并行改稿 |
| AN29 | 无 subagent 完成多片后发生压缩，历史同时含旧候选、新答复和修正 / 下一片或全局整合 | 当前文件明确有效版本、采用事实、覆盖与公共归属；只补读必要依据，不能把旧历史当当前事实，也不能只看各片成功或标题而漏全局义务 |
| AN30 | XLSX 隐藏附注、公式缓存或嵌入对象包含重要范围，而默认读取未覆盖 / 输入读取 | 结构目录暴露未读面，定向补相关区域；摘录绑定原件及读取身份，不能以缓存/截断内容假装完整事实，也不因无关对象不可读全案重跑 |
| AN31 | 原型持续出现重复状态、缺失前置或模拟响应，已有观察可能过期 / 探索与复用 | 按重要疑点和新增证据价值继续或停止，明确未验证面；区分源码与实际观察、静态包版本与运行条件，不穷举或反复修原型制造成功 |
| AN32 | 相关历史范围已分析，目标能力没有语义匹配 / gap 与模式判断 | 只为本期负责的工作默认“新建”，使用模板原词；保留零匹配范围/依据，不问是否新建；复杂度独立遵循默认 M 政策，类型/集成属性与方案不因此默认 |
| AN33 | 搜索无结果但历史未读/损坏，或本期基础存在关键歧义 / 匹配 | 零结果不等于零匹配；在剩余轮次内批量补读/澄清，不能按新建掩盖读取失败或本期基础不足。历史已读但候选实例未定另按新建+待确认 |
| AN34 | 新页面调用旧公共组件，或本期新建公共能力被另一片消费 / 片内拆解 | 按实际资产/工作单元判断模式，新页面不因公共能力存在就全选复用；本期候选不成为历史 as-is，公共工作不重复计量 |
| AN35 | 目标已被 as-is 满足，或新材料未再提旧能力 / gap 综合 | 无本期工作则不建收费 Task；不把全部 to-be 重拆，也不因未提及就自行下线；全无 gap 时如实说明，不制造范围或虚假估算 |
| AN36 | 往期和本期都叫发布方案/迁移，但属于不同版本或源目标 / 工作边界匹配 | 对照具体交付事件和资产，历史同名不等于本期已完成；按目标和标准判断本次工作，禁止机械排除或重复全量重建 |
| AN37 | 多份往期 SOW 增补、修订、同名跨系统或范围冲突 / as-is 综合 | 按明确适用范围/修订关系综合；不以最新文件取代全部历史，不仅用名称匹配；真实关键冲突按输入问答处理 |
| AN38 | 历史只有层级和简述，无 AC 或 Task 类型 / as-is 建模 | 保留可识别条目、层级、说明和来源，不重建完整历史 SOW，不逐条补规格；描述粗略不冒充读取失败 |
| AN39 | 订单查询 API 类型/业务相关，实例适用未知 / 匹配 | 本期新建工作有依据则新建+具体复用待确认；不直接复用、不扣工作、不无限补读；无关 API 不生成候选问卷 |
| AN40 | 出站事件类型相同，发送/接收/触发/契约未明或不同 / 匹配 | 实例适用明确才分类；相关但未明则新建+待确认，已知不适用则排除候选；不因类型相同省掉本期工作 |
| AN41 | 原型仍有新入口或新路径，追加调查批次已耗尽 / 探索 | 停止追加并处理剩余影响；局部问题随结果，基础缺口补料退出，不以新路径绕过上限 |
| AN42 | 大资料分页或多片首次覆盖，混入重复游标/无限拆片 / 读取与生成 | 正常有限集合首次覆盖可完成，不用两轮截断；禁止重复游标无进展和无限产生新片，追加范围受共享上限约束 |
| AN43 | 每个主题/Task 各自追加或逐项提问 / 批次准备 | 输入调查共用一次追加，问题合并到最多两轮；共享候选一问多目标，不按主题数量乘上限 |

## 3. Clarify 定位、讨论与有限应用

| ID | 场景 / 最早识别点 | 期望处理与验收结果 |
|---|---|---|
| CL01 | 新会话只有本次反馈，没有 generate 聊天 / 入口 | 从共享文件恢复相关业务状态，不要求粘贴旧会话 |
| CL02 | 没有任何可用基线 / 入口 | 说明缺失文件和恢复方式，必要时请先 generate，不隐式重走全生成 |

## 5. 文件、恢复与执行边界

| FS16 | 同一候选已修一次，或请求已返修两批，仍有错误 / 检查与恢复 | 到限结束并保留候选/current，不继续更换根因名返修，不把结构或内容错误伪装成业务待确认 |
| FS17 | 首次 ingest 初始化/登记中途失败，或分析候选已存但尚未交付 / 登记恢复 | 复用已有身份、模板和有效输入；不创建 current，不覆盖冲突配置，分析登记不使新版事实提前生效，无额外 setup 用户阶段 |
| FS18 | 已有 current 又请求 generate，或首次 generate 生效前异常出现 current / 入口与保存前检查 | 重复取结果走幂等；修改现版走 clarify，独立方案明确新目录；首次生效要求空基线，异常变化以 BASE_STALE 退出，不覆盖有效版或绕过确认 |

| OB14 | 请求开始较晚才读到快照、累计 reset/乱序，或同会话混入别的请求 / usage 接纳 | 只在同 scope/epoch、有可信边界且归属成立时求差；缺区间或混合范围单列，不能把线程总计当本请求 |
