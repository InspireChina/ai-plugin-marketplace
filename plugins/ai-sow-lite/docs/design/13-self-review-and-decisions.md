# AI SOW Lite · 自检结论与已定边界

[审阅入口](REVIEW.md) · [设计总览](README.md) · [实施计划](implementation/README.md)

初次自检基线为 `c121086`。本稿已根据用户对 Q1/Q2 的明确答复收口，并将有限编辑的机械构造接入现有工具合同；不再保留待选的并行改稿或金额控制方案。初次记录中的实施状态仅代表当时；当前进度见实施目录。下述输出边界按用户最新的 Excel 独立可读要求更新，I6.1 的实现与实际验证见 [增量记录](../validation/I6-self-contained.md)。

## 1. 两项决定

### Q1 · 同一个人串行使用

用户明确：“不存在并行场景，用法是一个人用，有问题由同一个人调整，都是串行的。”

Generate、离线查看、clarify 讨论和应用顺序发生。删除同时讨论多个改稿请求、判断基线变化是否无关、自动重建候选、迁移原确认和记录第二套应用基线的设计。

保留的版本机制只有实际消费者需要的部分：当前完整文件包、具体修改确认、稳定 ID、短提交锁、防止过期草案覆盖、请求幂等及中断恢复。后续请求直接使用最新 current；意外基线变化返回 BASE_STALE 并保留草案，不自动衔接。

这项决定针对用户请求流程。当前专业执行仍以单 session 为基线，是否优化某个分析活动的上下文继续由实测决定，不因此引入运行时并行团队。

### Q2 · 金额由模板自己计算，插件不改模板

用户明确：“金额让模版自己算，插件不用管，也不要改模版。”

这比初次自检建议的“只去掉部分汇总”更明确：一并取消插件的金额完整性判断、空值保护公式、部分金额汇总、SIT/UAT 三态改写、金额差额分析和原模板公式修复。不能在输出副本偷偷加入这些逻辑。

| 责任方 | 当前边界 |
|---|---|
| Agent | 从输入识别三类需求、拆解 Story/AC/Task，匹配工作类型/方式/复杂度/集成类型，明确业务待确认事项 |
| Python 工具 | 复制原模板、填写已有可写列、必要时按既有原型扩行；维护文件/行/名称映射和文本安全；调用 Office、检查填值及公式/结构保存 |
| 原模板及 Office | 按原有公式处理人天、SIT/UAT、取整、空白和汇总；插件不替换结果或增加计算条件 |

模板资产保持原字节，原四张表的结构、参数及公式不变。用户最新要求覆盖早先“输出仅四张表”的决定：生成结果增加可见的 04-待确认事项、05-完整说明，两表即使为空也保留；问题、当前处理、状态/目标、已有来源定位、实际采用答复和长 AC/正文在工作簿内完整可读。短字段直接填写，长文按原顺序逐字续行，主表用内部位置及可点击入口，不依赖 Markdown 外链或 UUID 问题标签。Markdown 和 projection path/anchor 保留兼容归档用途；独立查看不等于支持回导，clarify 仍需原项目文件。

未知类型/方式等仍留空，复杂度未知仍直接 M+待确认；问题表达业务事实和未拆明义务，不参与金额计算。模板结果不能被插件当成业务范围已完整的证据；模板怎样处理这些输入属于模板职责。

## 2. 自检发现及处理结果

| 发现 | 处理结果 | 权威位置 |
|---|---|---|
| 真实 Agent 候选与 token 可得性验证排得偏后 | I1.1 合同首次可校验后，先做最小 work 候选和受控 usage 探针；正式交付仍需完成 I1 | P01、P02、D09 |
| 局部编辑需准备完整候选与重复元数据，机械构造入口未闭合 | 已补 check/edits 与 prepare_edit：Agent 给有限编辑，代码派生完整候选、diff、读写集合、可读计划及摘要 | P00 §3/§5、D07 §4、P03 I3.1 |
| 原型“新路径”与“新增目标”混用 | 同一已列目标的新路径属首次覆盖；新增目标或首批后的重查受共享追加上限限制 | D03 §5.2、D04B §1 |
| 大材料只在小样本出现瓶颈后才验证 | 固定至少一组长材料单 session 的生成与局部修改基线；有瓶颈再做配对，不扩成大规模跑分 | 06、P04、D09 |
| 用户只带 Excel 可能无法后续修改 | 明确需保留原项目 `.ai-sow-lite/`；新会话无需原聊天，仅 Excel 不能重建完整基线 | README、D05、P03 |
| 单人用法却承担并行改稿衔接 | 删除自动重建/跨基线确认等分支；保留简单拒绝过期候选 | D05、D07、P00、P03 |
| 插件承担额外的金额展示与控制 | 删除整套费用完整性/保护/部分结果规则，改为原模板填值及不参与计算的业务说明 | 05、D06、EX04、P01 |

用户直接指定 S/M/L 仍被允许。仅由定档决定解决的问题可以关闭；同一问题若还包含范围、方案或责任的事实缺口，则按部分答复保留，不能伪造规模事实。

## 3. 有限修改现在怎样落地

以数百个 Task 中仅修改“资料迁移”的复杂度为例：

1. Agent 读取相关对象和依据，写本次档位、问题/决定去向、依赖选择及回查边界，不重输出其余 Task。
2. 现有 `check` 接收有限编辑稿，确认基线仍是 current，在 work 复制完整文件并应用明确编辑；程序生成 before/after、write_set、所读版本和具体 review。
3. 用户确认实际变化后，复用同一候选；金额直接让原模板重算，输出新版 Excel 与同版问题说明。
4. 不相关对象保持原值；发现过期基线、越界编辑或文件故障时保留草案/当前有效版，按既有有限出口结束。

P00 已明确编辑稿字段、嵌入 AC 的父数组处理、引用登记、增加/删除的顺序和结果文件；P03 包含有限编辑构造及未改对象校验。代码不猜语义依赖、不自动关闭问题，也不代替用户确认；没有第七个工作流操作。

## 4. 仍需实证，不再变成产品问卷

- **专业效果与上下文成本：** Lite 还没有真实速度/token 基线。先观察三类义务、默认 M、来源与候选编写成本，再决定是否需要上下文优化。
- **逐步观测：** 原生请求边界、活动归属与迟到 usage 仍需验证。缺数值保持未知，G12 不因此关闭；不以配额或模型运行器替代观测目标。
- **文件交付：** 验证原模板填值、必要扩行、安全别名、工作簿内完整正文与内部链接、Office 往返与串行恢复；不重做已验证安装/Excel 能力的基础选型，也不新增估算算法测试。
- **局部修改：** 验证构造接口确实避免模型侧全量重写、变化与确认一致、失败只保留旧有效版或识别已成功新版。
