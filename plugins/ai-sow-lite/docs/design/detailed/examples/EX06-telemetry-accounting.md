## 1. 真实只读探针与限制

探针日期：2026-09-09。未启动模型调用、另一个 App Server、后台服务或 OTel，未修改宿主配置和依赖。只检查已安装 CLI 的版本/公开类型生成能力，以及宿主标识所指向的当前会话记录；没有采集客户正文、完整工具输出、凭据或隐藏推理。

| 检查 | 实际结果 | 能证明什么 / 不能证明什么 |
|---|---|---|

## 2. 累计快照：先有可信边界，才有请求总量

以下假定合成适配器已经验证：同一 scope/epoch，序号可靠，B0 在本请求开始之前，B3 在本请求所有模型工作结束之后；这段范围只有本请求工作。total = input + output；cached 为 input 子集，reasoning 为 output 子集。**这些是假定的夹具条件，不是对当前 Codex 字段语义的实测结论。**

| 源序号 | 累计 input | 累计 output | 累计 cached | 累计 reasoning | 累计 total | 新增区间的活动 |
|---|---:|---:|---:|---:|---:|---|
| B0 | 10000 | 2000 | 6000 | 500 | 12000 | 请求前基线 |
| B1 | 11200 | 2300 | 6700 | 560 | 13500 | 输入分析 |
| B2 | 14200 | 3000 | 8000 | 800 | 17200 | 骨架与生成切片共同覆盖 |
| B3 | 14800 | 3200 | 8200 | 850 | 18000 | 合并与返回共同覆盖 |

请求 input = 4800，output = 1200，total = **6000**；cached = 2200、reasoning = 350 都是明细，不能再加到 6000。请求前的 12000 不属于本请求。

可独占归属输入分析 1500；骨架/生成共享 3700；合并/返回共享 800。总量完整，步骤分解只有部分独占归因。6000 不是四个活动各自 6000，也不按活动时长分摊。该源没有物理调用 ID，不能据四个快照宣布发生三次模型调用。

| 变体 | 预期结果 |
|---|---|
| B2 重复两次，B1 迟于 B2 到达 | 按原生序号恢复快照顺序并去重，仍为 6000；不把负到达差值裁零后累计 |
| B0 缺失 | 可报告 B1→B3 的已覆盖 4500；请求全程 total 未知，不把 B1 当零或把 18000 当请求量 |
| B3 未到 | B0→B2 已知 5200，最终尾段未知；收尾返回 partial，不轮询等齐 |
| B1→B2 之间混入另一个请求，无法分开 | 3700 只能保留在混合宿主范围；不得全部归本项目。独占的已知区间另列 |
| B2 计数突然小于 B1，epoch 信息缺失 | 该连接区间为 unknown；不能自动视为零成本或根据模型窗口猜重置 |
| 重启明确切新 epoch | 每个 epoch 内分别要求可信起点；有 reset 边界且证明从零开始才可用零基线，不能跨 epoch 相减 |

一个请求级指标的示意投影如下；完整报告还包含 input/output、共享分解、诊断与来源记录，不能只保存这一合计。

```json
{
  "value": 6000,
  "unit": "tokens",
  "scope": {"kind": "request", "id": "R-DEMO-01"},
  "basis": {"kind": "cumulative_difference", "source_id": "S-DEMO", "counter_epoch": "E1", "start": "B0", "end": "B3"},
  "coverage": "complete",
  "attribution": "exclusive",
  "diagnostics": []
}
```

这里 exclusive 针对整个请求；不能传播成每个子活动都可独占归属。

## 3. 物理调用：重试要计，重放不计

另一个合成来源有可靠物理调用 ID 和修订顺序，与上一例无数据关联：

| 观察 | 值 | 接纳结果 |
|---|---:|---|
| C1 流式快照 revision=1 | 600 | 暂记 C1=600 |
| C1 最终 revision=2 | 700 | 修正为 C1=700，不额外加 700 |
| C1 最终事件重放 | 700 | 去重，不产生新调用 |
| C1 revision=1 迟到 | 600 | 不覆盖已接纳最终值 |
| C2 是失败后实际重试 | 500 | 新调用，计 500；不能因 logical operation 相同丢掉 |
| 另一来源给出同范围父汇总 | 1200 | 只核对，不与 C1/C2 再相加 |

合计为 **1200**，两个真实调用。若 C1 的最终事件没有可判断的修订身份，不能自行把“后到”或“更大”当权威；保留诊断，待已验证来源处理。缓存命中也保留实际用量及时间，不标成免费零耗时。

## 4. 时间：并行区间与等待分别算

以下均为合成的同一可对齐时钟上的秒数：

| 区间 | 起止 | 时长 |
|---|---|---:|
| 输入分析父活动 | 0—30 | 30 |
| 子工具 A | 2—12 | 10 |
| 子工具 B，与 A 部分并行 | 8—18 | 10 |
| 等待输入澄清 | 30—90 | 60 |
| 回答后生成并返回 | 90—110 | 20 |

自然历时 110；已知等待 60；处理时段 0—30 与 90—110 合计 50。子工具累计 20，但区间并集 2—18 只有 16；父活动排除这两个完整子区间后为 14，不能减成 10。该 14 仍含模型、队列和其他未分解时间，不能称 CPU 或精确模型时间。

若 B 的结束事件丢失，B 为 incomplete；可以报 A=10 和父活动=30，但不能声称完整子区间并集或排除子活动后的时长。若 30—90 期间宿主未观察等待边界，则该间隔未知，不能沿用夹具的 60 作为真实用户等待。

用户在文件返回后隔两天发起 clarify，两天不加入 generate 的 span。Clarify 分别计接收到具体方案、已观察确认等待、确认后到更新文件；若跨时钟域而不能校准，只报可验证区间，不计算伪精确端到端用时。

## 5. 取消、迟到与采集故障

| 情形 | 当次可见结果 | 后续影响范围 |
|---|---|---|
| 请求取消时只掌握 5200，另有模型/工具未结束 | 业务按 D07 结束/保留原版；报告已知 5200、尾段未知和 incomplete 操作 | 实际收到最终 6000 后更新同请求观测报告，增量只接纳一次，不激活候选 |
| Excel 已交付，末次答复 usage 才到 | 交付摘要带当时截止点；报告暂为 partial | 后续回调/显式查询可重建报告，已交付 summary/Excel/manifest/current 不改 |
| 事件已写入、游标尚未写入就崩溃 | 恢复从旧游标重放 | event/source 身份去重；不能重跑原模型来补记录 |
| JSONL 最末一行不完整 | 完整前缀可读，尾部记 gap | 有原源才有界重读；中间损坏另报，不能当作正常结束 |
| 观测文件不能写但业务目录正常 | 业务结果正常，明确本次记录缺口 | 不触发 SOW 回退；业务也写不下则按真实 I/O 失败处理 |
| 来源生产者升级，字段/语义未验证 | 工具耗时照常，usage 适配未验证 | 保留白名单可读字段供诊断，不将原适配的 complete 能力声明沿用 |
| 埋点命令被 hook 再次观察 | 不递归生成记录器的记录器 | 实际宿主调用仍在整体 token 中；观测开销单独用外层汇总检验 |

## 6. 预期报告与性能交接

正常用户摘要可以是“已生成 Excel；本次已观测处理 50 秒、已知用户等待 60 秒；6000 token，步骤归因为部分；详见报告”。这组数只适用于第 2/4 节完整夹具；若缺起点/终点、混合 scope 或时钟覆盖不同，就分别写出已知范围和缺口，不能拼成同一次完整实测。

开发者查看活动表、共享用量、读取/返回规模、D04B 轮次与退出，以及输入/模型/模板和采集版本。只有实际执行、质量覆盖与观测范围相当，才讨论优化幅度。本文没有真实 Lite 响应时长、token 基准、目标阈值或提速结论。

后续先以受控宿主请求验证第 1 节未定边界，再把第 2—5 节变成采集/聚合器的事件夹具；最后随首个真实 generate/clarify 增量采集性能，不要求重跑旧 ai-sow 全流程。场景主责在 [D09](../D09-validation-and-implementation.md)，新增 OB14—OB19 和已有 OB01—OB13 共同覆盖。
