# EX07 · 设计收口的合同反例

[D09 收口与实现规划](../D09-validation-and-implementation.md) · [D02 数据](../D02-shared-data-and-evidence.md) · [D06 投影](../D06-excel-projection-and-delivery.md) · [D07 保存](../D07-tools-storage-and-recovery.md)

这些是合成反例及预期结果，用于实现增量的验收设计；本轮未生成对应 Excel、运行 Schema 或模拟真实文件中断。

## 1. 已有 Task 输入齐备，仍须保留未拆明的业务义务

以 EX01 的交付 Story 为基线，输入变体明确本期还承担一项额外切换工作，但缺少界定具体工作单元的内容。Agent 已判断它是可隔离局部缺口，既有迁移 Task 的范围仍成立；这里不是仅缺条数/复杂度。若实际材料不足以支持这种隔离，应走 D01 补料退出，不采用本例。

一个问题的完整示意如下，引用的身份来自本合成变体，不是生产定位：

```json
{
  "id": "P-WORK-01",
  "revision": 1,
  "question": "请补充本期额外切换工作的具体内容，以便确定可计量的 Task。",
  "targets": [{"object_id": "S-04", "field": null}],
  "evidence_refs": ["EV-H2-CUTOVER"],
  "current_handling": "保留已有迁移 Task；额外切换义务尚未拆成 Task，待补充工作内容后处理。",
  "unestimated_work": true,
  "status": "open",
  "resolution": null
}
```

| 观察点 | 预期结果 |
|---|---|
| 当前模型 | 已有 Task 和字段保留，额外义务通过当前问题与输入依据可见；不为了凑工作行编造 Task |
| 机械检查 | true 必须是对象级 Story/Feature/Epic 目标；缺失引用、非法字段目标拒绝；是否确属局部缺口由 agent 判断 |
| 工作簿与问题文件 | 复制既有模板，只填写已有迁移 Task 的白色输入；pending-items.md 与 Excel 同版，完整展示 P-WORK-01、open 状态、业务义务及当前处理方式，在既有备注引用，不新增问题列或 Sheet |
| 原公式与 Office 结果 | 已有金额、SIT/UAT、汇总及参数公式保持原语义，Office 计算结果原样保存；unestimated_work 不参与计算，不新增金额标签、完整性保护、部分汇总或三态改写 |
| 有关义务后来全部可拆 | Clarify 展示实际新增/改动的 Task、问题标记/状态及依据；同基线确认后共同应用。验收检查输入和问题的真实变化，不以金额变化判断义务是否补齐 |
| 用户明确取消额外义务 | 展示有限退出方案，确认后记录 scope_decision，并将该问题 superseded；不是伪装为已回答完成 |

对照变体：只缺复杂度时为 M + open 问题，unestimated_work=false；有具体历史候选但当前按新建时也为 false；Task 类型或集成属性为合法 null 时，对应白色输入留空并关联问题。检查原值、空字段及问题输出，不传播金额未知；标记只说明业务范围，不替代字段检查或驱动计算。

如果 Feature/Epic 有可隔离的本期义务却尚无下级工作行，问题指向该父对象，在 pending-items.md 展示，并从模板既有可写备注注明；不得为了引用凭空造 Story/Task。当前无义务的空父项应从交付模型移出，在分析中保留去向。不能因 Excel 只投影 Story 行而吞掉骨架范围，也不能用金额判定范围结论。

本例遵循统一文件交付边界：超长原文完整进入同版 details.md，可写单元格注明定位，公式列不覆盖。既有四张表不新增列、Sheet、汇总、参数或公式体系；仅在超容量时按原公式原型扩行并保留语义，模板资产哈希保持原值。

## 2. 真正无 gap 与输入不足的空模型

| 同样没有工作行的情况 | 预期出口 |
|---|---|
| 必需输入齐备且已分析，所有目标已有依据确认为已满足/不在本期，无未拆明工作 | 输出说明“本期无新增工作”的 Excel 和同版 pending-items.md，分析/排除依据仍被本版引用；金额与空行公式由原模板和 Office 处理 |
| 只有空 PRD/HLD、读取失败或基础未明 | 列补料/读取限制，保留有效工件，不拆解，不用空数组或金额为 0 冒充分析完成 |
| 有明确本期义务，但还没有任何可计量 Task | 先判断是否已构成基础不足；确属可隔离局部缺口才保留对象级问题及业务说明，不编工作行，不以金额判定业务状态 |

代码检查空工作与问题/引用是否自洽；agent 对输入充分性及“确实无 gap”的语义负责。金额缓存可能为数值、空白或错误值，均由 Office 按原模板计算和保存；插件不裁决完整、部分或不可算，也不修金额公式。文件、写入、引用或公式保存错误仍需机械恢复。这个分支不增加用户对生成结果的审批。

## 3. 初始化、重复 generate 与身份

| 输入/中断 | 预期行为 |
|---|---|
| 新项目，类型/目录已明确，首次 ingest | 初始化项目身份、请求 work 和内置模板副本，登记有效原件；没有 setup 问卷，没有 current |
| PRD 登记成功，HLD 读取失败 | 保留 PRD 版本与准确失败范围；修复 HLD 后只补相关读取，不重置计数或改模板 |
| 结构/观察已读完，agent 写出主题候选 | ingest 验证来源/摘要后保存不可变 analysis 工件；原 current 尚未采用这些新结论 |
| 首次 generate 准备后，current 意外变为非空 | 保存前最小版本核对返回 BASE_STALE；保留当前有效版与本次草案，不自动重建，不隐式转成 clarify。正常使用仍是单人串行，本变体只证明防误覆盖 |
| 相同 generate 请求已成功，响应丢失或用户再取结果 | 核实完整生效事实并返回原已应用版本，不重复写入；若后续串行修改已更新 current，不倒回旧版。指针生效前中断则保留旧有效版或无 current，不将孤立文件自动激活 |
| 已有 current，又要求“生成” | 识别取已有结果、修改现版或另建方案；修改走 clarify，独立新方案使用明确的新目录 |
| 同名对象、改名、重新分片 | 已有 ID 保留，新义务用新 UUID；不把标题/行号/片号变成身份，不逐条找服务领号 |

本例沿用 XL26、FS17—FS18，以及 AN18/AN35、XL21—XL24 和 FS01—FS08；按 Q1/Q2 调整原场景验收范围，不增加场景。I1 验证白色输入、问题文件、原公式/Office 结果保存和简单串行恢复；I1.1 合同可校验后前置最小真实候选及 usage 探针，只写 work，I2/I3 接通真实 Skill 后补语义与交互的集成证据。
