# EX07 · 设计收口的合同反例

[D09 收口与实现规划](../D09-validation-and-implementation.md) · [D02 数据](../D02-shared-data-and-evidence.md) · [D06 投影](../D06-excel-projection-and-delivery.md) · [D07 保存](../D07-tools-storage-and-recovery.md)

这些是合成反例及预期结果，用于实现增量的验收设计；本轮未生成对应 Excel、运行 Schema 或模拟真实文件中断。

## 1. 已有 Task 可算，不代表工作全部可算

以 EX01 的交付 Story 为基线，输入变体明确本期还承担一项额外切换工作，但缺少界定具体工作单元的内容。Agent 已判断它是可隔离局部缺口，既有迁移 Task 的范围仍成立；这里不是仅缺条数/复杂度。若实际材料不足以支持这种隔离，应走 D01 补料退出，不采用本例。

一个问题的完整示意如下，引用的身份来自本合成变体，不是生产定位：

```json
{
  "id": "P-WORK-01",
  "revision": 1,
  "question": "请补充本期额外切换工作的具体内容，以便确定可计量的 Task。",
  "targets": [{"object_id": "S-04", "field": null}],
  "evidence_refs": ["EV-H2-CUTOVER"],
  "current_handling": "保留已有迁移 Task；额外切换义务尚未拆成 Task，未计入完整估算。",
  "unestimated_work": true,
  "status": "open",
  "resolution": null
}
```

| 观察点 | 预期结果 |
|---|---|
| 当前模型 | 已有 Task 和字段保留，额外义务通过当前问题与输入依据可见；不为了凑工作行编造 Task |
| 机械检查 | true 必须是对象级 Story/Feature/Epic 目标；缺失引用、非法字段目标拒绝；是否确属局部缺口由 agent 判断 |
| 工作簿 | 04 表“尚未拆明工作”为是、状态 open；已有 Task 金额保留；相关 Story 和项目不显示完整金额，已知部分正常显示 |
| SIT/UAT | 已有任意适用 Task 时仍为是；全部已有 Task 不适用但仍有未拆明工作时为未知，不能从已知子集得出否 |
| 有关义务后来全部可拆 | Clarify 展示实际新增/改动的 Task、问题标记/状态及影响；确认后共同应用，不能只改标记让金额看似完整 |
| 用户明确取消额外义务 | 展示有限退出方案，确认后记录 scope_decision，并将该问题 superseded；不是伪装为已回答完成 |

对照变体：只缺复杂度时为 M + open 问题，unestimated_work=false；有具体历史候选但当前按新建时也为 false；Task 类型或集成属性为合法 null 时由字段缺值传播，不能用 unestimated_work=false 绕过原有保护。标记不替代字段检查。

如果 Feature/Epic 有本期义务却尚无下级工作行，问题指向该父对象，完整金额同样受保护；当前无义务的空父项应从交付模型移出，在分析中保留去向。不能因 Excel 只投影 Story 行而吞掉骨架范围。

## 2. 真正无 gap 与输入不足的空模型

| 同样没有工作行的情况 | 预期出口 |
|---|---|
| 必需输入齐备且已分析，所有目标已有依据确认为已满足/不在本期，无未拆明工作 | 输出说明“本期无新增工作”的可用 Excel，完整值为 0；分析/排除依据仍被本版引用 |
| 只有空 PRD/HLD、读取失败或基础未明 | 列补料/读取限制，保留有效工件，不以空数组导出一个 0 人天 SOW |
| 有明确本期义务，但还没有任何可计量 Task | 先判断是否已构成基础不足；能隔离才保留工作问题并交付真实未知，不能显示完整 0 |

代码检查空工作与问题/引用是否自洽；agent 对输入充分性及“确实无 gap”的语义负责。这个分支不增加用户对生成结果的审批。

## 3. 初始化、重复 generate 与身份

| 输入/中断 | 预期行为 |
|---|---|
| 新项目，类型/目录已明确，首次 ingest | 初始化项目身份、请求 work 和内置模板副本，登记有效原件；没有 setup 问卷，没有 current |
| PRD 登记成功，HLD 读取失败 | 保留 PRD 版本与准确失败范围；修复 HLD 后只补相关读取，不重置计数或改模板 |
| 结构/观察已读完，agent 写出主题候选 | ingest 验证来源/摘要后保存不可变 analysis 工件；原 current 尚未采用这些新结论 |
| 首次 generate 准备后，另一个请求已写 current | 锁内拒绝首次生效；不覆盖先成功者，不隐式转成 clarify |
| 相同 generate 请求已成功，响应丢失或用户再取结果 | 返回原已应用版本；若 current 后续更新，不倒回旧版 |
| 已有 current，又要求“生成” | 识别取已有结果、修改现版或另建方案；修改走 clarify，独立新方案使用明确的新目录 |
| 同名对象、改名、重新分片 | 已有 ID 保留，新义务用新 UUID；不把标题/行号/片号变成身份，不逐条找服务领号 |

本例对应新增 XL26、FS17—FS18，以及已有 AN18/AN35、XL21—XL24 和 FS01—FS08。最早在 I1 的合同/投影/保存中验证机械部分，I2/I3 再用真实 Skill 演练语义与交互；不能只在最终端到端测试才发现这些接口缺口。
