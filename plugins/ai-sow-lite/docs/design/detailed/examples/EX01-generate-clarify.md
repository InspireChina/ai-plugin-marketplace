# EX01 · 三类需求生成与新会话补值

[D01 交互](../D01-interaction-and-outcomes.md) · [D02 数据](../D02-shared-data-and-evidence.md) · [D07 保存](../D07-tools-storage-and-recovery.md)

这是**专为设计走读编写的合成项目**，以下 PRD、HLD 和用户答复均为样例输入，不是客户资料或真实执行记录。版本 v1/v2 和所有 ID 是可读示例；未在本例实际生成 Excel、计算人天或测量 token。示例标准名称已按 [Lite 模板](../../../../assets/sow-template.xlsx) 核对，不复制标准人天。

## 1. 输入包

项目：“资料与公告查询台”，新项目。PRD、HLD 必需且已有；未提供原型。本例未提供往期 SOW，估算 as-is 为空；P1/H1 表达 to-be，H1 指明的外部前提不计为本期建设。每项本期工作仍按实际工作边界和模板判断，零匹配默认新建。

开场记录：用户调用 generate 时已说明是新项目，agent 直接采用；接着收集必要的 PRD/HLD，说明原型可选。用户提供下面的 P1/H1 后开展分析。若材料已随请求提供，直接登记；不重复索取，不在开场增加范围或技术方案问卷。

下列块标识作为样例原件定位。真实项目由不可变输入版本、章节/区域与摘录指纹定位，不要求用户给原文添加这些 ID。

### PRD，版本 P1

| 来源块 | 原始要求 |
|---|---|
| P-B1 | 资料查询页和公告查询页分别提供列表。各页均有六个已定义的筛选/展示条件，其中两个为精确匹配筛选、四个为展示条件；只有一个查询数据源和一个使用角色；查询后分别显示结果、无结果或失败反馈。不提供编辑、导出、权限管理和分页状态跨会话恢复，不要求复杂计算。 |
| P-B2 | 两类查询各有一个业务对象。API 支持资料/公告按给定条件精确查询、简单分页；返回有结果、空结果或失败三类结果；无排序聚合、多租户隔离或量化服务目标。使用既有入口的单一权限规则，不改身份平台。 |
| P-N1 | 两页对同类失败显示一致的错误码含义和提示，用户可手动重试；切换查询后不显示上一请求的迟到结果。这是本期非功能要求。不得自动重试有副作用的操作；本期两个查询均为只读。 |
| P-D1 | 上线后可在资料查询页检索原库的既有资料，资料编号、标题与正文等约定字段保持一致。公告数据已由平台提供，不需要迁移。 |

### HLD，版本 H1

| 来源块 | 原始方案/约束 |
|---|---|
| H-B1 | 前端两页和后端两个查询事务均为本期新增，打包为一个部署组件。平台方已经提供目标存储结构、只读访问层、入口鉴权和运行环境，支持上述两类查询；本期不修改这些资产。每个 API 仅对其对应数据对象查询，不另接外部系统。 |
| H-N1 | 新建一个应用级公共查询客户端程序库，独立版本管理，提供 query、cancel、normalizeError、bindRequestState 四个公开接口，供两个页面模块使用；包括示例、基础兼容说明和独立验证。沿用标准实现，不承担 UI 渲染、历史版本兼容、插件扩展、跨应用治理或额外安全/性能专项。 |
| H-N2 | 公共程序库实现统一错误转换、手动重试调用及迟到响应处理。两个页面只接入公开接口并验证本页行为；程序库构建及其独立验证只交付一份。不得在页面 Task 中重复计入公共实现。 |
| H-D1 | 原资料库被目标存储替代。资料域为单一源目标组合、一个对象组、14 个已确定字段一对一映射，质量基线明确，不要求清洗、持续同步或双写。新建迁移资产，包含装载及字段/记录核验；允许整体回滚，无零停机或独立停机时长门禁。记录条数未提供。生产数据由客户掌握，插件和本期开发人员不直接访问生产取数。 |
| H-D2 | 本期发布为同一个部署组件、一个执行团队、一个已确定窗口；现有发布规范给出六个步骤、标准回滚及 Go/No-Go 判据。需要形成对应版本的发布与切换方案，使用上述既定规范，不新设计发布策略。本期是否负责该方案、迁移资产及生产执行，待责任人确认。 |
| H-D3 | 迁移资产验证通过的字段/记录核验结果供发布方案引用。迁移独立演练、生产迁移、部署执行、正式验收测试活动及培训由客户已有团队承担，本期开发 Task 自身必要验证仍包含在相应工作中；最终责任以本次澄清为准。 |

### 这些材料支持和不支持什么

- P-N1 + H-N1/H-N2 支持独立公共技术 Story；不是看到“NFR”字样就创建一个新服务。
- P-D1 + H-D1 支持主动识别资料承接与核验，即使 PRD 没有“迁移 Epic”的标题。
- H-D2/H-D3 尚不能单独决定本期交付责任，需要用户确认；原型缺失不阻断分析。
- H-B1 界定平台方提供且本期不改的外部前提，属于 to-be 责任边界；本期不为这些资产创建建设 Task。新页面/API/客户端和迁移资产无对应 as-is，按“新建”处理；不另行调查平台来建立全量现状库。
- 数据条数暂缺不猜规模；复杂度按授权默认 M 出稿并附待确认，不反复查条数；没有业务依据的额外设计、PoC、自动化平台、正式测试和生产执行不能按常见清单加入。

## 2. 分析后的问答

**Agent：** HLD 的本期责任尚未明确：请确认资料迁移资产、发布与切换方案、独立演练和生产执行分别由谁承担。

**用户 A1：** 本期负责迁移资产及其自测、字段和记录核验，以及发布与切换方案。独立演练、生产迁移、部署和正式验收由我们已有团队负责。其他边界按 HLD。

A1 随初版作为已采用的事实保存。责任问题已解决；条数缺口被明确隔离到迁移分类，其他方案与范围足够。用户无需再批准骨架或每个切片。若 A1 改为“迁移方式、源目标和发布策略也没定”，则不能沿本例继续，应要求补方案。

这轮只确认影响本期范围的交付责任；不让用户选择 Task 类型/复杂度、批准七个 Task 的拆法或确认“可以开始出稿”。后续分类由 agent 使用事实与模板自主判断。第 5 节的修改方案确认属于独立 clarify 入口。

这里没有隐瞒已知缺口来人为制造“后期问题”：输入分析记录缺少条数，Task 拆分后再把这个限制绑定到具体 Task 字段。

## 3. 骨架、Story 与 Task

本例恰好采用三个 Epic，便于检查三类范围。实际项目不要求三个顶层目录；内部也不增加一个“业务/技术/交付”必填枚举。

| Epic / Feature | Story（内部 ID） | 从材料提取的 AC | Task |
|---|---|---|---|
| E-01 信息查询 / F-01 资料查询 | S-01 查询资料 | AC-01：依约定条件查询并显示结果、空结果或失败。AC-02：本页同类失败提示一致，手动重试可再次查询，迟到响应不覆盖新查询。来源 P-B1、P-B2、P-N1。 | T-01 资料查询页及公共客户端接入；T-02 资料查询 API |
| E-01 信息查询 / F-02 公告查询 | S-02 查询公告 | AC-03：公告按约定条件查询并显示对应三类结果。AC-04：本页遵循统一失败、重试及迟到响应要求。来源 P-B1、P-B2、P-N1。 | T-03 公告查询页及公共客户端接入；T-04 公告查询 API |
| E-02 查询技术基础 / F-03 公共查询客户端 | S-03 交付公共查询客户端 | AC-05：两个页面模块通过四个公开接口使用统一错误转换、手动重试及迟到响应处理；提供版本、示例、兼容说明和独立验证结果。来源 H-N1、H-N2、P-N1。 | T-05 新建公共查询客户端程序库 |
| E-03 资料承接与上线准备 / F-04 资料承接 | S-04 承接历史资料 | AC-06：按约定 14 字段映射装载资料并给出字段/记录核验结果，资料可从目标查询链路检索；允许整体回滚。来源 P-D1、H-D1、A1。 | T-06 资料域迁移资产与核验 |
| E-03 资料承接与上线准备 / F-05 发布准备 | S-05 编制本次发布与切换方案 | AC-07：方案覆盖本次组件、窗口、六个步骤、既有 Go/No-Go 及标准回滚，并引用迁移核验结果；不承担生产执行。来源 H-D2、H-D3、A1。 | T-07 本次发布与切换方案 |

AC 可在一个单元格中逐条展示，但内部保留轻量 ID 方便改其中一条。Task 归 Story，不强制关联 AC：T-01 同时支持两条 AC，T-02 也支持查询结果；不能按两条 AC 把整套实现复制两份。

### 3.1 四项定性匹配

| Task | 工作类型名称（标准 ID） | 工作方式 | 复杂度 | 集成类型 | 判断依据与包含边界 |
|---|---|---|---|---|---|
| T-01 | 信息展示与查询页面（FE-VIEW） | 新建 | M | 不适用，Excel 留空 | P-B1 的六项条件、三个状态落入标准中档范围，无已知高档触发；H-B1 明确新页。包括本页调用及验证，不含 T-05 公共建设。 |
| T-02 | 业务数据查询 API（FE-QUERY-API） | 新建 | S | 不适用，Excel 留空 | P-B2/H-B1：一个对象、简单精确查询和分页、三个结果状态、单权限规则，无高档条件；查询能力和必要验证一起计量。 |
| T-03 | 信息展示与查询页面（FE-VIEW） | 新建 | M | 不适用，Excel 留空 | 与 T-01 使用相同规则，但页面是独立交付；公共建设仍仅由 T-05 承担。 |
| T-04 | 业务数据查询 API（FE-QUERY-API） | 新建 | S | 不适用，Excel 留空 | 对公告对象形成独立查询事务；依据 P-B2/H-B1，不因同为 API 合并成一个 Task。 |

| T-06 | 历史数据迁移（DATA-MIGRATION） | 新建 | **M（默认，待确认）** | 不适用，Excel 留空 | H-D1/A1：起点、映射和回滚已知，条数未提供，无法确定档位，按默认 M；关联 P-01，不追加补证。装载与内含核验同计，不再重复建“对账” Task。 |
| T-07 | 发布与切换方案（REL-PLAN） | 新建 | S | 不适用，Excel 留空 | H-D2/A1：本次新方案，单组件、单团队、六步、窗口和标准回滚明确。独立演练与生产执行不计入。 |

表中“新建”都有本次交付资产起点依据。两个页面要接入公共组件，不意味着页面 Task 的工作方式自动改为“接入复用”；标准已把普通组件消费包含在对应实现中，没有额外的跨系统集成交付。

标准的每个计量单位仍需核对。这里恰好各为一个页面、事务、程序库、数据域源目标组合或发布批次，没有数量乘数，也未将多个独立单位塞进一个 Task 来压低估算。

| 关系 ID | 使用/依赖方 → 提供/前置方 | 用途 |
|---|---|---|
| R-01 | S-01 → S-03，uses | 公共契约变化时检查资料页实际接入 |

## 4. 初版 v1 的交付预期

初版含 3 个 Epic、5 个 Feature、5 个 Story、7 条 AC、7 个 Task，P-01 保持 open。项目模型不保存人天或 SIT/UAT 值。

| 问题 | 影响 | 现行处理 | 需要的回答 |
|---|---|---|---|
| P-01，问题修订 1 | T-06 的 complexity，及受其影响的汇总 | 按默认 M 估算迁移工作；P-01 待用户确认/调整，不误标未估算 | 确认 M 是否可接受，或提供目标档位/规模事实；若工作边界变化一并说明 |

Excel 仍是主要交付物：七个 Task 均有可估算分类，T-06 按默认 M；P-01 清楚展示当前口径与待确认事项。人天及汇总由既有模板自行计算，插件不判定完整估算或全部事实已确认。**缺类型、方式或必要集成属性时，保留输入空值，并在同版独立待确认说明中列明事实缺口，不改变模板公式或金额。**

UAT 按现有标准公式派生：S-01/S-02/S-03 为“是”，S-04/S-05 为“否”。T-06 默认 M 不改变其已知任务类型；本例所有 Story 的 SIT 均为否，没有 SIT/UAT 决策问题。技术 Story S-03 适用，说明领域类别不能替代类型规则。

成功返回即结束 generate。用户不回来则流程已经满足使用方式，不存在必须定稿或后台补检。

v2 将 complexity 改为 S，并将默认口径依据更新为该字段的事实判断记录，依据为 EV-H-D1 和 D-02，规则定位仍为 DATA-MIGRATION；这属于该字段的必需依据更新，不是额外业务变化。P-01 的 resolution 引用 D-02 和本次已应用请求。完整写集合必须包含这些元信息，不能把它们伪装成无需检查的旁写。

## 6. 公共能力变化的第二种走读

用户若说“取消统一迟到响应处理”，这是自由建议，不是 P-01 补值。它会改变 P-N1 及 S-03 的技术义务，并影响 S-01/S-02 对应 AC 和 T-01/T-03 接入工作。Agent 需要呈现具体删除/保留方案，并要求用户明确覆盖原 PRD 要求的范围，不能只删 T-05 或自动改为三个局部实现。

此时读入两个直接消费方和公共契约；方案写集合可能包括 S-03、AC-02/AC-04/AC-05、T-01/T-03/T-05 的受影响字段及关系依据。API、迁移和发布是否受影响按具体契约判断，不默认重拆。如果公共实现仍承担其余接口，同名 Task 可以保留 ID；若交付对象实质替换或拆分则换 ID 并记录义务去向。这个方案需要 D05 的进一步实例，不能沿用 CP-01 的确认。

## 7. 提前走读的失败与取消分支

| 分支 | 最早识别与用户结果 | 保留与有限恢复 |
|---|---|---|
| 分析后问题包混入“批准 Task 拆法/选复杂度/确认出稿” | 提问前移除这类问题；有缺失输入事实就直接问事实，无实质输入问题就推进 | 保留输入分析，由 agent 完成专业拆解和分类 |
| 缺 HLD、老项目缺往期 SOW | 接收即要求对应材料，不从标题生成 AC | 原件索引；补料后分析 |
| A1 只回答生产责任，仍未决定迁移资产责任 | 分析后继续问具体责任 | 复用已经确定的外部执行边界，不进入生成 |
| A1 表明目标存储、映射和切换方向都未定 | 说明需补方案，本次结束 | 保留需求和冲突，不输出伪完整 Excel |
| A2 只有“8 万条”，没有确认方案 | 答案只进入草案，展示 CP-01 | v1 及 open 的 P-01 不变；新会话可继续 |
| 用户取消 CP-01 | 不应用 | v1 可用；迟到导出只留候选 |
| A2 同时把一对一迁移改成持续双写 | 不是仅补档位，重新讨论影响范围 | CP-01 不生效；保留新事实草案，不局部偷偷替换方案 |
| 生成 Excel 时失败 | 说明尚未交付成功 | 七个 Task 和依据仍可复用，仅修导出/计算 |
| 新文件完成而 current 尚未切换时中断 | 用户仍使用 v1 | 核对完整候选、确认及基线后决定是否恢复 |
| v2 已生效但响应丢失 | 找到已应用请求，返回 v2 | 不再补一次值、再次关闭问题或生成重复版本 |
| 他人先修改了 T-06 的映射前提 | 旧方案失效，展示具体差异 | v1 的确认不能覆盖新前提；无关内容不重拆 |
| usage 不可得 | 不展示虚构 token 数 | 文件仍可交付；标记未知粒度，保留可实测工具用时 |

## 8. 走读结论及尚未证明的部分

设计走读表明：三类范围能够在同一层级中表达；公共建设单计，接入包含边界可说明；一个局部问题可在新会话定位到单个分类字段；无需独立实施对象、全量 IR 或流程状态机。

这些是设计中的可解释性结论。实际 Skill 能否主动识别该范围、真实模型能否被机械验证、未知如何正确传播到 Excel、文件中断是否可靠、实际用时/token 是否改善，分别由 D03/D04、D02/D07、D06、D07、D08 后续实现验证，见 [D09](../D09-validation-and-implementation.md)。
