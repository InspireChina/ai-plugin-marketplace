# EX04 · 同一份 SOW 的 Excel 投影走读

[D06 投影合同](../D06-excel-projection-and-delivery.md) · [EX01 业务内容](EX01-generate-clarify.md) · [EX03 历史候选](EX03-as-is-to-be-gap.md)

本例用已有合成输入说明字段、文件引用及修改范围。未生成工作簿、未实算人天、未测量性能；坐标是设计预期，不能当作真实 `projection.json` 或已执行测试。模板资产保持原字节，输出保留原四张表并增加可见的 `04-待确认事项`、`05-完整说明`，全部金额由 Office 执行原模板公式。Excel 独立可读；本例不是 I6.1 验证记录。

## 1. EX01 初版：迁移复杂度默认 M，问题在工作簿内阅读

EX01 v1 有 3 Epic、5 Feature、5 Story、7 AC、7 Task。资料条数不足以识别 T-06 的复杂度，直接填 M，P-01 针对 complexity 保持待确认；不回头搜索或追问条数。公共建设 T-05 只保留一条建设 Task。

| Story | 01 表行 | D / E 的关键预期 |
|---|---|---|
| S-01 查询资料 | 5 | D 保留 AC-01、02；E 引用公共客户端和迁移前提 |
| S-02 查询公告 | 6 | D 保留 AC-03、04；E 引用公共客户端 |
| S-03 交付公共查询客户端 | 7 | D 保留 AC-05；所属建设任务为 T-05 |
| S-04 承接历史资料 | 8 | D 保留 AC-06；E 链接 P-01 在待确认表中的位置 |
| S-05 编制本次发布与切换方案 | 9 | D 保留 AC-07；E 保留迁移核验前提 |

A/B/C 分别填写 Epic、Feature、Story 的同版显示名，内部 ID 和层级不变。容量内保留模板预留区域：SOWStoryTable 仍为 A4:J64；七个 Task 写入 02 表第 5—11 行，TaskTable 仍为 A4:L204。其余输入行保持空白，公式行不删除。

T-06 在 02 表第 10 行：C 为“历史数据迁移”、D 为“新建”、E 为 M、F 空白（不适用）、G 保留原备注并追加“复杂度默认 M；请确认或提供调整意见，见 04-待确认事项”，并链接实际问题区段。01 表 F:J、02 表 H:L、03 表汇总公式及标准/参数均保留原样，不由工具写数或增加保护公式。

`04-待确认事项` 中 P-01 对应区段为（P-01 仅为本例短 ID，实际显示可读序号，不使用 UUID 问题标签）：

| 内容 | 预期 |
|---|---|
| 版本 / 位置 | v1 / 待确认表实际区段；内部链接按本版位置生成 |
| 编号 / 状态 | P-01 / 待确认 |
| 涉及内容 | T-06“资料域迁移资产与核验”的 complexity；全部实际 targets 逐项保留 |
| 待确认事项 | 当前默认 M，请确认或提供调整意见；也可补充资料条数等事实 |
| 当前处理 | 复杂度输入采用默认 M，未声称材料已证明 M |
| 来源定位 | EX01 H-D1/A1 的实际登记位置，本例不编造行号 |
| 已采用答复 | 空白 |
| 工作簿位置 | `02-任务清单!E10`，备注入口在 G10；Story 备注引用位于 `01-需求故事!E8` |

工作簿始终包含两张说明表；没有长文时 05-完整说明 展示空态，不加金额状态栏。`summary.md` 说明本版存在 1 项默认复杂度待确认，并给出工作簿入口；它不展示金额或完整/部分标签。Office 按原公式计算并保存结果，工具只复读输入、引用、公式和缓存保存事实。

## 2. Clarify：确认或调整默认 M

用户 A2 提供 8 万条且其余条件不变，具体方案 CP-01 把 T-06 从默认 M 调整为 S，更新依据、关闭 P-01 并记录决定。用户确认方案后应用，实际专业写范围仍限于这些字段。

| 阶段 | 文件结果 |
|---|---|
| 收到 A2，还在讨论 | v1 的 E10 仍为 M，同版待确认表仍展示原问题及待确认状态 |
| 方案确认且 apply 成功 | 新版 E10 为 S，待确认表标记 P-01 已解决，并展示实际采用的 A2 答复；原公式由 Office 计算保存 |
| 用户直接确认 M 可用 | 值仍为 M，只更新依据、问题、决定和版本说明，不为补条数继续追问 |
| 用户指定改 S/L | 无已知标准冲突时记录用户决定并展示有限方案，不编造规模事实证明档位 |
| Office 或文件投影失败 | 保留候选和 v1，只处理对应导出故障，不重拆其他 Task |
| apply 前预期版本不匹配 | 返回 `BASE_STALE`，保留候选，不自动迁移到新 current 或沿用跨基线确认 |
| apply 成功但响应丢失 | recover 返回已成功版本，不重复重算或生效 |

对象数量、顺序、名称和 ID 不变。工具记录输入字段与文件的变化，不计算金额差额，不用金额变化反推业务影响范围。只有同一基线及全部绑定内容未变的完整准备包可以复用。

## 3. EX03：新建非空且复用问题 open

本节是独立候选变体，不往 EX01 添加订单需求。T-ORDER/T-EVENT 有具体历史 API/事件候选但实例适用未明，工作方式当前填新建；复杂度采用有依据判断或默认 M。

备注显示“当前工作方式为新建，历史候选尚未确认适用”，并链接 04-待确认事项 中的实际问题区段。待确认表列出候选及待确认事实，不增加假想复用 Task、复用金额或费用对照。

若 T-EVENT 同时缺必要集成类型，F 留空并引用独立字段问题；原模板公式继续由 Office 处理。工具不判定 SIT 或项目金额是否完整，也不因为 D 已填新建就关闭任何问题。

用户明确指定历史 API 且说明需新增过滤条件后，clarify 核对实际内容、模式、复杂度和相关依赖，给出具体方案；不能只替换工作方式并自动沿用旧档位。已有依据但未拆明的局部工作以 `unestimated_work` 在待确认表说明业务范围，不创建无依据 Task，也不接入公式或金额门禁。

## 4. 机械别名和长内容变体

两个不同 Feature 下恰好都有名为“查询订单”的 Story：

- 初次按稳定 ID 分配显示名，同名时使用可区分的身份后缀；每个 Task 的“所属故事”取同一映射。
- 同一基线的下一版新增同名 Story 时保留既有合法别名，给新增对象分配未占用别名，不修改原业务标题。
- 原名 `查询*?~订单` 使用 `S-短身份码` 这样的机械安全别名；Story C 和全部所属 Task A 一致。原名完整写在 E 备注或 `05-完整说明`，原 COUNTIF/SUMIF 公式不改写。
- 超长标题也使用短别名，完整原名按对象/字段以原顺序在 05-完整说明 续行保存；别名不添加任何业务含义。
- AC/备注过长时，白色输入保留明确标注的片段、05-完整说明 内部位置与可点击入口；续行逐字保留换行规范化后的全部原文、空白和 AC 顺序，项目映射保留 AC ID，不建立永久片段实体或新投影协议。
- 名称或 AC 以 `=SUM(...)` 等字符串开头时强制按文本写入，不以添加单引号或拼接公式改变原文；关联名是否需别名单独按安全规则判断。

任务列表 H 是只读公式列。显示不全或原公式达到文本容量时保留其公式与 Office 原样结果，完整 Task 清单按已有关系以可读续行放在 05-完整说明，内部入口只写入 Story E 备注。TaskTable 的所有任务行保留，不把 H 覆盖为清单、任务数或位置公式。

`projection.pending_items` 记录问题 ID、`pending-items.md` 路径、锚点和全部目标位置；`projection.details` 只记录对象/字段、`details.md` 路径、锚点与入口单元格。这些 path/anchor 继续用于兼容和项目归档，不能作为工作簿的阅读入口。正文在工作簿内完整保存，状态来自同版问题数据；projection 仍为 lite-projection-v1，不新增正文、金额 status 或分段协议，渲染实现为 lite-render-v5。复读核对实际续行、内部链接和归档引用。

## 5. 文件检查与业务出口

| 变体 | 预期出口 |
|---|---|
| 复杂度无法识别，其他分类齐备 | 默认 M+问题，照常投影，不回查补证或伪造规模 |
| 已知适用 Task 与未知类型 Task 同属一 Story | 保留已知类型和合法空白，问题定位正确，SIT/UAT 和金额原公式不改 |
| 局部分类留空可能使多个结果为空或出现原模板提示 | 只核对输入是否按候选写入、原公式及缓存是否保存；不打完整/部分/不可算标签 |
| 没有本期 gap，来源和责任已足够 | 说明无新增工作，保留预留区、原公式及两张说明表的真实空态，不生成虚假 Story/Task，不手写零结果 |
| 只有空骨架，实际范围未知 | 专业阶段停止拆解，返回资料要求与已有分析，不能用空 Excel 替代 SOW |
| 第 61 个 Story、第 201 个 Task | 一次按原型扩表，末行公式、数组 ref、校验、保护和打印范围对应新容量 |
| 输入或普通保存导致 Office 缓存丢失 | 原实算记录不能证明最终文件，定向处理保存问题，失败不激活；不修原模板公式 |
| 原模板对合法输入产生错误值或长列表不可读 | 保存原样结果，不按金额裁决交付；列表全文通过既有备注引用，投影自身损坏另作技术诊断 |
| 模板或投影版本变化但文件路径相同 | 旧准备包不能按路径直接复用，核对真实输入身份及兼容原型 |
| 说明表遗漏/隐藏、续行缺字/乱序或内部链接失效 | 文件核验失败；外部 Markdown 全文存在不能替代工作簿独立可读 |
| 项目归档 pending/details 漏交或锚点失效 | 仍按项目包一致性核验，Excel 阅读不依赖这些文件 |
| 旧 applied 与旧 prepared | 旧已应用版本保持原样；旧准备包不能凭原成功收据绕过 v5 核验 |

后续实现验证须覆盖真实文件、别名关联、文本安全、原公式保存、超容量扩行及 Office 复读。D09 分开记录“走读预期”“既有模板证据”和“Lite 投影实际验证”；本轮只修设计，不修改或执行测试，也不生成或编辑模板资产。
