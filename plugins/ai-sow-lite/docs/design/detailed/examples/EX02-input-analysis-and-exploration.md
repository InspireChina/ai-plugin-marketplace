# EX02 · 多用途材料、原型冲突与输入问题的去向

[D03 输入分析](../D03-input-analysis-and-exploration.md) · [EX01 业务结果](EX01-generate-clarify.md) · [D04A 单 session 全景](../D04A-single-session-panorama.md)

这是合成设计走读，复用 EX01 的查询、公共客户端、资料迁移与发布范围。为验证输入边界，本例改为**旧项目新增这些能力**，并增加混合工作簿与原型。以下文件、读取结果、观察和答复均为设计样例；未创建或运行该原型、未解析真实工作簿、未生成本例 Excel，也没有真实 token 记录。

## 1. 输入包与角色登记

用户已说明是旧项目，并一次性提供下面三份输入；开场直接复用项目类型和已给文件。

| 物理输入版本 | 合成材料内容 | 角色与用途 |
|---|---|---|
| C1：`scope.md` | 一个文件分“产品需求”和“高阶设计”两部分，分别包含 EX01 的 P-B1—P-D1、H-B1—H-D3 内容 | 一个物理版本，PRD/HLD 两类内容，各自登记对应章节；本期范围与架构/交付约束 |
| W1：`prior-and-draft.xlsx` | `历史范围` 中记载旧权限配置管理页及其专用配置 API，范围明确不含资料/公告查询或应用级公共查询客户端；`本期草稿` 中 BA 已列出资料/公告查询的 Epic/Feature；`附注` 隐藏区域说明本期发布责任以新 HLD 澄清为准；另有旧估算标准 | 历史区域构建 as-is，辅助 draft 属于 to-be；分别指向区域，旧标准不作为本期规则 |
| R1：`prototype/` | HTML/JS/CSS、模拟数据与页面入口，演示两个查询页；失败后自动重试一次；没有真实后端连接 | 可选原型，作为交互证据/线索；不证明能力已实现或可复用 |

PRD、HLD、旧项目往期 SOW 的**内容角色**在此齐备，不要求为三个角色提交三个独立文件。原型可选，但既然已经提供且涉及查询行为，就分析有关部分。W1 的业务骨架不限制范围：公共技术、迁移与发布仍从 C1 主动识别。

如果 C1 的“高阶设计”实际只有标题和一句“沿用平台”，角色标签不足以通过充分性判断；改为要求补充主要技术边界。若 W1 只有本期 draft，没有历史内容，也不能当作已提供往期 SOW。

## 2. 第一次读取返回与保留内容

| 操作 | 工具保存/读取 | 同一主 session 接收什么 |
|---|---|---|
| 登记 C1 | 原字节、角色/用途区域、标题及结构索引 | 两部分目录、身份与必要限制；随后按主题读有关内容 |
| 登记 W1 | Sheet/Table、合并与隐藏区域、相关单元格和公式/缓存状态 | 历史、draft、附注、旧标准的区域位置；附注未读时明确标记 |
| 登记 R1 | 包内路径/内容摘要、入口与静态资源关系 | 入口、与查询/重试相关源码线索、模拟数据说明 |
| 读取 C1 查询与公共客户端主题 | P-B1/P-B2/P-N1、H-B1/H-N1/H-N2 对应实际区域 | 业务行为、公共契约、单一建设归属和必要反例 |
| 读取 W1 相关内容 | 历史能力边界、两个业务 Feature、有关隐藏附注 | 有关原文与准确位置；不读取旧标准来覆盖 Lite 标准 |

上表不预设具体行号、单元格地址或摘要。真正执行时由读取器生成 `text_lines` / `xlsx_range` 定位与指纹；EX01 的 P/H 块名仅用于说明本例引用的内容，不能当作生产工具已验证的 locator。

W1 历史区域直接构建 as-is。其管理页/专用配置 API 与 C1 的资料/公告查询和公共客户端是不同能力；完成相关范围分析后无匹配，按“新建”继续，不另问是否已交付或是否新建。历史管理功能并未被目标要求改变，不计入本期；draft 的当前名称也不能反向变成历史能力。匹配到旧资产时的其他模式见 [EX03](EX03-as-is-to-be-gap.md)。

## 3. 原型探索及证据边界

**以下 OBS-01/02 是预期记录示意，不是实际浏览记录。**

| 观察示意 | 实际执行时要记录的最少信息 | 能支持什么 | 不能据此断言什么 |
|---|---|---|---|
| OBS-01 查询展示 | R1、查询页起点、模拟数据前置、输入筛选/执行查询、列表或空结果表现；必要页面状态附件 | 原型表达的筛选和结果状态，与 PRD 对照 | 真实 API 已存在、权限平台可用或数据库含这些记录 |
| OBS-02 失败重试 | R1、演示失败的可用前置、执行查询、错误出现后原型自动再发一次模拟查询；保留相关脚本/状态与限制 | 与 P-N1/H-N2 的手动重试存在重要差异 | 自动重试就是本期新要求，或应该修改 PRD/HLD |

两个页面共用客户端不能仅靠标题或外观相同认定。通过输入的共用边界与相关源码核对是否相同；只对确有独立行为差异的消费方追加观察，不为同一共用规则重复遍历所有组合。

若失败状态不可达，OBS-02 不应写“已看到自动重试”。可用源码中的明确逻辑记录为 `statement`，保留“未运行验证”的限制；如果冲突是否存在仍不确定，先补读必要资源。没有真实观察时不能生成截图或用文字回忆冒充工具捕获。

若原型完全启动失败，保留 R1 源码、已知模拟条件和缺失运行前提。PRD/HLD 足以说明业务行为时可继续输入综合，并注明原型未验证；只有关键输入因此无法理解时才要求具体补料。不能改写原型逻辑或添加假后端来获得成功截图。

## 4. 输入分析形成什么

| 主题 | 必要结论与依据 | 限制/下一步使用 |
|---|---|---|
| 查询行为 | C1 的 PRD/HLD 支持两类只读查询及已有明确验收意图；W1 提供可复用命名 | 原型自动重试差异待确认；后续形成业务骨架与来源 AC |
| 公共客户端 | H-N1/H-N2 表达目标独立建设、两页消费；相关 as-is 无对应客户端，默认新建，公共实现只计一次 | 与查询主题共享重试事实；后续形成技术骨架和消费关系 |
| 资料承接 | P-D1/H-D1 支持源目标替换、14 字段映射、装载与内含核验 | 本期责任需确认，条数缺失；后续形成迁移范围及分类依据 |
| 发布责任 | H-D2/H-D3 与 W1 附注表明责任需本次澄清，已有发布策略有依据 | 需明确方案、独立演练与生产执行归属；后续区分本期与外部工作 |

这里保存主题、必要依据与限制，不先输出五个完整 Story、七个 Task。物理覆盖记录还包含 W1 的旧标准区域：已经识别它是历史规则，明确不用于本期估算；不能把“未读旧公式”误报成“当前标准已分析”，也不要求展开全表来证明无关。

## 5. 分析后只问输入事项

工作问题先关联主题和来源，不引用尚不存在的 Task ID。

| 输入问题 | 来源与影响 | 用户需要回答什么 |
|---|---|---|
| IQ-01：重试行为 | C1 手动重试要求与 R1 自动重试冲突，影响查询及公共客户端 | 本期以哪种输入行为为准，原型差异是否属于本期 |
| IQ-02：迁移与发布责任 | H-D2/H-D3 与 W1 附注；影响本期/外部交付边界 | 迁移资产/内含核验、发布方案、独立演练、生产执行分别由谁负责 |
条数缺口保留为 work 事项 IQ-03，但不加入本轮问卷：它只影响定档，形成 Task 后直接默认 M 并带出待确认。

合成答复 A1：本期仍按 PRD/HLD 做手动重试，原型的自动重试只用于演示，不计入本期；本期负责迁移资产、自测与字段/记录核验、发布与切换方案，独立演练和生产执行由客户已有团队承担。其他约束不变。

Agent 保存这条答复的必要原话、对应问题/修订和适用范围：手动重试决定只解决有关行为冲突，不代表整个原型已被用户放弃，也不是用户批准任何 Task 清单。责任答复不新增 HLD 未规定的迁移方式或发布策略。

基础现在足够；IQ-03 只影响复杂度，采用默认 M 后等待后续意见。无需要求用户批准分析摘要、骨架或“开始出稿”，也不在下一片再次询问同一条数。

## 6. 交给骨架与分片的实际内容

继续复用 EX01 的范围组织：两个业务查询目标、一项独立公共客户端、资料承接及发布方案。交给 D04 的内容是 as-is/to-be 对照后的本期 gap、相关历史匹配范围/零匹配结论、责任/依赖、采用的重试事实、来源定位、覆盖限制和未决条数；不把 R1 的全部探索过程或 W1 的旧标准重新传入。

同一 session 的历史仍可能含原文、观察示意对应的真实工具返回和问答。上述文件/读取安排减少下一次新增内容，不保证历史消失；真实压缩发生时从当前有效主题和工作记录恢复，不能误用 A1 之前的自动重试候选。

| 输入问题的去向 | 生成后的对应结果 |
|---|---|
| IQ-01 已解决 | 查询和公共客户端按手动重试形成来源 AC/工作内容；引用 A1 及适用原文，不新增 open 问题 |
| IQ-02 已解决 | 迁移资产及核验、发布方案纳入本期；外部演练和生产执行不计为本期 Task |
| IQ-03 仍未知 | 实际生成 EX01 对应 T-06 后，创建 P-01，精确绑定 `T-06.complexity=M`，注明默认口径；其输入来源与 work 问题关系保留 |

P-01 的字段定位由 agent 根据实际生成结果确定；这里的 T-06 是 EX01 走读身份，不要求实现输出固定编号。若同一条数缺口实际影响多个工作，就关联真实受影响字段，不能只绑定第一个找到的 Task；若义务退出本期，须说明依据和问题去向。

无需把已解决 IQ-01/02 再包装成两个未决事项。未解决 IQ-03 也不能因工作记录中的状态或 ID 转换丢失，更不能因已经填 M 就关闭问题。最终模型、依据与可见待确认项的语义与 EX01 保持一致。

## 7. 有限变化与异常变体

| 变化 | 应读/应改的范围 | 不应发生的处理 |
|---|---|---|
| A1 只回答责任，未解决重要重试差异 | 保留已答责任，继续澄清 IQ-01 的输入行为；条数仍按局部未知记录 | 把部分答复当全部充分，或重复询问已答责任 |
| A1 说明迁移源目标、方式和发布策略都未确定 | 保存已有分析，列出具体 HLD/交付资料缺口，本次不进入拆解 | 用很多待确认行包装成可用 SOW |
| W1 隐藏附注无法读取，且包含唯一责任说明 | 保留读取限制，补该区域或在分析后问责任事实 | 因附注隐藏就删除其影响，或因局部不可读重读全部材料 |
| R1 字节未变，但外部模拟响应改了 | 检查观察前置/资源依赖；只更新受影响行为的观察与主题 | 仅凭 HTML 哈希命中就复用旧运行结论 |
| C1 只补上资料条数 | 登记新版本，复核对应区域及引用，更新迁移局部分析 | 因文件改名或新版本号重新分析所有页面与公共能力 |
| 出稿后用户要求改变共用重试行为 | Clarify 读当前公共客户端、真实消费者、有关来源，讨论有限修改方案 | 直接用新 analysis/index 偷换 current，或重跑全部 generate |
| 压缩后输入问题还未绑定正式对象 | 恢复工作问题与实际候选，核对仍影响本期的缺口去向 | 因暂时找不到 Task ID 就漏掉待确认项或补一个假对象 |

## 8. 此次走读证明与未证明的内容

已说明：单文件多角色不豁免材料内容要求，历史/draft/旧标准用途不同，原型观察有条件边界，三类需求可主动识别，输入问题在生成前后有明确去向，单 session 可以按主题复用有用结果。

尚未证明：实际读取定位/指纹正确、浏览器可以稳定执行这些动作、长材料不会漏项、压缩能保留全部必要事实、最终 Excel 正确或 token/速度改善。后续按 D03/D09 的差异案例验证，不把这份合成记录当端到端通过。
