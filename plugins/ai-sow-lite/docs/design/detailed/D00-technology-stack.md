# D00 · 技术栈与运行形态

[返回详细设计目录](README.md) · [返回路线图](../11-detailed-design-roadmap.md)

## 1. 状态与技术基线

ai-sow 已由用户确认跑通，Lite 的动因是降低出稿与修改的耗时和 token。依赖安装、Python 工具链与 Excel 操作采用既有可行性证据作为起点，R0—R1 重点核对可复用范围、Lite 差异和真实未知能力。Lite 的 Skill 与运行时尚未实现；采用已有技术基线不表示 Lite 适配已经完成。

选型优先级依次为：满足业务与交付要求、支持 agent 自主工作、独立安装与可恢复、可观察实际成本、减少启动和维护开销。不能仅因为某技术可以记录更多事件，就让插件重新承担整套 agent 会话与细步骤编排。

Lite 继续采用此前确定的两个入口、agent 自主专业工作与小范围确定性工具。允许参考和迁入 ai-sow 的成熟机械能力，不继承其专业流程、Action 链、审批或业务 Schema。来源版本已跑通、源码/测试覆盖、Lite 模板单项验证、Lite 差异回归和完整交付是不同证据层次；不重复证明未改变能力的基础可行性，也不把未执行的新路径标成通过。

## 2. 采用的基础组合与待适配部分

**推荐方向：宿主 agent + generate/clarify Skill + Python 确定性工具 + 文件化业务状态。Excel 写入、公式重算和宿主观测分别设置适配边界。**

| 部分 | 技术基线或待选部分 | 选择理由与约束 | 剩余适配或验证 |
|---|---|---|---|
| Agent 执行 | 使用宿主现有 agent；两个 Skill 提供专业指令、按需参考与工具使用边界 | 复用插件与宿主执行形式；阅读、探索、拆解和局部修改仍由 agent 决定 | 验证 Lite 新交互、跨会话 clarify、取消与观测差异 |
| 模型 | 使用用户选择的宿主模型；实验记录实际模型与配置 | 首版不硬编码模型型号、每阶段模型路由或固定 worker 数 | 用代表性材料比较质量和开销，再提出有依据的推荐配置 |
| 确定性工具运行时 | **Python 3.12 + uv 0.11.7**，采用源版本已使用的组合 | 独立依赖声明、锁文件和环境；专业分析不移入 Python；不为 Lite 默认升级到 3.13 | 迁入时调整身份与路径并做冒烟；测启动和复用成本，有实际阻碍才重新选型 |
| 工具接入 | **本地 CLI 优先**，结构化小结果与文件引用；需要时增加薄 MCP 适配 | 同一能力不重复实现 CLI/MCP 两套业务逻辑；大量原文和模型留在文件中 | 验证目标宿主能可靠调用、取消及识别错误；常驻服务只有明确收益时引入 |
| 数据合同 | **JSON Schema + jsonschema 4.26.0**，复用已使用的校验技术 | Lite 自己定义最小结构；跨对象关系用小范围代码检查，语义充分性由 agent 判断 | 验证 Lite 的正常、未知、不适用、非法值及修改实例；不复制旧业务 Schema |
| 业务存储 | **JSON + Markdown + 不可变版本目录**；当前指向完整版本，同一人串行使用 | 支持新会话读取、检查 diff 和局部修改；不为单项目文件操作先引入数据库服务 | 验证候选文件完整性、过期草案拒绝、切换当前版本和中断恢复；原子性由协议证明，不能仅靠目录存在 |
| 原始输入 | 保留原件；非原型只支持可直接读取的文本（默认 Markdown）与 `.xlsx` | 复用文本读取与 openpyxl；PDF/DOCX、扫描件及其他输入不支持，不引入 Docling、pypdf、python-docx 或 OCR | 验证轻量索引、用途分离、文本编码及 Excel 相关结构/未读面；不支持格式要求提供可读内容 |
| 原型探索 | 优先使用宿主已授权浏览器能力；缺少所需能力时验证 **Playwright Python + Chromium** | agent 自主选择探索路径，浏览器只提供动作与观察；不按页面预制 Action 链 | 验证静态与需构建的原型、动态状态、进程清理及浏览器依赖安装成本 |
| Excel 写入 | **openpyxl 3.1.5**；参考已有投影和必要 OOXML 处理 | 可见模板是规则来源；内部 ID 和来源保存在独立业务文件中 | 验证 Lite 列映射、扩行、UAT、独立问题说明及保护的差异，不再证明 openpyxl 是否能写 Excel |
| 公式重算 | **LibreOffice 无界面模式**；复用已有引擎适配方法 | 写入与重算分开；模板保持计算权威，不在 Python 复制估算算法 | 记录实际引擎版本；针对 Lite 输出验证重算、缓存和结构，原生检查聚焦填值、扩行与原公式/结构保留 |
| 观测 | **JSONL 事件 + 工具计时 + 宿主 usage 适配**；业务与观测存储分开 | 记录真实粒度并去重，不通过人为拆调用制造逐步 token | 证明可采范围和盲区；不能把请求总量假分摊到各步骤，也不能让观测失败阻断业务 |
| 验证 | 保留 Lite unittest 模板回归；Python 工具沿用 **pytest 8.4.1** | 优先复用适用案例；测试并行度按实际成本决定，不照搬固定 worker 数 | D09 明确证据复用、迁入冒烟、差异回归和新能力实验各自范围 |

以上区分已选基础组合与仍需设计的 Lite 适配。来源平台与安装限制先作为参考，迁入实现保持等价的部分只需适用性核对及冒烟；有路径、依赖、宿主或模板变化时检查对应差异。最终支持声明基于复用证据和 Lite 的实际改动范围，不机械重复完整平台可行性实验。

## 3. 运行形态与主语言的取舍

| 选择 | 适用价值 | 本项目的判断 |
|---|---|---|
| **宿主 agent + Skill + 本地工具** | 直接服务于用户已有会话，专业过程可以保持自主 | 推荐作为基线；主要不确定性是宿主扩展可取得的观测与生命周期事件 |
| 插件自行驱动 agent SDK / 模型 API | 当需要自有会话生命周期、模型请求或宿主没有的控制接口时有价值 | 不作为默认方案；会增加会话、鉴权、交互与计费边界。SDK 本身并不等于必须细步骤编排，但是否引入要有真实需求 |
| 只用自然语言 Skill，不提供确定性工具 | 初始实现少 | 文件一致生效、Excel 结构保真、边界 diff 和真实事件记录仍需要可靠实现，不宜全部交给临时生成脚本 |

主工具语言采用已跑通的 Python 组合，不再为 Lite 单独开展 Python/TypeScript 比选。只有新增需求与已有能力发生实际冲突时再评估替代方案；首版避免维护两套核心运行时。

CLI 只暴露读取定位、检查、保存、投影、重算和观测等能力。它不拥有“下一个专业动作是什么”的总控状态机。仅在宿主接入或进程复用确有收益时增加 MCP，不因为插件可以配置 MCP 就预建服务。

## 4. Excel 差异与观测未知分别处理

### 4.1 Excel 复用成熟路径，只验证 Lite 差异

openpyxl 官方说明它不计算公式；`data_only` 读取的是保存的公式缓存值。它也不是任意 XLSX 内容的无损往返保证。因此“能够载入并保存模板”不能作为选型完成的依据。[公式说明](https://openpyxl.readthedocs.io/en/stable/simple_formulae.html)、[载入与保存限制](https://openpyxl.readthedocs.io/en/stable/tutorial.html)。

ai-sow 已提供 LibreOffice 无界面重算、独立运行环境和公式/缓存复读实现，Lite 手工模板也已做实算与原生 Excel 检查。复用这些证据和方法，命令行接口参考[官方参数](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)。

剩余工作集中在 Lite 删除辅助列后的映射、既有 UAT 公式保存、超过预留行数的扩展、合法空值与独立待确认说明、版本保存后的结果复读。复用适用案例，只对这些差异补测；未改部分不另做基础可行性探针。冷启动与连续导出作为性能基线记录，依赖准备复用既有安装方法并核对 Lite 路径。

I1.3 的差异复现已确认 LibreOffice 会省略 Table 计算列元数据并裁剪整列数据验证范围。采用 [D06 §8](D06-excel-projection-and-delivery.md#8-office-复读失败与恢复) 的两项有限兼容处理，保留原模板与单元格公式/缓存；不迁入旧版整张 Table 或保护设置的无条件恢复。真实交付及原生复核结果按 [I1 验证](../../validation/I1-reliable-delivery.md) 记录。

如果候选计算器只能算部分公式、覆盖了公式或破坏文件，不能以“用户打开 Excel 后会重算”作为自动交付的默认补救。应更换适配方式或明确支持边界，也不能以 Python 重新实现估算公式来绕过问题。

### 4.2 逐步 token 需要真实的数据来源

官方 Codex App Server 文档列出了 `thread/tokenUsage/updated` 事件；本地 CLI 也提供 app-server 相关接口。这只能证明协议存在相关能力，**尚不能证明普通 Skill 可以订阅当前会话事件，或拿到每个专业活动的精确 token**。App Server 面向自建集成，不能直接等同于插件内可调用能力。[官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。

[D08](D08-telemetry-and-performance.md)/[EX06](examples/EX06-telemetry-accounting.md) 已补当前环境的有限只读探针：CLI 协议类型与当前会话尾部均有 usage 字段，但生产者版本不同，后者的 usage payload 本身没有 turn_id。未启动模型或接通采集器；请求边界、调用身份和活动归属仍未证明。

需要分别验证：

- 插件自有工具可以记录的开始、结束、失败、重试与读写规模。
- 宿主能提供的请求、turn 或模型调用 usage，及其唯一标识、累计口径、缓存明细与迟到事件。
- agent 标记的专业活动能否与实际调用对应；一个调用跨多个活动时能否分开，不能分开就保留真实组合粒度。
- 取消、进程退出和用户等待的事件来源；仅靠 agent 自报起止不能保证异常情况下的数据完整。

如果只能取得整次 token，就显式记录整次总量和各步可得耗时，逐步 token 标为不可得。这是能力限制，不能把它说成已满足完整逐步观测目标。优先调查宿主支持的扩展或轻量采集方式；若最终只能通过改变运行形态满足要求，再给出增加组件、安装成本与使用方式变化的具体取舍，不擅自改成另一套 agent 产品。

## 5. 依赖、存储与启动成本

依赖基线从源版本的 Python 3.12、uv 0.11.7、jsonschema 4.26.0、openpyxl 3.1.5 出发；移除 pypdf 等当前输入范围不需要的依赖，生成 Lite 自己的声明和锁文件。升级以解决具体需求为前提，并回归受影响能力。[uv 项目结构与锁文件](https://docs.astral.sh/uv/concepts/projects/layout/)。

插件包自包含，运行时不读取其他插件或 marketplace 根目录。可复用代码迁入 Lite 后调整依赖与路径，去掉旧流程耦合；设计期参考源实现不等于运行时跨插件 import。系统浏览器和计算引擎的准备及发现优先沿用已跑通方式，新增平台或环境差异才单独处理。

Playwright 的浏览器安装与缓存需要单独管理，因此 Python 包安装成功不代表原型探索已可运行。[Playwright 浏览器管理](https://playwright.dev/python/docs/browsers)。首版只准备已选路径需要的组件，不默认安装全套浏览器、OCR、数据库、模型 SDK 和遥测服务。

业务文件优先用可检查的版本目录；事件按请求写入 JSONL，避免多个 writer 直接争写同一文件。只有实测显示查询规模或并发需求超出此方案时，再评估 SQLite 等索引或存储组件。索引不替代原件，也不能生成第二份可独立修改的当前业务事实。

业务未知不触发库级自动重试；工具错误须返回可定位原因，交由入口判断是否有明确且有限的修法。日志默认只保留执行标识、规模、状态和用量，不把原文或完整提示词作为遥测必填项，也不默认引入外部观测平台。

## 7. 已查阅的其他官方依据

官方 Skill 文档描述了指令、参考资料、资产和可选脚本，并采用按需加载。它支持本稿“专业指令与确定性工具分开”的方向，但不证明某个业务流程已经可靠运行。[Skill 文档](https://learn.chatgpt.com/docs/build-skills)。

[D04](D04-generate-and-context.md) 保留已核对的子 agent 能力及条件边界，但尚未选定委派。先按 [D04A](D04A-single-session-panorama.md) 分析一个 Skill、一个主 session 的完整输入输出和历史累积，测量必要读取、生成、合并、压缩恢复及 Excel 成本。只有出现实际收益依据时再验证局部隔离/并发；宿主支持某能力不代表 Lite 应默认使用或已经验证。

Python jsonschema 是已选的 JSON Schema 执行器；Lite 的结构语义由自身详细设计确定。结构合法性与业务充分性仍需分别判断。[jsonschema 文档](https://python-jsonschema.readthedocs.io/en/stable/)。
