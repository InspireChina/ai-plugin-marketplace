# 10 · 自制 Draft 作为辅助输入

[返回总览](README.md)

## 1. 明确用途

Draft 的价值是复用用户已经整理的业务结构和内容。例如 BA 已拆出 Epic/Feature，并附少量 tech note，generate 可以在分析 PRD 和高阶设计时对照这些成果，保留有依据的命名、层级和范围线索，再补全 Story、来源 AC 与 Task。

Draft 可能只覆盖业务功能。agent 仍须结合 PRD、原型和 HLD 主动识别技术/NFR 公共能力、业务接入及迁移、上线等交付需求；有依据的遗漏可以补入同一层级，不把已有 Epic/Feature 当作完整范围，也不为保持原骨架而把非业务工作全部塞入备注。

这项能力服务于首次生成或明确的内容补充，不以 Excel 文件来回编辑、自动同步所有单元格为目标。当前不增加第三个 Skill，也不让导入 draft 自动建立一份“有效 SOW”。

| 输入组合 | 能做什么 | 能否直接进入拆解 |
|---|---|---|
| 只有 Epic/Feature 标题 | 知道期望主题、分组和术语 | 不能，缺少 PRD、高阶设计及具体业务依据 |
| Epic/Feature + 少量 tech note | 额外获得接口、组件或技术方向线索 | 通常仍不能；技术备注不足以给出业务规则和来源 AC，必需材料仍需提供 |
| PRD + 高阶设计 + draft | 用必需材料验证并复用 draft，减少重复组织 | 分析后关键缺口补足即可 |
| 老项目上述材料齐备但缺往期 SOW | 能了解目标和草稿结构 | 不能豁免往期 SOW，要补充后再判断 |
| Draft 已含部分 Story、AC、Task | 提取已有内容、来源与确定程度，复用有依据部分 | 仍检查必需材料和内容充分性，不把草案写全等同于事实已足够 |

PRD、HLD 和老项目往期 SOW 的要求以 [01](01-workflow-and-user-input.md) 为准。[D03](detailed/D03-input-analysis-and-exploration.md) 明确按内容角色与区域判断：同一文件可含 PRD/HLD，或历史/draft，但必须有清楚可分、足够的对应内容，不能用标签免除材料要求。[EX02](detailed/examples/EX02-input-analysis-and-exploration.md) 给出走读。

## 2. 为什么标题和 Tech Note 通常不够

例如只有“订单管理 → 创建订单”和“调用订单服务”，可以识别能力主题和技术线索，但还缺：

- 谁在什么条件下发起，哪些数据或规则由输入明确规定。
- 输入中有哪些验收条件或可明确提取的验收意图。
- 目标交付与已有系统的关系，哪些工作已存在、实际可用、由谁承担。
- 判断工作类型、方式、复杂度和集成属性所需的实际边界与规模事实。

agent 不能从一个标题推导整套业务规则或 AC，也不能从“调用服务”推断已有接口可直接复用；应对照往期 SOW 的 as-is，无相关候选按新建，相关候选实例未明按新建+待确认；未读/读取失败或本期目标歧义不能冒充已完成分析。如果缺口广泛，要求补充 PRD/HLD 等资料；少量关键缺口可以在输入分析后的交互中补齐。

## 3. 分析与复用规则

1. **保留原件和层级。** 记录标题、层级、说明、tech note、已有 AC/Task 及其原始位置，不强制用户先改造成完整 Lite 模型。
2. **对照必需输入。** 找到每项内容在 PRD/HLD、老项目往期 SOW 和用户答复中的依据；区分已明确内容、建议和未知。
3. **复用明确成果。** 有依据的 Epic/Feature 名称与分组可直接作为骨架。已有 AC 可以忠实整理，但不能把技术建议或暂定想法自动升级为验收义务。
4. **分析后处理关键冲突。** Draft 与 PRD/HLD 不一致时，不只按文件时间、标题相似度或用户手写就选一方；能从适用范围解决则解释，需用户决定则集中澄清。
5. **满足充分性后分片生成。** 缺依据的后期局部字段留空并关联待确认项；不因为 draft 已有值就免除依据核对，也不因导入而重新发明大量业务字段。

来源位置、标题或旧行号不是 Lite 的稳定业务 ID。建立模型时保存必要映射，防止两个同名 Feature/Story 被误合并。若只修改表述，保留相同业务含义；若拆合有实质变化，记录关系与来源。

## 4. 与 Clarify 的关系

存在有效 SOW 时，clarify 仍以共享模型为基线。用户新增 draft、tech note 或有明确修改意图的 Excel 内容，都作为补充输入分析；先定位影响、讨论方案，确认后在有限切片内应用。

如果用户只交来一个文件却没有说明它表达的是新增意见、旧材料还是首次草案，先明确用途，再选对应入口。不能把一个外来工作簿直接覆盖为 current，也不把每个格式或公式差异都解释为业务修改。

## 5. 首版范围与待验证内容

首轮从 D03 列明的 Markdown/XLSX 读取方法出发，保留 Epic/Feature 层级、描述、技术备注及原位置，与必需材料一起分析。列含义和层级由 agent 结合实际内容识别，不写固定表头别名穷举器；结构、隐藏附注和不可读对象由工具暴露。非原型材料只支持可读文本（默认 Markdown）与 `.xlsx`，其他格式暂不支持；歧义与复用效果继续用实际样例验证，不承诺任意工作簿结构、公式或批注无损导入。

最值得验证的是：复用 BA 的骨架能减少多少整理成本，是否仍能发现标题未覆盖的 PRD 范围、原有 AC 的依据不足及真实起点缺失。若“导入能力”只是省去了几次复制粘贴，却增加大量解析和冲突复杂度，可以先用 agent 读取原文完成同样的辅助分析，不急于实现通用导入器。
